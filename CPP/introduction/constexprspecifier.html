C++ constexpr Specifier (Compile-Time Evaluation) 🚀

The **constexpr** specifier (introduced in C++11) is used to indicate that the **value of a variable or the return value of a function can be computed at compile-time**. This shifts computation overhead from runtime to compilation, significantly improving program execution speed and providing constants guaranteed at compilation.

The use of constexpr is often needed for features that require a known value during compilation, such as **array sizes**, **switch case labels**, and **template parameters**.

Declaring Variables with constexpr

A variable declared with constexpr **must be initialized with a constant expression** (a value that can be determined at compile-time).

Valid Examples:

  • constexpr int y = 4;
  • constexpr int x = 7 + 5;
  • constexpr int x = sum(10, 2); (if sum is a constexpr function)

Invalid Examples:

  • constexpr int a; (Must be initialized)
  • int z = 7; constexpr int x = z; (z is a runtime variable, not a constant expression)

Functions with constexpr Specifier

A constexpr function must be simple enough to be evaluated at compile-time when called with constant arguments. If it's called with non-constant (runtime) arguments, it behaves like a regular function.

Key Rules:

  • The **parameter and return types** must be **literal types** (e.g., int, double, char, bool).
  • The function **cannot have side effects** (e.g., no I/O operations like cin/cout, no modification of global/static variables).
  • A constexpr function can **only call other constexpr functions** (not simple, non-constexpr functions).
  • From C++14, a constexpr function can contain loops and multiple statements (before C++14, it was restricted to a single return statement).

Constructors with constexpr

The constexpr specifier can be applied to constructors to allow classes and objects to be created at compile-time. This is often used for creating small, compile-time-known constant objects.

Key Constraints:

  • The class cannot have **virtual base classes** or **virtual member functions**.
  • The class cannot have **mutable data members**.

const vs. constexpr

While both deal with immutability, their key difference is in when the value must be known:

const constexpr
Value can be evaluated at **compile-time OR run-time**. Value **MUST** be evaluated at **compile-time**.
A variable can be initialized with a run-time value (e.g., user input). A variable can only be initialized with a compile-time constant expression.
May have runtime overhead if initialized at runtime. Guarantees **zero runtime overhead** for its evaluation.

Limitations of constexpr

Despite its performance benefits, constexpr has restrictions:

  • No **I/O operations** (cin/cout).
  • No **dynamic memory allocation**.
  • No support for **exception handling**.
  • Only **literal types** are permitted for parameters and return types.
