Flask Routing: Variable Rules and URL Converters 🔗

Flask allows you to build **dynamic URLs** by adding variable parts to the routing rule. These variables are placed within angle brackets (<variable-name>) in the @app.route() decorator and are automatically passed as **keyword arguments** to the associated view function.

Basic Variable Example

In the following code, the part <name> captures a string from the URL and passes it to the hello_name function:

@app.route('/hello/<name>')

def hello_name(name):

return 'Hello %s!' % name

Visiting **http://localhost:5000/hello/TutorialsPoint** renders the output: **Hello TutorialsPoint!**

URL Converters

By default, variable parts are treated as strings, but you can explicitly specify the data type by using a **converter** in the format <converter:variable-name>. This ensures the variable is passed to the function in the correct Python type.

Available Converters

ConverterDescriptionExample Usage in Route
string(Default) Accepts any text without a slash.<string:username>
**int**Accepts **positive integer** values.<int:postID>
**float**Accepts **floating-point** values.<float:revNo>
**path**Accepts strings and includes **slashes** (/), useful for directory structures.<path:filepath>

Canonical URLs and Trailing Slashes

Flask's URL rules are based on **Werkzeug's routing module**, which ensures unique and well-formed URLs, following common conventions.

Trailing Slash Behavior

The use of a trailing slash (/) at the end of a route rule dictates its canonical (preferred) form and how it handles user input:

  • **Rule with Trailing Slash (e.g., /python/):**
    • The URL **/python** will be **redirected** to the canonical URL **/python/**.
    • Both **/python** and **/python/** will return the expected output.
  • **Rule without Trailing Slash (e.g., /flask):**
    • The URL **/flask** will return the expected output.
    • Attempting to access **/flask/** (with a slash) will result in a **404 Not Found** error.
