PHP - Post-Redirect-Get (PRG) Pattern

Understanding the PRG Technique

The **Post-Redirect-Get (PRG)** pattern is a design solution used to prevent the accidental **resubmission of forms** when a user refreshes the browser or uses the back button after a $\text{POST}$ request. Without PRG, refreshing the page after a successful form submission results in the browser displaying a warning and, if confirmed, sending the same data again, potentially causing data duplication or loss of data integrity.

The Standard Problem

When a form is submitted using the $\text{POST}$ method, the server processes the data and typically returns an HTML response. If the user hits refresh ($\text{F5}$) at this point, the browser attempts to repeat the last action, which was the original $\text{POST}$ request, leading to duplicate submissions.

The PRG Solution Flow

The PRG technique breaks this flow into three distinct steps:

  1. Post: The client submits the form data using $\text{POST}$ to the server script.
  2. Redirect: The server script processes the data, stores any necessary information (e.g., in a session), and then issues a $\text{302}$ ($\text{Found}$) $\text{HTTP}$ **redirect** back to itself or to a result page.
  3. Get: The client, upon receiving the redirect, automatically makes a **$\text{GET}$** request to the new (or same) page. Since the last action was $\text{GET}$, refreshing the page now simply repeats the $\text{GET}$ request, which is safe and does not resubmit the form data.

Example: Implementing PRG in PHP

The core of the PHP implementation relies on **sessions** to temporarily hold the form data and the **$\text{header()}$** function to perform the redirect.

Key Steps in the PHP Script

  1. Start the session: $\text{session\_start()}$;
  2. On $\text{POST}$ Submission: Store submitted data in $\text{\$_SESSION}$ variables.
  3. Perform the redirect: $\text{header("Location: current\_page.php")}$; and immediately call $\text{exit}$; to terminate script execution.
  4. On $\text{GET}$ Request (After Redirect): Check if the data is present in $\text{\$_SESSION}$. If so, display the result.
  5. Clear the session variables using $\text{unset()}$ to ensure the result is only displayed once.
<?php
   session_start();
   if (isset($_POST["submit"])) {
      // 1. POST: Store data in session
      $_SESSION['fname'] = $_POST['first_name'];
      $_SESSION['lname'] = $_POST['last_name']; 
      
      // 2. REDIRECT: Send the user back to a GET request
      header("Location: " . $_SERVER['PHP_SELF']);
      exit; // Crucial to stop execution
   }
   
   // 3. GET: Check session for results after the redirect
   if (isset($_SESSION["fname"])) {
      echo "First name: " . $_SESSION['fname'] . " " . "Last Name: " . $_SESSION['lname'] . "";
      unset($_SESSION["fname"]); // Clear data after display
      unset($_SESSION["lname"]);
   }
?>
