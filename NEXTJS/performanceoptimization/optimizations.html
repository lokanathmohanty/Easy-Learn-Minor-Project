Next.js - Optimization Techniques

Built-in Optimization Techniques

Next.js includes several built-in optimizations designed to improve application speed and achieve high **Core Web Vitals** scores. Key optimization areas include:

  • Implement Lazy Loading: A technique to defer the loading of **non-critical resources** (like images, components, or modules) until they are needed, prioritizing the visible content.
  • Optimize Images Rendering: Using the built-in **<Image> component** instead of the standard <img> tag automatically handles image optimization, including compression, responsive sizing, and modern formats.
  • Optimize Script Loading: The built-in **<Script> component** optimizes the loading of third-party scripts, giving developers control over when and how the script is executed to prevent blocking the main thread.
  • Reduce JavaScript Bundles: Next.js automatically applies **tree shaking** and code splitting to reduce the final JavaScript bundle size, ensuring users only download the code necessary for the initial page load.
  • Optimize Memory Usage: Built-in tools are available to help monitor the application's memory usage, allowing developers to identify and resolve **memory leaks**.

Optimizing Metadata

Providing proper **Metadata** is crucial for Search Engine Optimization (SEO), as it helps search engines understand the webpage's content. Metadata includes details like the page title, description, and keywords.

In Next.js, metadata is typically defined in the **layout page** (app/layout.tsx) where it is then inherited by all child routes.

Example: Defining Global Metadata

// app/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'Next JS Tutorial',
  description: 'We provide simple and easy to learn tutorial on Next JS',
}

export default function RootLayout({ children }: RootLayoutProps) {
  return (
    <html lang="en">
      <body>
        <header>
            <h1>Header Element</h1>
        </header>
        <main>{children}</main>
      </body>
    </html>
  )
}

Lazy Loading Image Optimization

The <Image> component uses lazy loading by default. This means images are not loaded until they are close to the viewport, which speeds up the initial page load.

You can control this behavior using the **loading** prop:

  • The default behavior is loading='lazy' (lazy loading).
  • You can set loading='eager' to force the image to load immediately upon page load.

Example: Lazy vs. Eager Loading

import Image from 'next/image';

export default function Example() {
    return (
    <div>
        <h1>Lazy Loading (Default):</h1>
        <Image
            src="/file.svg"
            alt="Example Image"
        />

        <h1>Eager Loading (For critical images):</h1>   
        <Image
            src="/next.svg"
            alt="Example Image"
            loading='eager' // Disables Lazy Loading
        />
    </div>
    );
}
