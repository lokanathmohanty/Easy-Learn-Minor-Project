Java Hashtable Class Summary ⚓️

The **java.util.Hashtable** class is a concrete implementation of a **hash table** that maps keys to values. It is a **legacy class** from the original Java Development Kit (JDK 1.0) and has been largely replaced by the **HashMap** and **ConcurrentHashMap** classes in modern Java.

I. Legacy Status and Key Differences from HashMap

While `Hashtable` and `HashMap` provide similar core functionality (fast, unordered key-value storage), they have three critical differences:

Feature Hashtable HashMap (Modern Standard)
**Synchronization** **Synchronized** (Thread-safe) Not Synchronized (Not thread-safe)
**Null Keys/Values** **Does NOT permit** null keys or null values. Permits one null key and multiple null values.
**Inheritance** Extends **Dictionary** (legacy). Extends **AbstractMap** (modern JCF).

II. Core Characteristics

  • **Synchronization:** Every public method of `Hashtable` is synchronized. This makes it thread-safe but imposes a performance penalty compared to `HashMap` in single-threaded environments. For concurrent applications, **ConcurrentHashMap** is the modern, more efficient replacement.
  • **Performance:** Like `HashMap`, `put()`, `get()`, and `remove()` operations are typically **constant time ($O(1)$)**, assuming a good hash function.
  • **Unordered:** It makes **no guarantees about the iteration order**. The order depends on the hash codes and the internal structure.
  • **Iteration:** It relies on the legacy **Enumeration** interface for accessing keys and elements, although it also provides modern `Iterator`-based views via `keySet()`, `entrySet()`, and `values()`.

III. Initialization and Capacity

Similar to `HashMap`, its performance is tunable with capacity parameters:

  • **Initial Capacity (Default: 11):** The initial number of buckets in the hash table.
  • **Load Factor (Default: 0.75):** Dictates the ratio of elements to capacity that triggers automatic resizing and rehashing to maintain performance efficiency.

The output `Hashtable elements: {3=3, 2=2, 1=1}` shows that the iteration order is **not** the insertion order (`1, 2, 3`), which is expected for a hash table implementation.
