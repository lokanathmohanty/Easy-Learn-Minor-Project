PHP File Inclusion: Reusing Code

**File Inclusion** is a core PHP feature that allows you to reuse the same code (like headers, footers, or menus) across multiple pages without writing it repeatedly. This improves organization, saves time, and simplifies maintenance. The content of the specified file is essentially copied into the calling script before execution.

File Inclusion Functions

PHP provides four main statements for including external files, differentiated by how they handle errors and whether they allow repeated inclusion.

1. `include()`

  • **Purpose:** Includes the content of the specified file. Used for **non-critical** files (like headers/footers).
  • **Error Handling:** If the file cannot be found, it generates a **Warning** but the script **continues** execution.
  • **Syntax:** include 'filename.php';

2. `require()`

  • **Purpose:** Includes the content of the specified file. Used for **critical** files (like configuration or database connection files).
  • **Error Handling:** If the file cannot be found, it generates a **Fatal Error** and **halts** the execution of the script immediately.
  • **Syntax:** require 'filename.php';
  • **Recommendation:** Generally preferred over `include()` for essential files, as a missing critical file should prevent the script from running incorrectly.

3. `include_once()` and `require_once()`

These functions behave identically to their non-`_once` counterparts, but they guarantee that the file will be included **only once**, even if the statement is called multiple times in the script. This prevents function/class re-declarations and script errors.

Security Risk: File Inclusion Vulnerabilities

The power of file inclusion creates a significant security risk if user input is used to determine which file to include. This is known as **Local File Inclusion (LFI)**.

Vulnerable Code Example:

$page = $_GET['page']; // User can manipulate this input
include($page); // Attacker can include any file, e.g., /etc/passwd

Prevention Strategies:

To prevent LFI, always strictly control the included file path:

  • **Whitelist Allowed Files:** Check user input against an array of explicitly allowed files.
    $allowed = ['home.php', 'about.php'];
    if (in_array($page, $allowed)) { include($page); }
  • **Use Predefined Paths:** Append the user input to a known, safe directory path, and ensure no directory traversal sequences (`../`) are present.
  • **Disable Remote Inclusion:** Set `allow_url_include = Off` in your `php.ini` file if you don't need to include files from remote URLs.
