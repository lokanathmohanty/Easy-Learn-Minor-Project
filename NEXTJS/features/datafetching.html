Next.js Data Fetching Methods 🌐

Overview of Data Fetching

Next.js enhances React's data fetching capabilities by offering multiple methods, primarily focused on server-side execution. Fetching data on the server side (pre-rendering) improves **performance** and **SEO** by reducing the amount of JavaScript the client needs to run and ensuring the HTML is fully formed when it reaches the browser.

The three main types of data fetching are **Server-side Fetching** (SSG/SSR), **Client-side Fetching**, and **Incremental Static Regeneration (ISR)**.

1. Server-side Fetching (Pre-rendering)

Data is fetched and rendered into HTML on the server, before the page is sent to the client.

A. Static Site Generation (SSG) 🏗️

  • **Mechanism:** Pages are generated once **at build time** and reused for every request (or until revalidated).
  • **Best For:** Pages with data that doesn't change frequently (e.g., blog posts, marketing pages). It provides the best performance.
  • **Function (Page Router):** **`getStaticProps`**
  • **Function (App Router):** Default fetching behavior within a Server Component.
// Example using getStaticProps (Page Router)
export async function getStaticProps() {
  // Fetches data only at build time
  const res = await fetch('...');
  const post = await res.json();
  return { props: { post } };
}

B. Server-side Rendering (SSR) 💻

  • **Mechanism:** Data is fetched **on every request** to the server, and the HTML is generated dynamically.
  • **Best For:** Pages requiring frequently updated or personalized data (e.g., a user's dashboard).
  • **Function (Page Router):** **`getServerSideProps`**
  • **Function (App Router):** Using the **`fetch`** API with dynamic options (e.g., no caching).
// Example using getServerSideProps (Page Router)
export async function getServerSideProps() {
    // Fetches data on every request
    const res = await fetch('...');
    const post = await res.json();
    return { props: { post } };
}

2. Incremental Static Regeneration (ISR) ⏱️

ISR is a middle ground between SSG and SSR. It allows a page to be statically generated at build time but also includes a mechanism to **update the static page incrementally** after deployment.

  • **Mechanism:** Uses the **`revalidate`** property inside `getStaticProps` to set a maximum frequency (in seconds) for regeneration when a new request comes in.
// Example using revalidate for ISR
export async function getStaticProps() {
    // ... data fetching ...
    return {
      props: { data },
      revalidate: 10, // Page is regenerated at most every 10 seconds
    };
}

3. Client-side Fetching

Data fetching happens entirely in the user's browser after the initial page has loaded. This is done using React hooks like **`useEffect`** and can be combined with SSG/SSR for initial load.

  • **Mechanism:** Uses hooks or libraries (like SWR or React Query) within a **Client Component** (marked with `"use client"`).
  • **Best For:** Non-essential data, user-specific data, or data that needs to be constantly updated (e.g., a "like" count).
