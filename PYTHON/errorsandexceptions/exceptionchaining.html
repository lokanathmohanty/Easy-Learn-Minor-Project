Exception Chaining

Exception chaining is a technique of handling exceptions by re-throwing a caught exception after wrapping it inside a new exception. The original exception is saved as a property (such as cause) of the new exception.

During the handling of one exception 'A', it is possible that another exception 'B' may occur. It is useful to know about both exceptions in order to debug the problem. Exception handlers may deliberately re-raise exceptions to provide extra information or translate exceptions.

Basic Example

try:
   open("nofile.txt")
except OSError:
   raise RuntimeError("unable to handle error")

This produces a chained traceback showing both exceptions:

The raise ... from Statement

Using an optional from clause in the raise statement indicates that an exception is a direct consequence of another. This helps clarify exception relationships in tracebacks. 

try:
   open("nofile.txt")
except OSError as exc:
   raise RuntimeError from exc

This results in output showing the original exception as the direct cause of the new one.

The raise ... from None Statement

Using from None disables the automatic exception chaining. 

try:
   open("nofile.txt")
except OSError as exc:
   raise RuntimeError from None

This suppresses the original exception in the traceback.

The __context__ and __cause__ Attributes

Raising an exception inside an except block automatically assigns the caught exception to the new exception's __context__. You can assign __cause__ explicitly using raise ... from. 

try:
   try:
      raise ValueError("ValueError")
   except ValueError as e1:
      raise TypeError("TypeError") from e1
except TypeError as e2:
   print("The exception was", repr(e2))
   print("Its __context__ was", repr(e2.__context__))
   print("Its __cause__ was", repr(e2.__cause__))

Output:

The exception was TypeError('TypeError')
Its __context__ was ValueError('ValueError')
Its __cause__ was ValueError('ValueError')
