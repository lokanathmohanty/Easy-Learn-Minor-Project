Django URL Mapping and Dispatching 🗺️

Django's **URL mapping** is the process by which the framework finds the correct **view function** to handle an incoming web request. This is managed primarily through the **urlpatterns** list defined in your project's or application's **urls.py** file.

Basic URL Mapping Structure

The core of URL mapping is the url() function, which takes three main elements:

url(regex_pattern, python_path_to_view, name)
  1. **The Pattern (regex_pattern):** A **regular expression (regexp)** that matches the URL requested by the user. Django processes patterns sequentially.
  2. **The Python Path to the View:** The fully qualified path (e.g., 'myapp.views.hello') or a direct reference to the view function that should be executed.
  3. **The Name (name):** An optional, but recommended, name for the URL pattern (e.g., name='hello'). This is essential for **URL reversing**, allowing you to refer to the URL in templates or code without hardcoding the path.

Example of a mapping in the project urls.py:

urlpatterns = patterns('',
   # Maps /hello/ to the 'hello' function in myapp/views.py
   url(r'^hello/', 'myapp.views.hello', name = 'hello'),
)

Organizing URLs (Best Practice)

To keep applications reusable and the project structure clean, the best practice is to define URLs within the application itself (myapp/urls.py) and then **include** that file in the main project's urls.py.

  • **Step 1: Create myapp/urls.py:** 
    urlpatterns = patterns('myapp.views',
   url(r'^hello/', 'hello', name = 'hello'),
   # ...
)

    Note: We use the first element of patterns to define the common Python path prefix ('myapp.views'), simplifying the subsequent view paths.

  • **Step 2: Include in myproject/urls.py:** 
    urlpatterns = patterns('',
   url(r'^myapp/', include('myapp.urls')),
   # ...
)

    Now, the view mapped to /hello/ is accessed via the full path **/myapp/hello/**, providing a cleaner structure.

Sending Parameters to Views

Parameters are passed from the URL to the view function by using **regular expressions to capture parts of the URL**.

  • **Positional Parameters (Order-Dependent):**

    Captured groups in the regex (parentheses ()) are passed to the view function as positional arguments, based on the order they appear in the pattern.

    url(r'^articles/(\d{2})/(\d{4})', 'viewArticles', name = 'articles'),

    For the URL /articles/12/2006/, Django calls the view as viewArticles(request, '12', '2006'). **The order of month and year in the view function signature must match the regex order.**

  • **Named Parameters (Order-Independent):**

    Using named capturing groups (?P<name>...) is the preferred way to pass parameters, as it makes the mapping order-independent and clearer.

    url(r'^articles/(?P<month>\d{2})/(?P<year>\d{4})', 'viewArticles', name = 'articles'),

    Django calls the view using keyword arguments: viewArticles(request, month='12', year='2006'), matching the parameter names in the view function's signature.
