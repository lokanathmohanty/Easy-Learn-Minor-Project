JavaScript - require() Function

Introduction

Files with JavaScript code that perform a specific task are called modules. Modules are self-contained and separated from other parts of code, which makes it easy to add, remove, and update functionalities without affecting the entire program.

If these modules are in separate JavaScript files, you should include them inside the main JavaScript code. The require() function is one way to do this.

How to Run ES and CommonJS Modules

  • ES Modules: Use import and export statements. Most browsers support ES modules natively.
  • CommonJS Modules: By default, Node.js supports the CommonJS format which uses module.exports to export and require() to import.

JavaScript require() Function

The require() method is a built-in CommonJS function in Node.js. By default, Node.js treats JavaScript code as CommonJS modules.

The function accepts a string parameter specifying the module's path:

  • Core module: If no ./, ../, or / is present, Node.js assumes it’s a core or node_modules package.
  • Local module: Paths starting with ./ or ../ are treated as relative/absolute paths.
  • Installed module: Modules installed via npm are resolved from node_modules.

Syntax


const locName = require(locationName);

Example: Local Module


// utils.js
const get_full_name = (first_name, last_name) => {
   return `My full name is ${first_name} ${last_name}`;
};
module.exports = get_full_name;
      

// index.js
const get_full_name = require('./utils.js');
console.log(get_full_name('Amit', 'Sharma'));

Output: My full name is Amit Sharma

Example: External Module


const myVar = require('http://web-module.location');

Difference Between require() & import()

  • require() can be used anywhere in your code, even conditionally.
  • import must always be used at the top of the file and cannot be conditional.
  • Files imported with require() usually have a .js extension.
  • Files imported with import often use the .mjs extension.

In summary, require() is more flexible in Node.js, while import follows ES module standards and is preferred in modern JavaScript projects.
