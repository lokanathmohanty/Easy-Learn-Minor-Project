Next.js Partial Pre-Rendering (PPR) ✨

What is Partial Pre-Rendering?

**Partial Pre-Rendering (PPR)** is an experimental rendering pattern in Next.js designed to combine the performance benefits of static rendering with the up-to-date nature of dynamic rendering on a **single page**. It ensures the fastest possible initial load by serving static content immediately while streaming dynamic content to the client.

During the build phase, the entire page's static structure is pre-rendered, including a **static fallback** for any dynamic sections. The actual dynamic data is fetched later on demand.

**Note:** PPR is an experimental, canary feature and is not recommended for production use as it is subject to change.

How PPR Works (Static Shell + Streaming)

PPR uses **React Suspense** boundaries to define the dynamic parts of a page:

1. Initial Static Shell Generation

  • At **build time**, Next.js generates the basic HTML structure (the "static shell") of the page.
  • All genuinely **static components** are included in this initial HTML.
  • The areas wrapped in **`<Suspense>`** are replaced by their **`fallback`** content (e.g., a loading spinner).
  • When the user first visits the page, they immediately see this static HTML and the fallback, resulting in a very fast **First Contentful Paint (FCP)**.

2. Dynamic Content Streaming

  • The page then loads the client-side JavaScript.
  • The dynamic component (the child of `<Suspense>`) starts fetching its data (often with the `cache: 'no-store'` option).
  • Once the dynamic data is ready, the content is **streamed** to the client, replacing the fallback UI with the final, data-rich component.

Key Implementation Element

The core mechanism for triggering Partial Pre-rendering is the combination of an **`async` Server Component** (for dynamic data fetching) wrapped in a **`<Suspense>`** boundary:

export default function Page() {
  return (
    <main>
      {/* Static content runs immediately at build time */}
      <StaticContent />
      
      {/* Dynamic component is replaced by fallback until data arrives */}
      <Suspense fallback={<div>Loading products...</div>}>
        <DynamicProducts />
      </Suspense>
    </main>
  )}
