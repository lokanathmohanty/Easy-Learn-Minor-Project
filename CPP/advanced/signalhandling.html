C++ Signal Handling 🚦🚨

**Signals** are software interrupts delivered to a process by the operating system (OS) to notify it of an event, often an exceptional condition. Handling signals allows a program to clean up resources or log state before being terminated.

The C++ signal-handling library is provided via the header **<csignal>**.

Catchable Signals

Here are some of the standard signals defined that a C++ program can register a handler for:

SignalDescription
**SIGINT**Receipt of an **interactive attention signal** (e.g., Ctrl+C).
**SIGTERM**A **termination request** sent to the program (graceful shutdown).
**SIGFPE**An **erroneous arithmetic operation** (e.g., divide by zero).
**SIGSEGV**An **invalid access to storage** (Segmentation Fault).
**SIGABRT**Abnormal termination, such as a call to abort().
**SIGILL**Detection of an illegal instruction.

The signal() Function (Registering Handlers)

The core function for trapping unexpected events is **signal()**. It registers a specific signal number with a custom function (the signal handler) that should execute when that signal is received.

Syntax

void (*signal (int sig, void (*func)(int)))(int);

In simpler terms, it takes two arguments:

  1. The **signal number** to catch (e.g., `SIGINT`).
  2. A **pointer to the signal-handling function** (e.g., `signalHandler`), which must take a single `int` argument (the signal number) and return `void`.
// Register SIGINT (2) to be handled by signalHandler()
signal(SIGINT, signalHandler);

The signal handler function typically performs necessary cleanup before terminating the program (often via `exit(signum)`).

The raise() Function (Generating Signals)

The **raise()** function allows a program to **send a signal to itself** internally, simulating an external interrupt. This is often used for testing error handling routines.

Syntax

int raise (signal sig);

The example shows how a program can deliberately call its own signal handler by executing `raise(SIGINT)` at a specific point in the code.
