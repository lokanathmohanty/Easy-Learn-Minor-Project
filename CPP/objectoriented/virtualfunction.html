Virtual Function in C++ (Runtime Polymorphism) 🎯

A **virtual function** is a member function in a base class declared using the **virtual** keyword. Its purpose is to enable **runtime polymorphism** (also known as **dynamic binding** or **late binding**).

When a virtual function is called through a **base class pointer** or **reference**, the function executed is determined by the **actual type of the object** being pointed to, not the type of the pointer/reference.

Syntax

class BaseClassName {
public:
    virtual void func_name() {
        // Base implementation
    }
};
// Derived classes override the function:
class Derived : public BaseClassName {
public:
    void func_name() override { 
        // Derived implementation
    }
};

How Virtual Functions Enable Polymorphism

Virtual functions rely on two internal mechanisms:

  • **VTable (Virtual Table):** The compiler creates a table of function pointers for every class that contains virtual functions. This table stores the correct memory addresses of the virtual functions for that class.
  • **VPTR (Virtual Pointer):** Each object of a class with virtual functions contains a hidden pointer (vptr) that points to the VTable of its class.

At runtime, when a call like `shapePtr->draw()` is made, the program follows these steps:

  1. It looks at the `shapePtr` to find the object's hidden **VPTR**.
  2. It follows the VPTR to find the correct **VTable** for the object's actual type (e.g., `Circle`).
  3. It looks up the address of the `draw()` function in that VTable and executes the correct `Circle::draw()` method.

Key Rules for Using Virtual Functions

  • **Access:** They must be accessed via a **base class pointer or reference** to trigger dynamic binding. Direct calls using an object instance will result in static (compile-time) binding.
  • **Keyword:** The `virtual` keyword is required only in the **base class** declaration; it is optional (though recommended for clarity) in derived classes, where the `override` keyword is often used instead.
  • **Virtual Destructor:** A base class with virtual functions **must** have a **virtual destructor** (`virtual ~Base() {}`) to ensure that when a derived class object is deleted via a base class pointer (`delete basePtr;`), the derived class's destructor is called first. Failure to do so leads to **memory leaks**.
  • **Pure Virtual Functions:** A virtual function set to zero (`= 0`) is a **pure virtual function**. A class containing one or more pure virtual functions is an **abstract class** and cannot be instantiated.
