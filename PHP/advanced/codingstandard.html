PHP - Coding Standard Guidelines

Importance of Coding Standards

A **coding standard** is a set of rules and guidelines that every developer in a team must follow when writing source code. Its primary purpose is to ensure **consistency, readability, and maintainability** across a codebase, especially when multiple developers contribute to different modules. Consistent coding acts as a blueprint, simplifying peer reviews, reducing common errors, and making future code revisions easier.

PHP Coding Style Guidelines

Indentation and Line Length

  • **Indentation:** Use an indent of **4 spaces**. Avoid using the Tab character, as its width varies across different development environments.
  • **Line Length:** It is recommended to keep lines at approximately **75-85 characters** long for optimal readability.

Control Structures ($\text{if, for, while, switch}$)

  • **Spacing:** Use **one space** between the control keyword and the opening parenthesis (e.g., $\text{if (condition)}$).
  • **Braces:** Always use **curly braces ($\text{\{\}}$)**, even when they are technically optional (e.g., for a single statement $\text{if}$ block), to prevent errors and improve clarity.
  • **BSD/Allman Style:** The opening brace is typically placed on a new line.
if (condition) {
   action;
} elseif (otherCondition) {
   anotherAction;
} else {
   defaultAction;
}

Functions and Variables

  • **Function Calls:** Call functions with **no spaces** between the function name, the opening parenthesis, and the first parameter. Use a **single space** after commas separating parameters. 
    $var = foo($bar, $baz, $quux);
  • **Function Definitions:** Follow the **BSD/Allman style** (opening brace on a new line). 
    function fooFunction($arg1, $arg2 = '') {
   // statements
   return $val;
}
  • **Variable Names:** Use **all lower case letters** and the **underscore ($\text{\_}$)** as the word separator (e.g., $\text{\$user\_name}$).
  • **Variable Prefixes (Recommended):**
    • **Global variables:** Prepend with '$\text{g}$' (e.g., $\text{\$g\_config}$).
    • **Global constants:** Use **all caps** with underscores (e.g., $\text{GLOBAL\_CONSTANT}$).
    • **Static variables:** May be prepended with '$\text{s}$' (e.g., $\text{\$s\_count}$).

Other Guidelines

  • **PHP Code Tags:** Always use the full form: **$\text{}$**. **Never use the shorthand $\text{}$**, as it is less portable and can cause issues with $\text{XML}$ processing.
  • **Comments:** **$\text{/* */}$** (C-style) and **$\text{//}$** (C++-style) are both acceptable. The Perl/shell style $\text{\#}$ is allowed but discouraged.
  • **Statement per Line:** Use **only one statement per line**, unless the statements are very closely related.
  • **Reentrancy:** Functions should be designed to be **reentrant** (thread-safe); they should not rely on static variables that store state between calls.
  • **Method Length:** Methods or functions should be short, ideally limited to a single screen or page of code.
