C# Exception Handling

What is an Exception?

An **exception** is a problem or an abnormal event that arises during the execution of a program, such as an attempt to divide by zero (DivideByZeroException), referencing a null object (NullReferenceException), or accessing an array outside its bounds (IndexOutOfRangeException). Exception handling provides a structured way to manage these runtime errors.

The Four Exception Handling Keywords

C# exception handling relies on four keywords:

  • try: Identifies a block of code where an exception might occur. This block is considered "protected code."
  • catch: Identifies the block of code (the exception handler) that executes when a specific type of exception is thrown in the try block.
  • finally: Contains statements that are **always executed**, regardless of whether an exception was thrown or caught. It's ideal for cleanup tasks like closing files or releasing resources.
  • throw: Used to explicitly raise an exception, either a predefined system exception or a user-defined exception.

Basic Structure and Flow

The **try** block must be followed by at least one **catch** block or a **finally** block (or both). The system checks catch blocks sequentially.

try {
   // Code that might cause an exception (e.g., division)
   result = num1 / num2; 
} catch( DivideByZeroException e ) {
   // Handle specific division by zero error
   Console.WriteLine("Error: Cannot divide by zero.");
} catch( Exception ex ) {
   // Catch any other exception (should be listed last)
} finally {
   // This code runs unconditionally
   Console.WriteLine("Cleanup complete.");
}

Multiple Catch Blocks:

You can list multiple catch blocks, each tailored to a specific exception type (e.g., IndexOutOfRangeException, DivideByZeroException). When doing this, specific exceptions must be listed before the more general System.Exception base class.

Exception Classes and User-Defined Exceptions

All exception classes in C# are derived directly or indirectly from the **System.Exception** class.

Key Base Classes:

  • System.SystemException: The base class for all predefined, runtime exceptions (like NullReferenceException or DivideByZeroException).
  • System.ApplicationException: The recommended base class for **user-defined exceptions**.

Creating Custom Exceptions:

To define your own exception, you must derive a new class from System.Exception (or System.ApplicationException).

public class TempIsZeroException : Exception {
   // Constructor calls the base Exception constructor
   public TempIsZeroException(string message) : base(message) { }
}

public void showTemp() {
   if(temperature == 0) {
      throw (new TempIsZeroException("Zero Temperature found"));
   }
