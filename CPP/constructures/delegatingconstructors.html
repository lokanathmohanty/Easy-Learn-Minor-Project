C++ Delegating Constructors (Code Reusability) 🔁

**Delegating constructors** (available since C++11) allow one constructor in a class to call, or **delegate** to, another constructor within the **same class**. This feature significantly simplifies constructor implementation by reducing repetitive initialization code, adhering to the **DRY (Don't Repeat Yourself)** principle.

Instead of duplicating common setup logic across multiple constructors, you define one **Primary Constructor** that handles the complete initialization, and other constructors simply call that primary one.

Syntax and Rules

Syntax

Delegation is performed in the **initializer list** of the delegating constructor.

class Example {
   public:
      // Primary Constructor (handles the heavy lifting)
      Example(int value) : data(value) { /* ... */ }

      // Delegating Constructor (calls the primary constructor)
      Example() : **Example(0)** {} 
      
   private:
      int data;
};

Key Rules

  • A constructor can only delegate to **one** other constructor.
  • Delegation must occur only within the **same class**.
  • **Circular delegation** (where two constructors delegate to each other) is illegal and results in a compile-time error.

The **Student** example clearly demonstrates this:

// Primary: Student(name, age, grade)
// Delegates: Student(name, age) calls Student(name, age, 0.0)
// Delegates: Student(name) calls Student(name, 18, 0.0)

Advantages

Delegation offers several benefits for class maintenance:

  • **Centralized Initialization:** All essential setup logic is contained within the primary constructor, making the code easier to read and verify.
  • **Reduced Redundancy:** Code duplication is eliminated, ensuring that a critical piece of logic is written only once.
  • **Easier Maintenance:** If you need to change how an object is initialized (e.g., adding a new member), you only have to modify the single primary constructor.
