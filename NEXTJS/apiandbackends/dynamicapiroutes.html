Next.js Dynamic API Routes (Pages Router) 🔄

What are Dynamic API Routes?

**Dynamic API Routes** are server-side endpoints designed to handle requests where a part of the URL is a variable parameter (like a product ID, a username, or a slug). This allows a single API file to serve content for thousands of different resources.

In the **Pages Router** system, these routes are defined by enclosing the variable segment in **square brackets** (`[param]`) within the `pages/api` directory structure.

Creating and Accessing Dynamic Routes

To create a dynamic route that handles different user IDs, you use the folder/file naming convention:

  • **File Path:** `pages/api/user/[id].js`
  • **Endpoint:** `/api/user/[id]` (e.g., `/api/user/123`)

Accessing the Parameter:

The dynamic parameter is accessed via the **`req.query`** object inside the API route handler function, where the key is the name used in the square brackets.

// File: pages/api/user/[id].js
export default function handler(req, res) {
    // Access 'id' from the URL (e.g., /api/user/99)
    const { id } = req.query; 
    
    res.status(200).json({ message: `Fetching data for user ${id}` });
}

Handling HTTP Methods with Dynamic Routes

You can combine dynamic parameters with method handling to perform different operations (GET, DELETE, etc.) on the specific resource identified by the parameter.

// File: pages/api/user/[id].js
export default function handler(req, res) {
    const { id } = req.query; 
  
    if (req.method === 'GET') {
        // Handle requests like GET /api/user/99
        res.status(200).json({ message: `Fetching details for user ${id}` });
    } 
    else if (req.method === 'DELETE') {
        // Handle requests like DELETE /api/user/99
        res.status(200).json({ message: `User ${id} deleted successfully` });
    } 
    else {
        // Fallback for unsupported methods
        res.setHeader('Allow', ['GET', 'DELETE']);
        res.status(405).end(`Method ${req.method} Not Allowed`);
    }
}

Frontend Interaction Example:

The client component uses the local `userId` state to construct the dynamic API URL for both GET and DELETE operations.

// Function to fetch user details (GET request)
const fetchUserDetails = async () => {
  const response = await fetch(`/api/user/${userId}`);
  // ... handle response
};

// Function to delete user (DELETE request)
const deleteUser = async () => {
  const response = await fetch(`/api/user/${userId}`, 
                                { method: 'DELETE' });
  // ... handle response
};
