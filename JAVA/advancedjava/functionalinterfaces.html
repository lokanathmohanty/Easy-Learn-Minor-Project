Java Functional Interfaces (Java 8+)

The Role of Functional Interfaces

A **Functional Interface** is an interface that contains **exactly one abstract method**. They are a core component of Java's shift towards functional programming, enabling the use of **lambda expressions** and **method references**.

By enforcing a single abstract method, a functional interface provides a target type for a lambda expression, allowing a developer to concisely provide the implementation for that single method without the boilerplate of creating a full class or an anonymous inner class.

Key Characteristics

  • **Single Abstract Method (SAM):** The defining feature; only one method can be abstract.
  • **@FunctionalInterface Annotation:** This annotation is **optional**, but highly recommended. The compiler uses it to ensure the interface adheres to the SAM rule, preventing accidental addition of a second abstract method.
  • **Default and Static Methods:** A functional interface can contain any number of default and static methods, as these provide concrete implementations and do not violate the SAM rule.

Primary Built-in Functional Interfaces (java.util.function)

Java 8 introduced a comprehensive set of generic functional interfaces for common programming patterns. These can be grouped based on their abstract method's signature (Input $\rightarrow$ Output).

1. Predicate $\langle T \rangle$ (Test $\rightarrow$ Boolean) 🧐

  • **Abstract Method:** boolean test(T t)
  • **Purpose:** Used for conditional checks, filtering elements, or comparisons (returns true or false).
  • **Example:** Filtering a list to find only even numbers in a stream.
    • Predicate<Integer> isEven = n -> n % 2 == 0;
numbers.stream().filter(isEven);

2. Consumer $\langle T \rangle$ (Input $\rightarrow$ None) ➡️

  • **Abstract Method:** void accept(T t)
  • **Purpose:** Used for side-effect operations on an input, such as printing, logging, or adding to another collection. It consumes an argument but returns nothing.
  • **Example:** Printing each element in a collection.
    • Consumer<String> printer = System.out::println;
list.forEach(printer);

3. Supplier $\langle T \rangle$ (None $\rightarrow$ Output) 📦

  • **Abstract Method:** T get()
  • **Purpose:** Used to generate or supply a value, often implemented for **lazy generation** of data (e.g., getting a random number, retrieving a value from a cache, or providing a default in Optional.orElseGet()).
  • **Example:** Generating a random number.
    • Supplier<Integer> randomizer = () -> (int)(Math.random() * 10);
int num = randomizer.get();

4. Function $\langle T, R \rangle$ (Input $\rightarrow$ Output) 🔄

  • **Abstract Method:** R apply(T t)
  • **Purpose:** Used for transformation or mapping operations, taking an input of type T and returning a result of type R.
  • **Example:** Squaring every number in a list during a stream map operation.
    • Function<Integer, Integer> squared = value -> value * value;
numbers.stream().map(squared);

Variations and Existing Functional Interfaces

The core interfaces listed above have several variants for specialized cases:

  • **Bi-versions:** BiPredicate, BiConsumer, BiFunction accept **two** arguments.
  • **Primitive Specializations:** Interfaces like IntPredicate, LongConsumer, and DoubleFunction are used to avoid auto-boxing/unboxing of primitive types, improving performance.
  • **Specialized Functions:**
    • **UnaryOperator<T>:** Extends Function<T, T> where the input and output types are the same.
    • **BinaryOperator<T>:** Extends BiFunction<T, T, T> where all three types (two inputs, one output) are the same.

Pre-Java 8 Functional Interfaces

Many interfaces that existed before Java 8 already met the Single Abstract Method criteria, allowing them to be used with lambda expressions:

  • **Runnable:** Used for threads (void run()).
  • **Callable:** Used for concurrent tasks that return a value (V call() throws Exception).
  • **Comparable:** Used for sorting (int compareTo(T o)).
