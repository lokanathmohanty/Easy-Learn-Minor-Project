Java Programming: Enum Customization

Session: Enum Constructor

Why Use an Enum Constructor? 🛠️

By default, an **enum** constant's value is simply its name (e.g., WEEKDAY.MONDAY prints "MONDAY").

An **Enum Constructor** is used when you need to associate **additional data** (like descriptions, values, or codes) with each enum constant, allowing the enum to be more than just a name.

This provides a way to assign a specific, private value to each constant, which can then be retrieved via a public **getter method**.

Scope and Accessibility of Enum Constructors

Enum constants are automatically created by the Java runtime when the enum type is loaded. To enforce that **only** the constants defined within the enum itself can initialize it, Java imposes a strict rule on constructor modifiers:

An enum constructor can **only** be:

  • **Private:** Explicitly declared with the `private` keyword.
  • **Package-private (Default):** Declared with no modifier.

**Crucially, setting an enum constructor as public or protected will result in a compile-time error.**

Example: Enum with Private Constructor and Data

In this common pattern, a constructor is used to initialize a **final instance field** for each constant, and a public getter is provided for external access.

enum WEEKDAY {
	// Constants must be listed first, and must call the constructor
	MONDAY("Day 1"),
	TUESDAY("Day 2"),
	SUNDAY("Day 7");
	
	// Private instance field to hold the extra data
	private final String description;
	
	// Private constructor (valid)
	private WEEKDAY(String description) {
		this.description = description;
	}
	
	// Public getter method to safely expose the data
	public String getDescription () {
		return this.description;
	}
}

Accessing the custom data:

System.out.println(WEEKDAY.MONDAY.getDescription());
// Output: Day 1
System.out.println(WEEKDAY.MONDAY);
// Output: MONDAY (The default toString() method is not affected)
