.NET Core - PCL Troubleshooting: Fixing NuGet Compatibility Errors

This chapter addresses the **NuGet package installation error** encountered when attempting to add the StringLibrary to the **Xamarin.Forms PCL** project. The core issue is a compatibility mismatch between the library's required **.NET Standard version** and the PCL project's **Targeted Frameworks** (specifically, **Windows Phone Silverlight 8**).

Understanding and Fixing the PCL Profile Mismatch

The error occurs because the Xamarin.Forms PCL project defaults to a profile (often **Profile 259**) that limits its compatibility to **.NET Standard 1.0**. Since our StringLibrary was built targeting **.NET Standard 1.3** (as indicated by the dependencies), the platforms must be adjusted to allow for a higher compatible profile.

Steps to Retarget the PCL Profile:

  1. **Uninstall Xamarin.Forms**: To safely modify the PCL targets without conflict, first uninstall the main package by running the following command in the Package Manager Console: 
    PM > Uninstall-Package Xamarin.Forms
  2. **Change Targets**: Right-click on the PCL library project (e.g., [ProjectName].Portable) and select **Properties**. Click the **Change** button under the "Target frameworks" section.
  3. **Remove Incompatible Platform**: **Uncheck** the box next to **Windows Phone Silverlight 8**.

    (Windows Phone Silverlight 8 only supports **.NET Standard 1.0**; removing it allows the PCL to target a higher profile.)

  4. **Verify New Profile**: After clicking OK, the PCL project should be retargeted to a profile (such as **Profile 111**) that supports **.NET Standard 1.1** or higher, making it compatible with our **.NET Standard 1.3** library. You can confirm this by temporarily unloading the project and inspecting the .csproj file.

Reinstalling the StringLibrary Package

With the PCL project retargeted, the custom library can now be installed:

  1. Open the **Manage NuGet Packages** dialog for the PCL library.
  2. Select your **PrivateSource** from the Package source dropdown.
  3. Find and select the **StringLibrary** package.
  4. Before clicking Install, select **Ignore Dependencies** from the **Dependency behavior** dropdown (as an extra measure to bypass potential dependency conflicts).
  5. Click **Install**.

The **StringLibrary** package is successfully installed, and its reference should now appear under the PCL project's References node.

Reinstalling Xamarin.Forms

Since Xamarin.Forms was uninstalled in the first step, it must be reinstalled to restore the cross-platform UI functionality:

  • Use the NuGet Package Manager or Package Manager Console to reinstall the **Xamarin.Forms** package. It is recommended to install the **same version** that was previously used (or the latest stable version).

The Xamarin.Forms PCL project is now fully configured and ready to use the functionality provided by your custom **StringLibrary** in your cross-platform application.
