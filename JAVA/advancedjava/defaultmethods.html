Java Default Methods in Interfaces (Java 8+)

The Need for Default Methods

Default methods, also known as Defender Methods or Virtual Extension Methods, were introduced in **Java 8**. Their primary purpose is to provide **backward compatibility** when extending existing interfaces, particularly in the Java Collections Framework.

Prior to Java 8, adding a new method to an interface (like forEach to the Collection interface) would have broken every single existing implementation of that interface. Default methods solve this by allowing the interface to provide a **concrete, non-abstract implementation** for a method.

This allows new methods to be added to an interface without forcing all implementing classes to immediately provide an implementation.

Syntax

A default method is defined using the **default** keyword and must include a method body (implementation).

public interface MyInterface {
   // Abstract method (must be implemented by classes)
   void abstractMethod();

   // Default method (implementation is provided)
   default void defaultMethod() {
      System.out.println("Default implementation is here.");
   }
}

Rules for Default Methods

  • The implementing class inherits the default implementation.
  • The implementing class **can** override the default method, treating it like any other instance method.

Resolving Multiple Inheritance Ambiguity

Java does not support multiple inheritance of classes, but default methods introduce a form of **multiple inheritance of behavior** from interfaces, which can lead to ambiguity if a class implements two interfaces with the same default method signature.

Ambiguity Resolution Rules

When a class implements two interfaces that both define a default method with the same signature, the compiler requires the ambiguity to be resolved in one of two ways:

1. Overriding with a Class Implementation

The implementing class overrides the conflicting method, providing its own implementation. This is the simplest way to resolve the conflict, as the class's method implementation takes precedence over both interface default methods.

class Car implements Vehicle, FourWheeler {
   // Class implementation takes highest precedence
   public void print() { 
      System.out.println("I am a four wheeler car vehicle!");
   }
}

2. Calling a Specific Interface's Default Method

The implementing class overrides the method but chooses to delegate the call to the default implementation of one of the interfaces using the **InterfaceName.super.methodName()** syntax.

class Car implements Vehicle, FourWheeler {
   public void print() {
      // Explicitly calls the default method from the FourWheeler interface
      FourWheeler.super.print();
   }
}

Static Methods in Interfaces (Java 8+)

In addition to default methods, Java 8 also allowed interfaces to contain **static methods** with implementations.

  • **Purpose:** Static methods in interfaces are typically used as **utility functions** or helper methods related to the interface itself.
  • **Access:** Unlike default methods, which can be called on an implementing class instance, static interface methods must be called directly on the interface itself: **InterfaceName.staticMethod()**.
  • **Inheritance:** Static interface methods are **not inherited** by implementing classes or sub-interfaces.
public interface Vehicle {
   static void blowHorn() {
      System.out.println("Blowing horn!!!");
   }
}

// Accessing the static method
Vehicle.blowHorn();
