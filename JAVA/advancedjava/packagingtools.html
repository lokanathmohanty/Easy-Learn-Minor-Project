Java - Packaging Tool (jpackage)

Purpose and Introduction

The **jpackage** tool, introduced in **Java 14** (and replacing the older javapackager), is a command-line utility that enables developers to package Java applications into **native, platform-specific installers**. This ensures the end-user can install and run the Java application like any other software (e.g., a .exe on Windows or a .dmg on macOS), without needing a pre-installed JRE or JDK.

jpackage creates a self-contained application bundle that includes the application's code, dependencies, and a minimal, customized Java Runtime Environment (JRE) created using jlink.

Why is jpackage necessary?

Modern software distribution requires a seamless installation experience. jpackage addresses this by:

  • **Bundling the Runtime:** Including a minimal JRE with the application, eliminating the dependency on the user having a compatible Java installation.
  • **Native Format:** Generating installers specific to the operating system:
    • **Windows:** .exe, .msi
    • **macOS:** .pkg, .dmg
    • **Linux:** .deb, .rpm
  • **Customization:** Allowing developers to specify application icons, installation directories, JVM options, and more.

Prerequisites for Using jpackage

To create native installers, jpackage often relies on native platform-specific tools, which must be installed separately:

  • Windows: Requires a third-party tool like **WiX Toolset (version 3.0 or later)** for creating .exe and .msi installers.
  • Linux (Debian/Ubuntu): Requires the **fakeroot** package (for .deb).
  • Linux (Red Hat/Fedora): Requires the **rpm-build** package (for .rpm).
  • macOS: Requires **Xcode command-line tools**.

Example Command Syntax

The following command demonstrates packaging a Java application named APITester into a Windows MSI installer:

jpackage --input lib \
  --name APITester \
  --main-jar APITester.jar \
  --main-class com.tutorialspoint.APITester \
  --type msi \
  --java-options '-Xms512m'

Common Command Line Options:

  • --input <folder>: Specifies the directory containing the application's JAR files and resources.
  • --name <name>: The name of the resulting package and the application.
  • --main-jar <file>: The application's main JAR file.
  • --main-class <class>: The entry point class within the main JAR. (Optional if specified in MANIFEST.MF).
  • --type <type>: The desired output format (e.g., msi, dmg, deb).
  • --java-options <options>: Specifies options to be passed to the JVM when the application is launched (e.g., heap size, system properties).
