Next.js - Full Route Caching

What is Full Route Caching?

Full Route Caching is Next.js's default behavior where it statically generates and caches the **entire output** for a route (the HTML page, layout, and metadata) at build time. This technique serves the pre-rendered static HTML directly to users instead of rendering the page on the server for every request, which is key to achieving **faster page loads** and better scalability.

How It Works

During the application build process:

  • Next.js identifies routes that can be statically rendered.
  • The complete output for these routes is generated and cached.
  • Each subsequent request for a cached route is served the static HTML.
  • This cache persists across deployments unless specific data revalidation occurs. (Note: The **Data Cache** is the only cache that automatically persists across deployments).

Invalidating the Full Route Cache

The Full Route Cache can be updated or cleared in two main ways:

  • Revalidating Data: When the underlying **Data Cache** (which stores the results of fetch calls) is revalidated (e.g., using revalidatePath), Next.js re-renders the components on the server. The output of this new render then replaces the old entry in the Full Route Cache.
  • Redeploying: A new build and redeployment of the application will automatically clear the entire **Full Route Cache**, forcing all pages to be re-generated on their next access.

Clearing / Opting Out of Full Route Caching

For routes that must show fresh data on every request (e.g., personalized content, real-time data), you need to **opt out** of Full Route Caching and force Next.js to render dynamically at request time. This is done by triggering dynamic rendering.

1. Using export const dynamic = 'force-dynamic'

This setting explicitly forces the page to be rendered **dynamically** at the time of the request, bypassing the Full Route Cache entirely.

Example: Force Dynamic Rendering

// Set as force dynamic page
export const dynamic = 'force-dynamic'

async function getData() {
  const randomNumber = Math.floor(Math.random() * 100)
  return {
    timestamp: new Date().toISOString(),
    randomNumber
  }
}

export default async function Home() {
  const data = await getData()
  // Every time the page is refreshed, a new random number is generated
  return (
    <main>
      <h1>Force Dynamic Example</h1>
      <p>Random Number: {data.randomNumber}</p>
    </main>
  )
}

2. Using Dynamic APIs (Reading Request-time Data)

If a route uses dynamic server-side functions that rely on request-time information (like cookies, headers, or URL search parameters), Next.js will automatically detect this and opt the page out of Full Route Caching, forcing dynamic rendering.

Example: Reading Cookies and Headers

The use of cookies() and headers() inside the page component signals to Next.js that the output depends on runtime request data, making the route dynamic and uncached.

// app/dynamic-data/page.tsx
import { cookies, headers } from 'next/headers' // Importing these makes the page dynamic

export default function DynamicPage({searchParams,}: { searchParams: { [key: string]: string | string[] | undefined }})  {
    const cookieStore = cookies() // Accessing request cookies
    const headersList = headers() // Accessing request headers

    const theme = cookieStore.get('theme')
    
    return (
        <div>
            <h1>Dynamic Data Example</h1>
            <section>
            <h2>Cookies:</h2>
            <p>Theme Cookie: {theme?.value || 'Not set'}</p>
            </section>
        </div>
    )
}
