Java - Records (Java 16+)

Purpose of Java Records

Records are a concise and syntactical way to create **immutable data classes** (or **Data Transfer Objects/POJOs**) in Java, introduced as a standard feature in **Java 16**. Their primary goal is to drastically reduce the boilerplate code required for classes whose main purpose is to simply hold data.

Traditional data classes often required 50+ lines of repetitive code, including private fields, a parameterized constructor, public getter methods, and custom implementations of equals(), hashCode(), and toString().

A Java Record automatically generates this required boilerplate code from its declaration.

Features of Java Records

A record declaration specifies its **component list** (the fields), and the compiler automatically generates the following:

  • Fields: A private, final field for each component in the list (ensuring immutability).
  • Canonical Constructor: A public constructor whose signature matches the component list, which initializes the fields.
  • Accessors (Getters): A public accessor method for each component, named identically to the field (e.g., id(), not getId()).
  • Built-in Methods: Sensible implementations of **equals()**, **hashCode()**, and **toString()**, based on all components.

Record Declaration Syntax

record Student(int id, String name, String className) {}

Immutability and Constraints

  • The components of a Record are implicitly **final**, enforcing immutability.
  • Records implicitly extend the java.lang.Record class.
  • Records are implicitly **final** and cannot be extended by other classes, but they can **implement interfaces**.

Example: Conciseness Comparison

A traditional data class requiring a full suite of boilerplate methods is replaced by a single line when using a Record:

// Traditional Class (50+ lines)
class Student {
   private final int id;
   private final String name;
   // ... constructor, getters, equals, hashCode, toString ...
}

// Equivalent Record (1 line)
record Student(int id, String name, String className) {}

// Usage (Accessors use the component name)
Student student1 = new Student(1, "Mahesh", "XII");
System.out.println(student1.name()); 
System.out.println(student1.toString()); // Auto-generated output

Customizing Records

While the goal is brevity, you can customize a Record's behavior:

  • Custom Canonical Constructor (Compact Form): You can define a constructor without parameters or parentheses, primarily used for validation or normalization of component values. 
    record Range(int min, int max) {
   // Compact canonical constructor for validation
   public Range {
      if (min > max) {
         throw new IllegalArgumentException("Min cannot be greater than max.");
      }
   }
}
  • Overriding Methods: You can override any of the auto-generated methods (like toString()) to provide custom behavior. 
    record Student(int id, String name, String className) {
   @Override
   public String toString() {
      return "Id: " + id + ", Name: " + name; // Custom implementation
   }
}
