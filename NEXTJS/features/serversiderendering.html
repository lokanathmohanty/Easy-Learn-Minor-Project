Next.js Server-Side Rendering (SSR) 🖥️

What is Server-Side Rendering (SSR)?

**Server-Side Rendering (SSR)** is a performance technique in Next.js where the full **HTML page is generated on the server for *every* request**. This means that when a user requests a URL, the server:

  1. Receives the request.
  2. Fetches all necessary dynamic data (e.g., from an API or database).
  3. Renders the complete, data-filled HTML page.
  4. Sends this fully formed HTML directly to the user's browser.

This process results in faster initial page loads and improved visibility for **Search Engine Optimization (SEO)**, as search engine crawlers receive ready-to-use content.

Implementing SSR

Page Router (Legacy) Implementation: `getServerSideProps`

In the older **Page Router** system, SSR is explicitly implemented by exporting the asynchronous function **`getServerSideProps()`** from a page file. This function runs on the server every time the page is requested.

export async function getServerSideProps() {
    // Data is fetched on *each* request
    const response = await fetch('https://link/to/api');
    const data = await response.json();

    // The data is passed as props to the component
    return { props: { data } }; 
}

App Router Implementation (Current)

In the new **App Router**, a default **Server Component** performs SSR by simply using `await fetch(...)` directly inside the component function. This achieves the same per-request fetching and rendering behavior as `getServerSideProps`.

export default async function SSRPage() {
    const response = await fetch('https://link/to/api', { cache: 'no-store' }); 
    const data = await response.json();
    
    return (
        <h1>Server-Side Rendered Data</h1>
        // ... display data ...
    );
}

SSR vs. Client-Side Rendering (CSR)

The difference lies in *where* and *when* the HTML is generated and populated with data:

Feature Server-Side Rendering (SSR) Client-Side Rendering (CSR)
**Where HTML is Rendered** Server (on every request) Browser (after initial HTML load)
**Initial Content Speed** **Very Fast** (User sees content instantly) **Slower** (User sees a blank/loading screen first)
**Data Freshness** Always **Up-to-date** on page load Up-to-date after JavaScript fetches data
**SEO Performance** **Excellent** (Content is fully present) Poor/Moderate (Crawlers may struggle with content)

CSR requires the user's browser to download, parse, and execute the JavaScript bundle before it can fetch data and render the final UI, often showing a **loading state** (`Loading...`) until the data is ready.
