Java Programming: Object-Oriented Concepts

Session: Encapsulation (Data Hiding)

What is Encapsulation?

**Encapsulation** is one of the four foundational OOP concepts (along with Inheritance, Polymorphism, and Abstraction). It is the mechanism of **wrapping data (variables) and the code that acts on the data (methods) together as a single unit** (a class). This concept is also known as **data hiding**.

The goal is to restrict direct access to the data, ensuring that variables can only be manipulated through a class's controlled methods.

Achieving Encapsulation in Java

Encapsulation is achieved by following two steps:

  1. Declare the instance **variables** (fields) of a class as **`private`**. This hides them from other classes.
  2. Provide **`public` setter** methods (to modify/write) and **getter** methods (to view/read) to access the private variables indirectly.

Example: Encapsulated Class (EncapTest)

The variables are private, but public methods provide controlled access points (Getters and Setters):

public class EncapTest {
   private String name; // Private (Hidden)
   private int age;     // Private (Hidden)

   // Public Getter (Read access)
   public String getName() {
      return name;
   }

   // Public Setter (Write access, can include validation)
   public void setAge(int newAge) {
      // Logic control can be added here, e.g., if(newAge > 0)
      age = newAge;
   }
}

Key Benefits of Encapsulation

  • **Data Hiding:** The class's internal state is protected from unauthorized access or modification by external classes.
  • **Control:** The class maintains **total control** over what values are stored in its fields, as logic (like validation) can be implemented inside the setter methods.
  • **Flexibility (Read/Write Control):** You can create classes that are **Read-Only** (by providing only getters) or **Write-Only** (by providing only setters), tailoring access as needed.
  • **Maintainability:** Changes to the internal data structure of the class don't affect external code, as long as the public getter/setter method signatures remain the same.

Access Control: Read-Only and Write-Only

By selectively implementing accessors, a class can restrict interaction with its private fields:

  • **Read-Only Class:** Only **Getter** methods are provided (e.g., to view a person's age, but not change it after creation).
  • **Write-Only Class:** Only **Setter** methods are provided (e.g., to set a password, but never read it back for security reasons).
