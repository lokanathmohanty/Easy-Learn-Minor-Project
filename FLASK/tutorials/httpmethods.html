Flask and HTTP Methods: Handling Form Data 💻

The **HTTP protocol** defines various methods for client-server communication, which form the foundation of the web. By default, Flask routes only accept **GET** requests, but you can explicitly specify the allowed methods using the methods argument in the @app.route() decorator.

Summary of Key HTTP Methods

  • **GET:** Used for **data retrieval**. Sends data unencrypted, typically via URL parameters (query string). This is the most common method.
  • **POST:** Used to **submit data** (like HTML form data) to be processed to a specified resource. Data is sent in the request body and is generally not cached.
  • **HEAD:** Identical to GET, but the server does not return a response body; useful for checking resource existence or metadata.
  • **PUT:** Used to **replace** a target resource's current representation with the uploaded content.
  • **DELETE:** Used to **remove** a target resource given by a URL.

Example: Conditional Handling of POST and GET

The example demonstrates how the Flask **request** object is used to process data submitted via a form, determining whether the data arrived through a **POST** or **GET** request.

The Flask login() Function

The route /login is configured to handle both POST and GET methods:

@app.route('/login',methods = ['POST', 'GET'])

Inside the login() function, the **request.method** attribute is checked to dictate how the submitted data is retrieved:

Data Retrieval Logic:

  • **If POST (Form Submission):**

    The data (e.g., nm) is retrieved from the request body using the **request.form** dictionary (e.g., user = request.form['nm']).

    This happens when the form is submitted with method = "post".

  • **If GET (URL Query String):**

    The data (e.g., nm) is retrieved from the URL query parameters using the **request.args** dictionary (e.g., user = request.args.get('nm')).

    This happens when the form is submitted with method = "get".

In both cases, the application uses **redirect(url_for('success', name = user))** to pass the retrieved user name to the /success/<name> route, which then displays the welcome message.
