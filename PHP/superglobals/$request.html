PHP `$_REQUEST` Superglobal

The **`$_REQUEST`** is a **superglobal associative array** in PHP used to collect user input data. Its primary function is to act as a convenience variable by aggregating data from the `$_GET`, `$_POST`, and `$_COOKIE` superglobals into a single array.

Sources of Data for `$_REQUEST`

`$_REQUEST` can contain data from three methods of transmission:

  • **`$_GET`:** Variables passed via the URL query string (e.g., `?key=value`).
  • **`$_POST`:** Variables passed via an HTTP POST request (typically from an HTML form).
  • **`$_COOKIE`:** Variables passed via HTTP Cookies.

Order of Data Precedence

The order in which these sources are registered in the `$_REQUEST` array is controlled by the **`request_order`** directive in the PHP configuration file (`php.ini`). If a variable name exists in more than one source (e.g., in both `GET` and `POST`), the value assigned to `$_REQUEST` depends on this precedence order.

Usage with GET and POST Methods

Using `$_REQUEST` with GET

If the URL is accessed with a query string like http://localhost/script.php?first_name=Amar, the value can be collected using `$_REQUEST`.

echo $_REQUEST['first_name'];

Output: Amar

Using `$_REQUEST` with POST

If an HTML form submits data using the `method="post"` attribute, the data can also be collected using `$_REQUEST`.

*In the receiving PHP script:*
if ($_SERVER["REQUEST_METHOD"] == "POST") {
   echo $_REQUEST['last_name'];
}

Security Considerations ⚠️

While convenient, using `$_REQUEST` without care is generally discouraged due to security concerns:

  • **Ambiguity:** It makes the source of the data ambiguous. A developer cannot tell if the input came from a legitimate form POST, a manipulated URL (GET), or a tampered cookie.
  • **Security Risk:** If a script expects a variable via POST but is vulnerable to cookie or URL manipulation, a malicious user could potentially override expected data by injecting a variable through a different, higher-precedence source.

**Best Practice:** It is safer and clearer to use **`$_GET`**, **`$_POST`**, or **`$_COOKIE`** directly when you know and expect data from a specific method. Always **clean and validate** user input to prevent vulnerabilities like SQL injection and Cross-Site Scripting (XSS).
