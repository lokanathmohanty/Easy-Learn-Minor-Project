Django Application Life Cycle: Creation and Registration 📦

In Django, a **project** is a collection of one or more independent **applications** (or "apps"). An application is a self-contained module with a specific objective (e.g., a contact form, a blog) that can be easily reused in different projects.

Creating an Application

An application is created within the main project directory (the folder containing manage.py) using the manage.py utility:

$ python manage.py startapp myapp

This command creates a new folder named myapp with the following default application structure:

myapp/
   __init__.py
   admin.py
   models.py
   tests.py
   views.py

Application Structure

Each file in the application folder serves a specific purpose tied to the MVT pattern:

  • **__init__.py:** A standard Python file that marks the directory as a Python package.
  • **models.py:** This is the **Model** component of the MVT pattern. It defines the application's data structure and handles interaction with the database via Django's ORM.
  • **views.py:** This is the **View** component. It contains the business logic, handles HTTP requests, interacts with the models, and prepares the data to be sent to a template.
  • **admin.py:** Used to register your models with the Django administration site, allowing you to easily view, create, update, and delete application data.
  • **tests.py:** Reserved for defining unit tests to ensure the application's functionality works correctly.

Registering the Application

After creating the application, the Django project must be informed that the application exists and should be loaded. This is done by adding the application's name to the **INSTALLED_APPS** setting in the project's **settings.py** file:

INSTALLED_APPS = (
   'django.contrib.admin',
   # ... (other default apps)
   'django.contrib.staticfiles',
   'myapp',  <-- Your new application
)

Once registered, the Django framework includes the application in the overall project environment.
