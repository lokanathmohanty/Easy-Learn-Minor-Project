Creational Design Patterns in C++ 🏭🏗️

**Creational Design Patterns** are a category of patterns concerned with **object creation mechanisms**. Their goal is to abstract the instantiation process, making the system independent of **how its objects are composed and created**.

By hiding the creation logic from the client code, these patterns achieve **loose coupling**, making the system easier to change, extend, and maintain (the "pizza delivery" analogy).

Purpose and Benefits

Creational patterns address problems where:

  • The code needs to produce objects but shouldn't be fixed on a **specific concrete class** (decoupling).
  • The type of object needed won't be known until **runtime**.
  • Building an object requires many **complicated steps** that shouldn't be scattered throughout the code.
  • You must ensure there is just a **single copy** of a specific resource in the entire program (e.g., a logger, a configuration manager).

Types of Creational Design Patterns

The five main types of creational patterns are:

  1. **Singleton Pattern:** Ensures a class has **only one instance** and provides a global point of access to it.
  2. **Factory Method Pattern:** Defines an interface for creating an object, but lets subclasses decide which class to instantiate. It **defers instantiation** to derived classes.
  3. **Abstract Factory Pattern:** Provides an interface for creating **families of related or dependent objects** without specifying their concrete classes (e.g., creating a family of GUI elements that all look "Dark Theme" or "Light Theme").
  4. **Builder Pattern:** Separates the construction of a complex object from its representation, allowing the same construction process to create **different representations** (e.g., building a simple or luxury car using the same steps).
  5. **Prototype Pattern:** Creates new objects by **cloning** an existing object (the prototype). This is used to avoid the cost of creation, especially when the object's initial state is expensive to set up.

Example Overview (Factory, Builder, Singleton)

The provided example uses three patterns together:

  • **Factory Method (`PizzaFactory::createPizza`):** Takes a string (`"Margherita"`) and returns an object that adheres to the `Pizza` interface, hiding the `new Margherita()` call.
  • **Builder (`PizzaBuilder`):** Orchestrates the creation process, taking steps to produce the final `Pizza` object, centralizing the construction logic.
  • **Singleton (`PizzaSingleton::getInstance`):** Guarantees that only one instance of the `PizzaSingleton` class can exist throughout the program's lifetime.
