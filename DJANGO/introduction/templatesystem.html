Django Template System (DTL) 🎨

Django's **Template System** is the **presentation layer** of the MVT architecture, enabling a clear separation of concerns: **Python logic** goes in **Views** (views.py), and **HTML markup** goes in **Templates**.

The render Function

The render() function is the bridge that links the View logic to the Template output. It takes three essential parameters:

  1. **request:** The initial HttpRequest object.
  2. **Path to the Template:** The template file path (relative to the TEMPLATE_DIRS setting).
  3. **Dictionary of Parameters (Context):** A dictionary containing the variables and data (known as the **context**) that the template needs to display. (Using locals() is a shortcut to pass all local variables).

Django Template Language (DTL)

DTL uses a simple mini-language syntax distinguished by special delimiters:

1. Displaying Variables {{ variable }}

Variables are placeholders enclosed in double curly braces. Django replaces them with the corresponding value from the context dictionary supplied by the view.

If a variable is an object (not a string), Django calls its __str__ method to display it. You can access object attributes or dictionary keys using a dot (e.g., {{ today.year }}).

2. Filters {{ variable|filter:argument }}

Filters are used to **modify variables at display time** without altering the underlying data. They are applied using the pipe symbol (|).

  • {{ string|lower }}: Converts the string to lowercase.
  • {{ string|truncatewords:80 }}: Displays only the first 80 words of the string.
  • {{ string|escape|linebreaks }}: Applies multiple filters: first escapes unsafe characters, then converts line breaks into <br> or <p> tags.

3. Tags {% tag %}

Tags provide procedural logic, enabling complex operations like loops, conditionals, and template inheritance. They are enclosed in curly braces and percent signs.

Conditional Logic ({% if %})

Supports `if`, `elif`, and `else` statements, similar to Python, for conditionally rendering content:

{% if today.day == 1 %}
    the first day of month.
{% elif today.day == 30 %}
    the last day of month.
{% else %}
    I don't know.
{%endif%}

Looping ({% for %})

Allows iteration over lists or other iterable data passed from the view:

{% for day in days_of_week %}
    <p>{{ day }}</p>
{% endfor %}

Template Inheritance ({% extends %} and {% block %})

This is Django's mechanism for code reuse and maintaining a consistent site structure:

  • **{% block name %}...{% endblock %}** (in the base template, e.g., main_template.html): Defines "holes" or regions that child templates can fill.
  • **{% extends "base.html" %}** (in the child template, e.g., hello.html): Specifies the parent template to inherit from.
  • **Child Template Block:** To fill a block, the child template uses the same block tag name (e.g., {% block title %}My Page{% endblock %}). Any content in the child block will override the content in the parent block.

Comment Tag

Used to add notes within the template that **will not appear in the rendered HTML source code** (unlike HTML comments): {% comment %} This note is only for developers. {% endcomment %}
