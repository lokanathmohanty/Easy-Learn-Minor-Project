PHP - Input Sanitization Techniques

What is Input Sanitization?

Input sanitization is the crucial process of cleaning user-provided data by removing potentially harmful or undesired characters and code before it's processed by server-side scripts. The main goals are Security (preventing attacks like XSS and SQL Injection), Data Integrity (ensuring stored information is consistent), and improving User Experience (reducing errors).

Core Sanitization Functions

The $\text{htmlspecialchars()}$ Function

This function is essential for preventing **Cross-Site Scripting (XSS)** attacks when displaying user input as HTML. It converts special characters to their corresponding HTML entities, rendering them harmless (e.g., they will be displayed as text instead of executed as code).

  • < (less than) becomes &lt;
  • > (greater than) becomes &gt;
  • " (double quote) becomes &quot; (unless $\text{ENT\_NOQUOTES}$ is set)
  • ' (single quote) becomes &#039; (when $\text{ENT\_QUOTES}$ is set)

The $\text{strip\_tags()}$ Function

This function removes all HTML and PHP tags from a string. It is useful for enforcing plain text content in fields where no formatting is allowed. An optional second parameter ($\text{\$allowed\_tags}$) can specify tags that should be preserved.

<?php
   $text = '<p>Hello World</p><a href="#">Click</a>';
   echo strip_tags($text);             // Output: Hello World Click
   echo strip_tags($text, '<a>');   // Output: Hello World<a href="#">Click</a>
?>

Content Example: $\text{filter\_var()}$ and SQL Safety

The $\text{filter\_var()}$ Function

This versatile function can sanitize input using predefined filter constants ($\text{\$filter}$). It is often preferred for specific data types.

Examples of Sanitize Filters:

  • $\text{FILTER\_SANITIZE\_EMAIL}$: Removes all characters except letters, digits, and valid email symbols.
  • $\text{FILTER\_SANITIZE\_URL}$: Removes all characters except letters, digits, and valid URL symbols.
  • $\text{FILTER\_SANITIZE\_NUMBER\_INT}$: Removes all characters except digits, plus, and minus signs.
  • $\text{FILTER\_SANITIZE\_FULL\_SPECIAL\_CHARS}$: Equivalent to $\text{htmlspecialchars()}$ with $\text{ENT\_QUOTES}$ set.
<?php
   $a = 'abc def@xyz.com';
   $sa = filter_var($a, FILTER_SANITIZE_EMAIL);
   // Output: abcdef@xyz.com
?>

Database Escaping (SQL Injection Prevention)

To prevent **SQL Injection** attacks, special characters in user input must be properly escaped before being used in a database query.

  • **$\text{mysqli\_real\_escape\_string()}$:** Escapes special characters (like $\text{'}$, $\text{"}$, $\text{\}$, $\text{\textbackslash n}$) in the string for use in an $\text{SQL}$ statement, based on the current connection's character set. This is the **correct and modern** way to escape data before constructing a query (though using prepared statements is the superior method).
  • **$\text{addslashes()}$ (Discouraged):** Simply adds backslashes before $\text{'}$, $\text{"}$, $\text{\}$, and $\text{NUL}$. This function is generally considered unsafe for database use as it is character-set unaware and not robust enough against all SQL injection techniques.
<?php
   // Using MySQLi object-oriented approach (Recommended for escaping)
   $conn = new mysqli("localhost", "user", "pass", "db");
   $user_input = "O'Reilly";
   $safe_input = $conn->real_escape_string($user_input); 
   // $safe_input will be: O\'Reilly
   $query = "SELECT * FROM users WHERE name = '$safe_input'";
?>
