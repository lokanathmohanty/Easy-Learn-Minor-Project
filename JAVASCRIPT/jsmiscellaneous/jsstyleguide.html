JavaScript - Style Guide

A JavaScript style guide is a set of rules that define how code should be written. It ensures consistency, readability, and maintainability, especially in large projects where multiple developers collaborate. Following a style guide avoids confusion and makes complex codebases easier to manage.

Code Indentation

Indent your code using a fixed number of spaces (commonly 2, 3, or 4) and avoid trailing white spaces.

<html>
<body>
   <h2>Indentation Conventions</h2>
   <div id="output"></div>
   <script>
      const output = document.getElementById('output');
      function func() {
         output.innerHTML = "Function executed!";
         return 10;
      }
      func();
   </script>
</body>
</html>

Comments

Prefer single-line comments (//) instead of block comments, and align them neatly with the code.

<html>
<body>
   <h2>Comment Conventions</h2>
   <div id="output"></div>
   <script>
      const output = document.getElementById('output');
      output.innerHTML = "Hello World!";
      // var a = 10;
      // var b = 20;
   </script>
</body>
</html>

Variable Declaration

Always declare variables at the top of their scope, whether global or local. Variable names must start with a letter.

<html>
<body>
   <h2>Variable Conventions</h2>
   <div id="output"></div>
   <script>
      var a = 10;
      var b = 20;
      document.getElementById('output').innerHTML =
         "The sum of 10 and 20 is: " + (a + b);
   </script>
</body>
</html>

Identifier Names in camelCase

Identifiers (variables, functions, objects, etc.) should follow camelCase convention: start with a lowercase letter, and capitalize the first letter of subsequent words.

<html>
<body>
   <h2>camelCase Conventions</h2>
   <div id="output"></div>
   <script>
      var greetMessage = "Hello Developers!";
      let output = document.getElementById('output');
      // Function name with camelCase
      function executeGreet() {
         output.innerHTML = greetMessage;
      }
      executeGreet();
   </script>
</body>
</html>

Spaces and Brackets

Use white space before and after operators, and around brackets for readability.

<html>
<body>
   <h2>Spaces and Brackets Conventions</h2>
   <div id="output"></div>
   <script>
      let output = document.getElementById('output');
      if (9 > 10) {
         output.innerHTML += "9 is greater than 10";
      } else {
         output.innerHTML += "9 is not greater than 10";
      }
   </script>
</body>
</html>

Object Rules

Objects should be written with each property on a new line, separated by commas, and without a trailing comma after the last property.

<html>
<body>
   <h2>Object Conventions</h2>
   <div id="output"></div>
   <script>
      const obj = {
         prop1: 'value1',
         prop2: 'value2',
         prop3: 'value3'
      };
      document.getElementById("output").innerHTML =
         JSON.stringify(obj, null, 2);
   </script>
</body>
</html>

Statement Rules

Statements can be:

  • Simple one-line: must end with a semicolon.
  • Compound: opening bracket on the same line, body on the next line, no semicolon after the closing bracket.
  • Multi-line: break long conditions or expressions after operators.
<html>
<body>
   <h2>Statement Guidelines Conventions</h2>
   <div id="output"></div>
   <script>
      const output = document.getElementById('output');
      // Simple one-line statement
      const arr = ["one", "two", "three"];

      // Compound statement
      for (let i = 0; i < arr.length; i++) {
         output.innerHTML += arr[i] + "<br>";
      }

      // Multi-line statement
      if (10 > 9 && 10 > 5 && 10 > 6) {
         output.innerHTML +=
            "10 is greater than 9 and 10 is greater than 5 <br>";
      }
   </script>
</body>
</html>

Line Length

Keep lines within 80 characters. Break long strings or code into multiple lines for readability.

<html>
<body>
   <h2>Line Length Conventions</h2>
   <div id="output"></div>
   <script>
      let str = `This is too long a sentence.
         Let's put the limit of 80 characters.`;
      document.getElementById('output').innerHTML = str;
   </script>
</body>
</html>

Conclusion

Following a style guide ensures that code remains consistent, clean, and maintainable. While the rules above are common, teams may define their own conventions, but consistency across the project is essential.
