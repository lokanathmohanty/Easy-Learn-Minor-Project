Next.js - Authorization

What is Authorization?

Authorization is the critical process that occurs after a user is authenticated (logged in). It determines what actions the verified user is **permitted to perform** and what resources (pages, routes, API endpoints) they are **allowed to access** within the application.

Types of Authorization Checks

Next.js applications commonly employ two types of authorization checks based on speed and security requirements:

  • Optimistic Authorization:

    The check is performed quickly using **session data stored in the cookie** (stateless session). These checks are generally used for:

    • Showing or hiding UI elements (e.g., an "Admin" button).
    • Client-side redirects based on basic roles or permissions.
  • Secure Authorization:

    The check is performed using a **token or session ID verified against the database** (database session). These checks are used for:

    • Authorizing access to critical **API endpoints**.
    • Validating complex user actions (e.g., deletion, financial transaction).

Implementation Steps

To implement a robust authorization system, developers should follow these steps:

  1. Create a **Data Access Layer (DAL)** to centralize authorization logic.
  2. Utilize **Data Transfer Objects (DTOs)** to limit exposed data.
  3. Use **Middleware** for optional optimistic checks (e.g., route protection).

Step 1: Create a Data Access Layer (DAL)

The DAL centralizes all database operations and authorization checks. It must contain logic to verify the user's session token/cookie on the server for secure access control.

Example: Verifying Session and Redirecting (Secure Check)

This server-side function decrypts the session cookie and redirects the user if the session is invalid or missing, ensuring unauthorized users cannot proceed.

// app/lib/auth.ts
import 'server-only'
import { cookies } from 'next/headers'
import { decrypt } from '@/app/lib/session'
import { redirect } from 'next/navigation'
import { cache } from 'react'

export const verifySession = cache(async () => {
    const cookie = (await cookies()).get('session')?.value
    const session = await decrypt(cookie)
    
    if (!session?.userId) {
        // If session is invalid, securely redirect to login
        redirect('/login') 
    }
    
    // Return key authorization data
    return { isAuth: true, userId: session.userId }
})

Step 2: Use Data Transfer Objects (DTOs)

DTOs are objects used to transfer data between the client and server. They help **minimize the data sent to the client** by only including necessary user information, improving performance and security by preventing over-exposure of sensitive database fields.

Example User DTO:

// app/lib/definitions.ts
export type User = {
    id: number
    name: string
    email: string
}
