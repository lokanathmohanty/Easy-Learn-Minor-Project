Next.js File Conventions (App Router) ⚙️

What are File Conventions?

**File conventions** in Next.js refer to the special filenames and folder structures that the framework automatically recognizes and uses to define core application logic, routing, and UI behaviors. By naming files according to these conventions, you instruct Next.js how to handle aspects like layouts, error handling, loading states, and API endpoints without explicit configuration.

Key File Conventions in the `app` Directory

The table below summarizes the core reserved files used within the **App Router** for structural and behavioral purposes:

File Name Purpose Function
`page.js`/`.tsx` **Route UI** Defines the unique UI component for a specific, accessible route segment.
`layout.js`/`.tsx` **Shared Layout** Defines persistent UI (e.g., header, footer, sidebar) that wraps nested routes.
`loading.js`/`.tsx` **Loading State** Defines the loading UI shown while a page's data is being fetched (using React Suspense).
`error.js`/`.tsx` **Error Boundary** Creates an isolated error UI to gracefully handle runtime errors in nested routes.
`not-found.js`/`.tsx` **404 Page** Defines the custom UI for when a route is not found (404 error).
`template.js`/`.tsx` **Reusable Template** Wraps child layouts/pages but remounts components on navigation (unlike `layout.js`).
`route.js`/`.ts` **API Endpoint** Defines a custom server-side HTTP request handler (API Route).
`middleware.js`/`.ts` **Request Handler** Allows running code before a request is fully processed (e.g., for redirects or header modification).

Less Common Conventions:

  • `default.js`: Provides fallback UI content when a parallel slot's URL doesn't match a dedicated route.
  • `instrumentation.js`: Used to define custom logic for tracking and monitoring application activity before the server starts.
