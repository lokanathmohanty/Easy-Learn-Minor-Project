Java - Hidden Classes (Java 15+)

The Concept of Hidden Classes

Hidden Classes were introduced in **Java 15** (JEP 371) to provide a standard and reliable way for frameworks to generate classes dynamically at runtime. A hidden class is a class that is **non-discoverable** and cannot be used directly by the bytecode of other, non-hidden classes.

The primary use case is for **JVM language implementations and dynamic proxies** (like those used in serialization or reflection-heavy frameworks) that need to generate short-lived, internal helper classes.

Key Characteristics and Goals

  • Non-Discoverable: Hidden classes are not linked to by other classes and cannot be found via reflection (e.g., Class.forName()). They do not have a canonical name, which prevents accidental or unauthorized use.
  • Limited Lifecycle: They are designed for **aggressive unloading** by the JVM's Garbage Collector. This allows frameworks to generate many temporary classes without causing performance degradation or excessive memory use.
  • Access Control: A hidden class is defined as a member of the **Based Access Control Context** (specifically, a nestmate of the class that defined it), allowing it access to private members of the original class's nest.
  • Standard API: They provide a secure replacement for the deprecated, non-standard method sun.misc.Unsafe::defineAnonymousClass.

Creating a Hidden Class

Hidden classes are defined using the **java.lang.invoke.MethodHandles.Lookup** class, which acts as the factory for dynamic class creation.

The process involves three main steps:

  1. Obtain Lookup: Get a MethodHandles.Lookup instance. 
    MethodHandles.Lookup lookup = MethodHandles.lookup();
  2. Define Class: Use defineHiddenClass(), passing the bytecode of the class to be hidden, along with relevant options (like ClassOption.NESTMATE to grant nest access). 
    Class hiddenClass = lookup.defineHiddenClass(
    byteArray, // Byte array containing the class bytecode
    true, 
    ClassOption.NESTMATE
).lookupClass();
  3. Use Instance: The hidden class can then be instantiated and used via reflection, allowing the framework to execute its internal logic. 
    Object hiddenClassObj = hiddenClass.getConstructor().newInstance();

Example: Properties of a Hidden Class

When inspected, a hidden class confirms its non-discoverable nature:

// Assuming 'hiddenClass' is the dynamically defined class

// Check if it's a hidden class
System.out.println(hiddenClass.isHidden()); 
// Output: true

// Check its canonical name (will be null)
System.out.println(hiddenClass.getCanonicalName()); 
// Output: null
