C++ Concurrency and Thread Management 🔄

**Concurrency** is the ability of a system to manage multiple tasks or processes in an **overlapping** manner, allowing them to progress independently. It focuses on the **structure and management** of tasks to improve efficiency.

  • **Concurrency** (Managing multiple tasks) is not always **Parallelism** (Simultaneously executing tasks on multiple cores).

Threads in C++ (<thread>)

A **thread** is the smallest unit of execution within a process, providing a separate, independent path of execution. The `<thread>` library provides the tools to create and manage threads in modern C++ (C++11 and later).

  • **Creation:** An std::thread object is constructed with the function to be executed by the new thread.
  • **t.join():** Makes the calling thread (e.g., `main`) wait for the thread `t` to complete its execution.
std::thread t(my_function); // Create and start thread
t.join();                   // Wait for thread to finish

Thread Synchronization (Preventing Data Races)

When multiple threads share resources (like variables in memory), synchronization mechanisms are required to ensure data integrity and prevent **data races**.

Mutex (std::mutex)

A **Mutex** (Mutual Exclusion) is a locking primitive that ensures only one thread can access a critical section of code at a time.

  • **std::lock_guard**: A simple **RAII** (Resource Acquisition Is Initialization) wrapper that locks the mutex upon creation and automatically unlocks it when it goes out of scope.
  • **std::unique_lock**: A more flexible lock manager that allows manual unlocking, re-locking, and use with condition variables.

Condition Variables (std::condition_variable)

These allow threads to block (wait) until a certain condition is met or another thread notifies them. They facilitate inter-thread communication.

  • **`wait()`**: Blocks the thread until notified.
  • **`notify_one()`**: Wakes up one waiting thread.
  • **`notify_all()`**: Wakes up all waiting threads.

Atomic Variables (std::atomic)

Atomic variables guarantee that operations on them (read, write, or read-modify-write) are indivisible and completed without interference from other threads, making them thread-safe for simple data types without needing a mutex.

Asynchronous Execution (<future>)

Asynchronous programming manages the communication of a result from one thread (a producer) to another (a consumer) without blocking the consumer unnecessarily.

  • **std::promise**: A mechanism used by a thread to **set a value or an exception** asynchronously.
  • **std::future**: An object used by another thread to **retrieve the value** set by the `std::promise`. Calling `future::get()` will block until the result is ready.
  • **std::async**: A utility that conveniently **launches a task asynchronously** and immediately returns an std::future object, simplifying the use of promises and futures.
