Next.js - Caching Mechanisms

What is Caching?

Caching is a core optimization technique in web applications where data is stored either in server memory or on the client's browser. Its purpose is to allow for **quick access** to this data, which significantly reduces load times, improves overall performance, and minimizes server load. Next.js provides several sophisticated mechanisms for both server-side and client-side caching.

Caching Mechanisms in Next.js

Next.js implements four distinct caching mechanisms, operating across the server and client to optimize data fetching and navigation:

Mechanism Description Used On
Request Memoization Re-uses the result of identical fetch or data requests within the **same React component render cycle** to prevent duplicate data fetching. Server
Data Cache Stores the results of fetch requests on the server, persisting the data across multiple user requests and server renders. This is the **primary data caching layer**. Server
Full Route Cache Caches the entire **HTML page output** (including the React Server Component Payload) on the server to be served quickly to the client. Server
Router Cache Caches the entire page (the React Server Component Payload and rendered output) on the **client side** to enable instant back/forward navigation. Client

Caching Behavior of Next.js Functions

Caching in fetch Function (Data Cache Control)

The standard browser fetch function is extended in Next.js to interact with the server-side **Data Cache**. By default, fetch behaves like { cache: 'no-store' } (no caching).

  • Disable Caching (Default): fetch(... , { cache: 'no-store' })
  • Opt-in to Caching: fetch(... , { cache: 'force-cache' })
  • Revalidate Cache: fetch(... , { next: { revalidate: 3600 }}) (Re-fetch at most every 1 hour)

Caching in useRouter Hook (Router Cache Control)

The client-side useRouter hook provides methods to interact with the client-side **Router Cache**:

  • router.prefetch('/products'): Manually prefetches the route and adds it to the Router Cache, resulting in faster subsequent navigation to that route.
  • router.refresh(): Clears the current route from the Router Cache and requests a fresh copy from the server. It **preserves React and browser state** during reconciliation, providing a smooth refresh experience.

Caching in generateStaticParams Function (Full Route Cache)

The generateStaticParams function is used for dynamic routes to generate static paths at build time. The resulting static paths are then cached in the **Full Route Cache**. Additionally, paths that are not generated at build time are cached on the first user visit (at request time).

Caching in <Link> Component

By default, the **<Link>** component automatically prefetches the target route segments from the Full Route Cache and adds the necessary payload to the **Router Cache**. This is a key feature for instant navigation.

<Link href="/products" prefetch={false}> 
  <a>Products</a> 
</Link>

Setting prefetch={false} disables this automatic prefetching, but the route will still be cached when the user eventually navigates to it.

Example of Caching in Action

This client component demonstrates forced caching for data fetching. When the data is fetched (using cache: 'force-cache'), the API response is stored in the server-side **Data Cache** and subsequently utilized by the **Router Cache** on the client. Upon subsequent page reloads or visits, the cached data allows for near-instant rendering.

// app/page.tsx
"use client"
import { useEffect, useState } from 'react'

export default function Page() {
  const [data, setData] = useState([])

  useEffect(() => {
    async function fetchData() {
      // Data is requested to be cached in the Data Cache
      let data = await fetch('https://jsonplaceholder.typicode.com/users', {
        cache: 'force-cache'
      }).then(res => res.json())

      setData(data)
    }

    fetchData()
  }, [])

  return (
    <div>
        {/* Render data */}
    </div>
  )
}
