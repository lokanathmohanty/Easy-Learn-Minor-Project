C++ Copy Constructor 👯

The **copy constructor** is a special member function used to initialize a new object from an existing object of the same class.

If you don't define one, the compiler provides an **Implicit (Shallow)** copy constructor. However, if your class manages dynamic memory (uses pointers and new), you **must** define an **Explicit (Deep)** copy constructor to prevent issues like **double-free errors**.

Syntax

ClassName(const ClassName &obj); // Declaration
ClassName::ClassName(const ClassName &obj) {
   // body of constructor
}

The parameter is typically a **constant reference** (`const ClassName &obj`) to the source object.

When is the Copy Constructor Invoked?

The copy constructor is automatically called in three primary scenarios:

  1. Initialization: When initializing a new object from an existing one: 
    Line line2 = line1; // Copy initialization
    Line line2(line1); // Direct initialization
  2. Pass by Value: When an object is passed **by value** as an argument to a function. (A copy is created for the function's parameter). 
    void display(Line obj); // When called, copy constructor runs
  3. Return by Value: When an object is returned **by value** from a function. (A temporary copy may be created).

Shallow Copy vs. Deep Copy

This distinction is critical for classes containing pointers or dynamically allocated memory.

1. Shallow Copy (Compiler Default)

  • The copy constructor simply copies the **values of the data members**.
  • If the member is a **pointer**, only the pointer's address is copied, meaning both the original and the new object point to the **same block of memory**.
  • **Danger:** When one object is destroyed, the memory is freed. If the second object is later destroyed, it attempts to free the same memory, resulting in a **double-free error**.

2. Deep Copy (User-Defined)

  • The user-defined copy constructor allocates **new memory** for the new object's pointers.
  • It then copies the **content** (the value) from the original object's memory into the newly allocated memory.
  • **Benefit:** The original and copied objects are completely **independent**, preventing resource conflicts.
// Deep Copy Implementation for a class with a pointer 'ptr'
Line::Line(const Line &obj) {
   ptr = new int;      // Allocate new memory for the new object
   *ptr = *obj.ptr;    // Copy the value, not just the address
}

The Rule of Three/Five

If you define a class member that manages a resource (like dynamic memory), you must manually define the functions responsible for managing that resource's lifespan. These include:

  • **Rule of Three:** If you define the **Destructor** (`~ClassName()`), **Copy Constructor** (`ClassName(const ClassName&)`), or **Copy Assignment Operator** (`ClassName& operator=(const ClassName&)`), you must define all three.
  • **Rule of Five (Modern C++):** If you define any of the three above, you should also consider defining the **Move Constructor** and **Move Assignment Operator** to support efficient resource transfer.
