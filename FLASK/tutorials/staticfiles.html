Flask Static Files: Serving Assets in Development 📦

Web applications require **static files** (like **CSS** files, **JavaScript** files, or **images**) to properly display a web page. In a production environment, the web server typically handles serving these assets. However, during **development**, Flask is configured to serve them automatically.

Static File Location and URL

  • **Location:** Static files must be stored in a dedicated directory named **static**, which should be placed next to your main Flask application module or package.
  • **URL Endpoint:** The files are made available on the application at the special URL endpoint **/static**.

Generating Static File URLs with url_for()

To link to a static file in your HTML templates, you use the **url_for()** function with a special endpoint name:

  • The first argument is the special endpoint name: **'static'**.
  • The second argument is a keyword argument, **filename**, which specifies the path to the file relative to the static folder (e.g., 'hello.js').

Example: Linking a JavaScript File

This example demonstrates how to link a JavaScript file named **hello.js** to an HTML template, index.html, so that the script runs when a button is clicked.

The Link in index.html

The **url_for()** function dynamically generates the correct path to the script in the <head> tag:

<script type = "text/javascript"

src = "{{ url_for('static', filename = 'hello.js') }}" ></script>

The resulting src attribute might look something like /static/hello.js.

The JavaScript File (static/hello.js)

This file contains the function called by the button's onclick event:

function sayHello() {

alert("Hello World")

}

This setup ensures that all static assets are correctly served during development and can be easily managed by the web server in production.
