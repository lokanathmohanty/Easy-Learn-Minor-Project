Unicode-bidi

The unicode-bidi property controls how bidirectional (BiDi) text is laid out when left-to-right (LTR) and right-to-left (RTL) scripts appear together. It works in tandem with the direction property and lets authors embed, isolate, or override the Unicode Bidirectional Algorithm for specific elements.

Use cases include mixing Arabic or Hebrew with English, showing part numbers that include both Latin letters and RTL words, or ensuring inline widgets do not affect surrounding paragraph order.

Key Concepts

  • Bidirectional text: Some scripts (e.g., Arabic, Hebrew) run RTL, while others (e.g., English) run LTR. Mixed content requires rules to decide visual order.
  • Base direction: The direction property defines the base direction for an element’s text flow (values commonly ltr or rtl).
  • Algorithm control: unicode-bidi fine-tunes how the Unicode Bidirectional Algorithm is applied to an element and its inline descendants.

Syntax (as text)

unicode-bidi: normal | embed | bidi-override | isolate | isolate-override | plaintext

direction: ltr | rtl

DOM style text (conceptual): object.style.unicodeBidi = "…"

When to Use Each Value

  • normal: Use the default Unicode algorithm with no special embedding or isolation. Good for most content.
  • embed: Start a new embedding level that follows the element’s direction. Use when you need a localized direction block that inherits its own base direction without overriding character order.
  • bidi-override: Force inline content to strictly follow the element’s direction, overriding natural character order. Use sparingly for special cases such as mirrored labels or legacy data that must be forced.
  • isolate: Keep the element’s content from influencing the bidi ordering of siblings. Use for inline widgets, badges, or user-generated snippets to avoid “spillover.”
  • isolate-override: Combine isolation with override behavior. Use only when you need both isolation from neighbors and strict direction inside.
  • plaintext: Determine the base direction from the element’s own first strong character and prevent its content from affecting or being affected by outside context. Useful for pasted text blocks of unknown language.

Important Notes

  • Works with inline layout: Some values have no effect on non-inline elements; test within text contexts.
  • Pair with direction: For embed, bidi-override, and isolate-override, set direction to ltr or rtl to get predictable results.
  • Not affected by all: The unicode-bidi and direction properties are not reset by the CSS all shorthand.
  • Authoring caution: Overuse can make text unreadable. Prefer semantic HTML and natural language order; use overrides only to fix specific rendering issues.

Text-Only Examples (what you would configure)

  • Example 1: Default bidirectional behavior

    direction: rtl

    unicode-bidi: normal

    Expected effect: Paragraph flows RTL using the Unicode algorithm. Latin snippets stay LTR within the RTL paragraph automatically.

  • Example 2: Embedded RTL section inside LTR page

    direction: rtl

    unicode-bidi: embed

    Expected effect: The element establishes its own RTL embedding level without forcing strict override of character order.

  • Example 3: Forced override

    direction: rtl

    unicode-bidi: bidi-override

    Expected effect: Inline characters render strictly right-to-left order, ignoring natural character direction. Use with extreme care.

  • Example 4: Isolating an inline badge

    unicode-bidi: isolate

    No direction change required unless you also want a specific base direction.

    Expected effect: The badge’s internal text does not alter or get altered by surrounding text order.

  • Example 5: Isolate and override together

    direction: rtl

    unicode-bidi: isolate-override

    Expected effect: The element is isolated from neighbors and its internal text strictly follows RTL order.

  • Example 6: Plaintext block with unknown language

    unicode-bidi: plaintext

    Expected effect: Base direction is resolved from the first strong character of the element; surrounding content is unaffected.

Practical Scenarios

  • Mixed labels: Product codes or usernames where Latin letters appear inside Arabic sentences. Prefer normal or embed with appropriate direction.
  • Inline UI chips: Category tags or counters inside multilingual paragraphs. Use isolate so chips don’t reorder surrounding text.
  • Pasted content: Chat messages or CMS blocks of unknown language. Consider plaintext to resolve direction locally.

Step-By-Step Lab (text guidance)

  • Create a paragraph that includes Arabic and English. Leave defaults: unicode-bidi: normal; direction: rtl for the paragraph. Observe natural reordering.
  • Wrap an English phrase with a child element and set unicode-bidi: embed; direction: ltr on that child. Observe stable LTR phrase inside RTL paragraph.
  • Add a small inline counter and set unicode-bidi: isolate on it. Confirm that removing the isolate value causes reordering issues, then reapply to fix.
  • Experiment with bidi-override for a short code sample to see forced reordering; revert afterward to avoid readability issues.

Do and Don’t

  • Do set direction when using embed, bidi-override, or isolate-override.
  • Do prefer isolate for inline widgets and user-generated fragments.
  • Don’t override natural character order unless there’s a specific rendering problem to solve.
  • Don’t rely on bidi-override for entire paragraphs of normal prose.

Accessibility and Internationalization Tips

  • Use correct language metadata elsewhere (for example, page language and element-level language indicators) so assistive technologies can choose proper reading rules.
  • Test with real RTL/LTR samples, not just placeholder Latin text.
  • Keep source order meaningful; BiDi control should not change logical reading order for screen readers.

Troubleshooting

  • Issue: Numbers or punctuation appear in unexpected positions.
  • Check: The element’s direction and whether a child needs isolate or embed.
  • Fix: Apply isolate to inline widgets; use embed with the correct direction on subruns.

Quick Reference

  • normal — default Unicode algorithm
  • embed — new embedding level with its own base direction
  • bidi-override — force strict rendering by base direction
  • isolate — prevent influence on neighbors
  • isolate-override — isolate + override combined
  • plaintext — base direction from first strong character, isolated

Mini Quiz

  • Which value prevents an inline widget from reordering surrounding text? (Answer: isolate)
  • Which values require you to set the base direction explicitly for predictable results? (Answer: embed, bidi-override, isolate-override)
  • Which value derives base direction from the element’s first strong character? (Answer: plaintext)
