Power BI - Cardinality

Cardinality in Power BI describes the type of relationship between two tables based on how rows in one table relate to rows in another.

Types of Cardinalities

  • One-to-One (1:1): Each row in Table A corresponds to one row in Table B, and vice versa.
  • One-to-Many (1:*): Each row in the primary table matches multiple rows in the related table. The filter flow is typically one-way.
  • Many-to-One (*:1): Multiple rows in the first table correspond to one in the second. This is the inverse of one-to-many.
  • Many-to-Many (*:*): Rows in both tables match many rows in the other. Relationships are typically bi-directional.

Examples

  • One-to-One: Two tables both having unique 'Date' columns joined on that column.
  • One-to-Many: A 'Customers' table linked to an 'Orders' table where customer IDs may repeat across orders.
  • Many-to-Many: Multiple students enrolled in multiple courses represented by enrollment and students' tables.

Best Practices

  • Avoid many-to-many relationships if possible as they can complicate data modeling and reduce performance.
  • Ensure dimension tables have unique values and fact tables may have duplicates.
  • Design relationships to reduce ambiguity; keep cross-filter directions limited where possible.
  • Remove or deactivate redundant relationships to simplify the model.
