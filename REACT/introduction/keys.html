ReactJS - Keys

List and Keys

We learned how to use collections in React using for loop and map function in previous chapters. If we run the application, it outputs as expected. However, the developer console shows a warning:

Warning: Each child in a list should have a unique "key" prop.

React tries to render only the updated values in the DOM. When rendering a collection, React needs a way to identify which items are new, updated, or removed. To solve this, React provides the key attribute. The only requirement is that the value of the key must be unique within the collection.

Adding Keys

Let us recreate the earlier application and apply the key attribute to each list item.

ExpenseListUsingForLoop (with keys)

expenses = items.map(
   (item, idx) => <tr key={idx}><td>item {idx + 1}</td><td>{item}</td></tr>
)

Here we used the index value as a key. This removes the warning from the console.

Key and Index

Using an index as a key works in simple scenarios, but it can cause issues in uncontrolled components where elements change dynamically. For example, adding an input field to each row and removing list items may cause unexpected behavior.

Problem Example

expenses = items.map(
   (item, idx) => <tr key={idx}><td>item {idx + 1}</td><td>{item} <input /></td></tr>
)

When the first item is removed, the input value may incorrectly shift to the next row because the index key is reused.

Using Unique IDs as Keys

To avoid this problem, use a unique identifier instead of the index. Modify the data structure to include id values.

Correct Implementation

expenses = items.map(
   (item) => <tr key={item.id}><td>{item.id}</td><td>{item.amount} <input /></td></tr>
)

Now each row uses item.id as its unique key. Removing or reordering items will not cause input values to shift incorrectly.
