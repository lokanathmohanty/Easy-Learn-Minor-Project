Next.js - Internationalization (i18n)

What is Internationalization?

Internationalization (i18n) is a built-in Next.js feature that enables the creation of **multi-language websites**. It manages content and **routing** based on the user's language preference (locale). By setting it up, Next.js automatically handles routes like /en/about and /es/about for the same page component.

Features of Internationalization

The key features provided by Next.js i18n include:

  • Automatic Locale Detection: Next.js detects the user's preferred language from their browser settings and sets the appropriate locale.
  • Locale-Aware Routing: It handles routing such that different locale-prefixed URLs (e.g., /en/page and /es/page) are served by the same underlying page component.
  • Default Locale: A fallback locale can be defined in next.config.js to be used when the user's locale is not supported.
  • Multiple Supported Locales: Supports defining a wide range of locales (e.g., en, es, fr).

Setup Internationalization

Step 1: Modify Next.js Config File

To enable the feature, the **i18n** object must be added to next.config.js, defining the supported languages (locales) and the primary language (defaultLocale).

// next.config.js

module.exports = {
  i18n: {
    locales: ['en', 'es', 'fr'], // Supported languages
    defaultLocale: 'en',         // Default language
  },
};

Step 2: Routing and Linking

The Next.js **<Link>** component is used for navigation. You can specify a target locale using the **locale** attribute when linking to a page.

import Link from 'next/link';
export default function HomePage() {
  return (
    <div>
      <h1>Welcome</h1>
      <Link href="/about" locale="es">
        Go to About in Spanish
      </Link>
    </div>
  );
}

Step 3: Setup Translation Strategies

Next.js handles routing but **does not include a content translation system**. External libraries must be integrated to manage translation strings, keys, and loading translation files. Examples include **next-i18next** or **next-translate**.

Locale Strategies

Next.js offers two primary methods for handling locales in URLs:

Sub-path Routing

The locale information is included as a prefix in the URL path.

  • Example URL: https://example.com/fr/blog
  • The default locale (e.g., en-US) is typically served without the locale prefix (e.g., /blog).
// Example Configuration
module.exports = {
  i18n: {
    locales: ['en-US', 'fr', 'nl-NL'],
    defaultLocale: 'en-US',
  },
}

Domain Routing

The locale is determined by the domain name itself, allowing for different language versions on entirely separate domains.

  • Example URL: https://example.fr/about
  • A single domain can also host multiple locales via sub-paths if configured (e.g., example.nl/nl-BE/blog).
// Example Configuration (Snippet)
i18n: {
  locales: ['en-US', 'fr', 'nl-NL', 'nl-BE'],
  defaultLocale: 'en-US',
  domains: [
    { domain: 'example.com', defaultLocale: 'en-US' },
    { domain: 'example.fr', defaultLocale: 'fr' },
    // ...
  ],
}

Automatic Locale Detection

When a user visits for the first time, Next.js detects their locale from browser settings. If a supported locale other than the default is found, the user is **automatically redirected** to the corresponding locale-prefixed path or domain.

To **disable** this automatic redirection feature, you can set the **localeDetection** option to false in next.config.js:

// next.config.js
module.exports = {
  i18n: {
    localeDetection: false,
  },
}
