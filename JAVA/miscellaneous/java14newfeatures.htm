Java 14 - Major New Features Summary (Non-LTS Release)

Overview of Java 14

**Java 14**, released in **March 2020**, maintained the 6-month rapid release cycle and is a **non-LTS (Long-Term Support)** release. This version solidified language changes like **Switch Expressions** and introduced two major preview features: **Records** and **Pattern Matching for instanceof**, fundamentally simplifying class creation and conditional logic.

Language and Compiler Features

1. Switch Expressions (Standard) (JEP 361) ✨

The enhanced switch feature, introduced in preview in Java 12 and 13, is now a **standard feature**. It can be used as an **expression** that returns a value, utilizing the **arrow (->)** syntax and the **yield** keyword (for returning values from a statement block), eliminating fall-through errors and break clutter.

2. Records (First Preview) (JEP 359) 🆕

A new kind of class, **record**, was introduced to simplify the creation of data-only classes. Records automatically generate boilerplate code (constructor, accessor methods, equals(), hashCode(), and toString()) based on the components declared in the header. They are immutable and intended for modeling data aggregates.

// Concise way to define a data class
public record Point(int x, int y) {}

3. Pattern Matching for instanceof (First Preview) (JEP 305)

Enhances the instanceof operator. If the check succeeds, it also performs a type cast to a new, local, pattern variable, eliminating the need for boilerplate casting code.

// Java 14+ Pattern Matching
if (obj instanceof String s) {
    // 's' is automatically cast to String and available here
    System.out.println(s.length());
}

4. Helpful NullPointerException Messages (JEP 358)

The JVM is now more intelligent in analyzing the cause of a **NullPointerException**. The generated message is enhanced to describe precisely which variable was null, greatly simplifying debugging.

JVM, GC, and API Changes

Garbage Collector Removals

  • CMS Garbage Collector Removed (JEP 363): The **Concurrent Mark Sweep (CMS)** garbage collector, deprecated since Java 9, was officially **removed** from the JDK. Users are encouraged to migrate to modern alternatives like G1 (now the default), ZGC, or Shenandoah.
  • Pack200 Tools and API Removed (JEP 367): Tools for compressing and decompressing JAR files (pack200 and unpack200) were removed, having been made obsolete by better compression formats.

Other JVM Enhancements

  • JFR Event Streaming (JEP 349): Enabled **asynchronous subscription** to JFR (Java Flight Recorder) events, making it easier to monitor live application data without constant polling.
  • Foreign-Memory Access API (First Incubator) (JEP 370): A new API to safely and efficiently access memory outside of the Java heap, paving the way for low-latency data structures and inter-process communication.
  • NUMA-Aware G1 (JEP 345): The G1 garbage collector was enhanced to be aware of **Non-Uniform Memory Access (NUMA)** architectures, optimizing heap memory usage and allocation on such systems.
