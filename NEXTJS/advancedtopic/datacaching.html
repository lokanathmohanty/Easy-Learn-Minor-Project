Next.js - Data Caching

What is Data Cache?

Data Caching in Next.js is a mechanism that **persists the results of data fetches** across different incoming server requests and even across deployments. This is possible because Next.js enhances the native **fetch API** to allow server-side requests to specify their own persistent caching rules.

How Data Caching Works

When a fetch request is made during rendering:

  • If the request uses the { cache: 'force-cache' } option, Next.js first checks the Data Cache for a matching cached response.
    • If found, the cached response is returned immediately.
    • If not found, the request is made to the data source, the result is stored in the Data Cache, and the result is also memoized for the current render.
  • For uncached data (e.g., using { cache: 'no-store' }), the result is always fetched directly from the data source and only memoized for the current render.

Revalidating Data Cache

Cached data can become stale, so Next.js provides two primary methods for **revalidating** (clearing and updating) the Data Cache:

1. On-demand Revalidation

This technique revalidates data based on a specific event, such as a user submitting a form, or data being updated in a Content Management System (CMS). This can be done using either a **tag-based** or **path-based** approach.

Example: Path-based Revalidation via Server Action

The **revalidatePath('/')** function is used within a **Server Action** (handleRevalidate) to tell Next.js to clear the cache for the home page ('/'), forcing a fresh fetch on the next request.

// app/lib/actions.ts (Server Action)
async function handleRevalidate() {
  'use server'
  revalidatePath('/') // Clears the cache for the root path
}

// app/page.tsx
export default async function Home() {
  const data = await getData() 
  
  return (
    <main>
      ...
      <form action={handleRevalidate}>
        <button type="submit">Fetch New Posts</button>
      </form>
    </main>
  )
}

2. Time-based Revalidation

This technique ensures that data is revalidated automatically after a specified time period, preventing data from becoming excessively stale. This is achieved by exporting a **revalidate** variable from the page or layout file.

Example: Revalidating Every 5 Seconds

By exporting const revalidate = 5, the page output will be checked for revalidation every 5 seconds. If a request comes in after 5 seconds, the user is served the stale page while Next.js attempts to generate a fresh version in the background (Stale-While-Revalidate).

// app/page.tsx
export const revalidate = 5 // Revalidate the page at most every 5 seconds

async function getData() {
  // Data will be fetched and stored in Data Cache
  return {
    timestamp: new Date().toISOString(),
    randomValue: Math.random(),
    message: 'This page revalidates every 5 seconds'
  }
}

export default async function Page() {
  const data = await getData()
  
  return (
    <main>
      <h1>5 Second Revalidation</h1>
      <p>Timestamp: {data.timestamp}</p>
      ...
    </main>
  )
}
