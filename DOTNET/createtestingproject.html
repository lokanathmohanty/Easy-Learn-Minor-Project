.NET Core - Creating and Running a Unit Testing Project (xUnit)

Unit testing is a critical practice for verifying the smallest testable parts (units) of an application work correctly in isolation. Since the Unit Test project template was not available in the Visual Studio UI for **.NET Core** at this stage, the project must be created using the **.NET Command Line Interface (CLI)**.

Creating the Test Project via CLI

We use the **dotnet new** command with the **xunittest** template to create a new project that uses the popular **xUnit** testing framework:

  1. Navigate to your solution folder, create a new test folder, and inside it, create a folder for the test project (e.g., StringLibraryTests).
  2. Execute the project creation command from within the new test folder: 
    dotnet new -t xunittest

This command creates a new C# project containing two key files:

  • project.json: Defines the project metadata, dependencies (like **xunit** and the **dotnet-test-xunit** runner), and sets the "testRunner" to "xunit".
  • Tests.cs: Contains the default starter test class with a simple passing test.

Contents of Test.cs

The generated Test.cs file includes a basic test using the [Fact] attribute, which marks a method as a parameterless test case for the xUnit test runner:

using System; 
using Xunit; 
namespace Tests { 
   public class Tests { 
      [Fact] 
      public void Test1() { 
         Assert.True(true); 
      } 
   } 
}

Restoring Dependencies and Running Tests

After creating the project, two additional CLI commands are necessary to prepare and execute the tests:

  1. **Restore NuGet Packages**: The dependencies specified in project.json must be fetched from NuGet before the project can be built: 
    dotnet restore
  2. **Run the Tests**: The dotnet test command compiles the test project and executes the tests using the configured test runner: 
    dotnet test

The command output confirms the compilation and provides a summary of the test run, which currently shows:

  • Tests Executed: 1
  • Errors, Failed, Skipped: 0

This confirms the unit testing environment is set up and functional. The next step is typically to add a project reference to the library under test (e.g., StringLibrary) and start writing meaningful tests.
