Django: Sessions Framework 🔐

Django's **Session Framework** provides a secure way to manage stateful data on a per-site-visitor basis. Unlike simple cookies, where data is stored directly on the client side, the Session Framework abstracts this process: the actual data is saved **server-side** (e.g., in a database), and the client-side cookie only holds a secure, unique **session ID** for identification. This enhances security and works even if the user's browser is configured to block cookies.

Setting Up and Using Sessions

Enabling Sessions

Sessions are typically enabled by default in a new Django project. To ensure they are active, verify the following lines are present in your project's settings.py:

  • In INSTALLED_APPS: 'django.contrib.sessions'
  • In MIDDLEWARE: 'django.contrib.sessions.middleware.SessionMiddleware'

By default, session data is stored in the database (in the django_session table), but this can be configured to use file systems or cache using the SESSION_ENGINE setting.

Storing Data in a Session

When sessions are enabled, every view's request object gains a dictionary-like attribute named **session**. You store data by setting a key-value pair on this attribute:

def login(request):
   # ... form validation logic ...
   if MyLoginForm.is_valid():
      username = MyLoginForm.cleaned_data['username']
      request.session['username'] = username # Data saved server-side
   # ...
   return render(request, 'loggedin.html', {"username" : username})

Accessing and Checking Session Data

You can retrieve session data by accessing the key or check for its existence using has_key() or standard dictionary methods (e.g., in operator):

def formView(request):
   if 'username' in request.session: # Check if key exists
      username = request.session['username'] # Retrieve stored value
      return render(request, 'loggedin.html', {"username" : username})
   else:
      return render(request, 'login.html', {})

Deleting and Logging Out

To end a user's session (e.g., during logout), you delete the specific session key or use session.flush() to clear the entire session data.

def logout(request):
   try:
      del request.session['username'] # Remove a single key
      # request.session.flush() # Alternatively, clear all session data
   except KeyError:
      pass
   return HttpResponse("You are logged out.")

Additional Session Methods

The request.session object supports several methods for managing session behavior and expiration:

  • set_expiry(value): Sets the expiration time for the session (e.g., set_expiry(600) for 10 minutes, or set_expiry(0) to expire when the browser closes).
  • get_expiry_age(): Returns the number of seconds until the session expires.
  • get_expiry_date(): Returns the date and time the session will expire.
  • clear_expired(): Manually removes expired sessions from the session store (usually handled automatically by Django).
  • get_expire_at_browser_close(): Returns True if the session is set to expire when the user closes their web browser.
