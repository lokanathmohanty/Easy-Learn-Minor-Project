Next.js - Router Caching (Client-Side)

What is Router Caching?

Router Caching is a client-side feature in Next.js that stores the complete rendered pages and their data (specifically, the React Server Component Payloads) in the **browser's temporary memory**. This client-side storage dramatically improves performance and load times by allowing for **instantaneous navigation** (e.g., back/forward) without needing to fetch the entire page again from the server.

How Router Caching Works

When a page is loaded, Next.js caches the page's output in the client browser. Subsequent navigation requests for that same page (e.g., using the browser's back button or the <Link> component) return the cached version instead of initiating a new network request.

Router Cache Duration and Invalidation

The client-side Router Cache persists based on two main factors:

  • Current Session: The cache is stored in the browser's memory and is **cleared** when the browser tab is manually reloaded or closed.
  • Automatic Invalidation Period: Next.js automatically invalidates cached layouts and loading states after a specific duration to prevent stale content:
    • For default pre-fetching (prefetch={null} or unspecified): **5 minutes** for static pages, but dynamic pages are generally **not cached**.
    • For full pre-fetching (prefetch={true}): **5 minutes** for both static and dynamic pages.

Revalidating the Client-Side Cache

While the automatic invalidation is helpful, developers can manually force the cache to update using two methods:

1. Time-based Cache Revalidation (Server-Side Control)

This technique controls the server-side **Data Cache** and **Full Route Cache**, which in turn dictates what data the client-side Router Cache stores. By setting the **revalidate** variable, you ensure the page's source data is refreshed on the server after the specified interval.

// export const revalidate = 5 // revalidate every 5 seconds
export default async function Page() {
  const data = await getData()
  
  return (
    <main>
        <h1>5 Second Revalidation</h1>
        <p>Timestamp: {data.timestamp}</p>
    </main>
  )
}

2. Revalidation by Path (On-Demand)

The **revalidatePath** function, used within a Server Action, clears the server-side cache for a specific route. When a user subsequently requests that route, Next.js fetches fresh data, effectively updating the underlying data used to populate the client's Router Cache on the next visit.

// Server Action for revalidation
async function handleRevalidate() {
  'use server'
  revalidatePath('/') // Clears server cache for the root path
}

export default async function Home() {
  const data = await getData()
  
  return (
    <main>
        <h1>Path Revalidation Demo</h1>
        <p>Random Number: {data.randomNumber}</p>
        
        <form action={handleRevalidate}>
            <button type="submit">Revalidate</button>
        </form>
    </main>
  )
}
