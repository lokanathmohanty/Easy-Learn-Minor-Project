Django Admin: Including Custom Models ➕

While the built-in models like **Groups** and **Users** are automatically registered with the Django Admin site upon project creation, **custom models** declared in your applications are not. You must explicitly register them in the corresponding app's **admin.py** file to manage them through the administrative interface.

Steps to Register a Custom Model

1. Define the Model (models.py)

The model must first be defined within your application's models.py file. For the example application myapp, the Employee model is defined with several fields:

from django.db import models

class Employee(models.Model):  
   empno = models.CharField(max_length=20)  
   empname = models.CharField(max_length=100)    
   contact = models.CharField(max_length=15)  
   salary = models.IntegerField()
   joined_date = models.DateField(null=True)
   class Meta:  
      db_table = "employee"

2. Create and Apply Migrations

Once the model is defined, the database must be updated to include the new table structure. This is done by creating the migration script and then applying it:

$ python manage.py makemigrations myapp
$ python manage.py migrate

3. Register the Model (admin.py)

To include the model in the Admin interface, import both the admin module and the custom model, then use the admin.site.register() function:

from django.contrib import admin
from .models import Employee # Import the custom model

admin.site.register(Employee)

Result and Next Steps

After registering the model and running the server, the **Employee** model will appear on the Admin homepage under the **MYAPP** section, allowing a superuser to perform CRUD operations.

By default, the list view for model objects is often unhelpful, showing generic labels like "Employee object (1)". To improve this, you should add a **__str__()** method to the Employee model class. This method defines a **meaningful string representation** of the object (e.g., returning self.empname) that the Admin interface will then use in its lists.
