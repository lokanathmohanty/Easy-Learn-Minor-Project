C# Events: Publisher-Subscriber Mechanism 📢

What are Events?

**Events** are used to signal occurrences or actions, such as user interactions (clicks, key presses) or system notifications (like a successful login or a temperature threshold being met). They are a mechanism for **inter-process communication** or, more commonly, **inter-object communication**.

Events in C# implement the **Publisher-Subscriber** design pattern:

  • **Publisher:** The class that **declares** and **raises** (triggers) the event.
  • **Subscriber:** The class that contains the **event handler** method and **registers** to receive notifications when the event occurs.

Events and Delegates 🤝

Events are fundamentally built on **delegates**. The delegate defines the signature of the method(s) that will be executed when the event is raised (the event handler).

Declaring an Event

Declaring an event requires two steps:

  1. Declare a Delegate: Defines the required method signature.
    2. public delegate void Notify(string message);
  2. Declare the Event: Uses the **`event`** keyword and the delegate type.
    3. public event Notify UserLoggedIn;

Event Handling and Subscription

1. Subscription

The subscriber class registers an event handler method with the publisher's event using the **addition assignment operator `+=`** (which internally utilizes delegate multicasting).

// Subscribe to the event, adding DisplayMessage to the invocation list
user.UserLoggedIn += DisplayMessage;

2. Invocation (Raising the Event)

The publisher class raises the event, typically from within a method. C# often uses the **null-conditional operator (`?.`)** before `Invoke` to ensure there are subscribers before attempting to call the delegate.

// Trigger event, calling all subscribed methods
UserLoggedIn?.Invoke($"Notification: {username} has logged in.");

3. Multiple Handlers (Multicasting)

Because events use delegates (which support multicasting), multiple event handler methods can subscribe to a single event. When the event is triggered, all subscribed handlers are executed sequentially in the order they were added.

station.OnTemperatureAlert += DisplayDevice; // Handler 1
station.OnTemperatureAlert += CoolingSystem; // Handler 2
