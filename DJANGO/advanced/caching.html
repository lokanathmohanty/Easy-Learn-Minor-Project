Django: Caching Framework ⚡

Caching is the process of storing the result of an expensive calculation or dynamic page generation so it can be served quickly on subsequent requests without being re-calculated. Django includes a robust, flexible caching system that allows you to cache **entire sites**, **specific views**, or **parts of a template**.

Setting Up the Cache Backend

Before using caching, you must configure where Django should store the cached data using the **CACHES** dictionary in settings.py:

Database Cache

Saves cache data directly into a database table. You must specify the table name using the **LOCATION** key and create the table with python manage.py createcachetable.

CACHES = {
   'default': {
      'BACKEND': 'django.core.cache.backends.db.DatabaseCache',
      'LOCATION': 'my_cache_table', # The name of the table to use
   }
}

File System Cache

Saves cache data as files on the server's file system. You must specify a directory path with the **LOCATION** key.

CACHES = {
   'default': {
      'BACKEND': 'django.core.cache.backends.filebased.FileBasedCache',
      'LOCATION': '/var/tmp/django_cache', # Ensure this directory exists and is writable
   }
}

In-Memory Cache (Memcached)

This is generally the fastest and most efficient method, storing data directly in memory using services like Memcached or Redis. You must have the respective service running and installed with the necessary Python bindings.

CACHES = {
   'default': {
      'BACKEND': 'django.core.cache.backends.memcached.MemcachedCache',
      'LOCATION': '127.0.0.1:11211', # IP:Port of the Memcached server
   }
}

Caching Techniques in Django

1. Caching the Entire Site (Middleware)

To cache every page output across your entire site, you use specific middleware classes. The order is crucial: UpdateCacheMiddleware must come before FetchFromCacheMiddleware.

# In settings.py
MIDDLEWARE = [
   'django.middleware.cache.UpdateCacheMiddleware',
   'django.middleware.common.CommonMiddleware',
   'django.middleware.cache.FetchFromCacheMiddleware',
   # ... other middleware ...
]

CACHE_MIDDLEWARE_ALIAS = 'default' # Use the 'default' cache defined above
CACHE_MIDDLEWARE_SECONDS = 600    # Cache pages for 600 seconds (10 minutes)

2. Caching a View (Decorator)

You can cache the output of an individual view function using the **@cache_page** decorator. The decorator takes the cache duration in seconds as its parameter.

from django.views.decorators.cache import cache_page
from django.http import HttpResponse

@cache_page(60 * 15) # Cache the result for 15 minutes (900 seconds)
def viewArticles(request, year, month):
   text = "Displaying articles of: %s/%s" % (year, month)
   return HttpResponse(text)

Alternatively, you can apply the decorator directly in your urls.py when defining the path, eliminating the need to import it in the view file:

# In urls.py
from django.views.decorators.cache import cache_page
# ...
url(r'^articles/(?P\d{2})/(?P\d{4})/', 
    cache_page(60 * 15)('viewArticles'), name = 'articles'),

Note: When a view has URL parameters (like year/month), Django caches each unique URL request separately.

3. Caching a Template Fragment (Template Tag)

To cache only a specific, expensive-to-render block within an HTML template, use the **{% cache %}** template tag.

{% load cache %}
{% extends "main_template.html" %}
{% block title %}My Hello Page{% endblock %}

{% cache 500 content %}
{% block content %}
    <h1>Hello World!!!</h1>
    <p>Today is {{today}}</p>
    <!-- ... expensive calculations or database loops go here ... -->
{% endblock %}
{% endcache %}

The tag requires two arguments: the cache duration in seconds (e.g., 500) and a unique name for the cache fragment (e.g., content).
