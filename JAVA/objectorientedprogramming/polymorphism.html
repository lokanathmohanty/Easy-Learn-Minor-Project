Java Programming: Object-Oriented Concepts

Session: Polymorphism (Many Forms)

What is Polymorphism?

**Polymorphism** is the ability of an object or method to take on many forms. It allows a single method name or reference variable to behave differently depending on the context or the actual object type being used.

Any Java object that passes more than one **IS-A test** (e.g., A Deer IS-A Animal and a Deer IS-A Vegetarian) is considered polymorphic.

Using Parent References for Child Objects

The most common use of polymorphism is when a **parent class reference** or **interface reference** is used to refer to a **child class object**.

// Legal polymorphic declarations:
Deer d = new Deer();
Animal a = d;        // Parent class reference points to Child object
Vegetarian v = d;    // Interface reference points to Child object

The type of the reference variable (Animal or Vegetarian) determines which methods can be called, but the actual method executed at runtime depends on the object type (Deer).

Types of Java Polymorphism

Polymorphism is categorized into two main types based on when the method call is resolved:

  • **Compile-Time Polymorphism** (Static Binding)
  • **Run-Time Polymorphism** (Dynamic Binding)

1. Compile-Time Polymorphism (Method Overloading)

This is achieved through **Method Overloading**, where multiple methods in the same class have the same name but different parameter lists (different number, type, or order of arguments). The correct method to call is determined by the compiler at compile time.

Example: Method Overloading

public class Main {
  // Method 1: two integers
  public int addition(int x, int y) { ... } 

  // Method 2: three integers
  public int addition(int x, int y, int z) { ... }

  // Method 3: two doubles
  public double addition(double x, double y) { ... } 
  
  // The compiler selects the correct 'addition' method based on arguments provided:
  // number.addition(444, 555); -> Calls Method 1
  // number.addition(10.15, 20.22); -> Calls Method 3
}

2. Run-Time Polymorphism (Method Overriding)

This is achieved through **Method Overriding**, which is implemented via **inheritance**. A subclass provides a specific implementation for a method that is already provided by its superclass. The method to execute is determined at runtime (dynamic method dispatch).

Example: Method Overriding (Dynamic Dispatch)

class Vehicle {
  public void displayInfo() { ... }
}

class Car extends Vehicle {
  @Override
  public void displayInfo() { // Overrides parent method
    System.out.println("I have a Car.");
  }
}

public class Main {
  public static void main(String[] args) {
    Vehicle v1 = new Car(); // Upcasting: Parent reference, Child object
    
    // The JVM invokes the overridden method in the actual object (Car), 
    // despite the reference type being Vehicle.
    v1.displayInfo();
  }
}

Output:

I have a Car.
