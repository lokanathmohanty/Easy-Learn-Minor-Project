Django: Deleting Data (CRUD: Delete) 🗑️

The Django ORM allows you to delete one or more database rows by invoking the **.delete()** method on a model instance or a QuerySet. This operation is automatically reflected in the mapped database table.

1. Direct ORM Methods (Shell or View)

The .delete() method can be applied to a single instance or a collection of instances (a QuerySet) for bulk deletion.

A. Deleting a Single Object

Retrieve the specific object using the model manager's .get() method (usually by primary key) and then call .delete() on the instance:

>>> from myapp.models import Dreamreal
>>> row = Dreamreal.objects.get(pk = 1)
>>> row.delete() # Deletes a single row from the DB

B. Bulk Deletion (QuerySet)

Use a filtering method (like .filter()) to create a QuerySet containing the objects you want to delete, and then call .delete() on the entire set:

>>> rows = Dreamreal.objects.filter(name__startswith = 'a')
>>> rows.delete() # Deletes all rows matching the filter criteria

Note on Related Objects: By default, Django's **ForeignKey** fields emulate the SQL constraint **ON DELETE CASCADE**. This means that when an object is deleted, any objects with a foreign key pointing to it will also be automatically deleted.

2. Deleting via Function-Based Views (Confirmation Required)

For operations as permanent as deletion, it is best practice to ask for user confirmation, typically handled by a view that processes both GET (show confirmation form) and POST (perform deletion).

A. View Function and URL Mapping

The view function receives the object's primary key (`pk`) via the URL path and handles the request:

# In views.py
def delete(request, pk):
   obj = Dreamreal.objects.get(pk=pk) 
   if request.method == "POST":
      obj.delete() # Deletes the object if form is submitted
      return HttpResponse("Deleted successfully")
   
   # GET: Render the confirmation form
   context = {"pk": pk}
   return render(request, "myform.html", context)

# In urls.py
urlpatterns += [path("delete/", views.delete, name='delete')]

B. Confirmation Template (myform.html)

The template sends a POST request back to the same URL upon confirmation:

<form action="../delete/{{ pk }}" method="post">
   {% csrf_token %}
   <h2>The record with primary {{ pk }} will be deleted. Are you sure?</h2>
   <input type="submit" value="delete">
   <a href = "../cancel"><input type="button" value="Cancel" /></a>
</form>

3. Using Generic Class-Based Views (DeleteView)

The **DeleteView** generic class is the fastest way to implement the delete functionality with confirmation, as it handles the object retrieval, confirmation form rendering, and the delete operation automatically.

from django.views.generic.edit import DeleteView 

class DRDeleteView(DeleteView):  
   model = Dreamreal  
   template_name = "myform.html" # Renders the confirmation form
   success_url = "../success/" # URL to redirect to after successful deletion

When the view is accessed (e.g., via /myapp/deleteview/2), it renders the specified template. Upon POST submission, it deletes the object and redirects to the success_url.
