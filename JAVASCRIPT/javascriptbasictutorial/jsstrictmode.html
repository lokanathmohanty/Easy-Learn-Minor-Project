JavaScript - Strict Mode

Strict Mode in JavaScript

In JavaScript, the strict mode is introduced in the ES5 (ECMAScript 2009). The purpose behind introducing the "strict mode" is to make the JavaScript code more secure.

The 'use strict' literal expression is used to add the strict mode in the JavaScript code. It removes silent errors from the code, such as using variables without declaration or modifying a read-only property of an object.

Enabling Strict Mode

To enable strict mode, you should write the following literal expression at the top of your code:

'use strict';

The 'use strict' directive enables JavaScript's strict mode.

Why Use the Strict Mode?

  • Error Prevention: Prevents common errors such as using undeclared variables or reserved keywords as identifiers.
  • Safer Code: Avoids accidental global variable creation and disallows unsafe statements like with.
  • Future Compatibility: Prepares code for future reserved keywords (e.g., public).

Strict Mode in the Global Scope

When 'use strict' is added at the top of a JavaScript file, strict mode applies to the entire code.

Example

<script>
"use strict";
let y = 50; // Valid
document.write("The value of Y is: " + y);
x = 100; // Invalid, will throw error
document.write("The value of X is: " + x);
</script>

Strict Mode in the Local Scope

Strict mode can also be enabled inside a function, restricting its scope only to that function.

Example

<script>
x = 100; // Valid outside strict mode
document.write("The value of X is - " + x);

function test() {
   "use strict";
   y = 50; // Invalid inside strict mode
   document.write("The value of Y is: " + y);
}
test();
</script>

Mistakes Not Allowed in Strict Mode

  • Using variables without declaring them.
  • Using objects without declaring them.
  • Deleting variables, functions, or object prototypes.
  • Functions with duplicate parameter names.
  • Assigning octal numbers or using escape characters.
  • Using reserved keywords like eval, arguments, public, etc.
  • Writing to read-only object properties or assigning values to getters.
  • Using this in functions without an object context (defaults to undefined).
  • Using with statements.
  • Declaring variables with eval().
  • Using reserved future keywords like implements, interface, package, private, protected.
