C# Polymorphism

Concept of Polymorphism

The term **Polymorphism** means "having many forms." In C#, it allows you to define one interface (or member name) that can have **multiple functions** or implementations. This concept is crucial for achieving flexible and extensible code.

Polymorphism is divided into two types based on when the function call is resolved:

  1. **Static Polymorphism** (Compile-Time)
  2. **Dynamic Polymorphism** (Run-Time)

1. Static Polymorphism (Compile-Time)

**Static Polymorphism** uses **early binding**, where the specific method to be executed is determined by the C# compiler at compile time. It is achieved through **Overloading**.

Function Overloading (Method Overloading)

This allows multiple methods within the same class to share the same name, provided they have different **signatures** (different number or types of parameters).

class Printdata {
    void print(int i) { /* ... */ }      // Signature 1: takes int
    void print(double f) { /* ... */ }   // Signature 2: takes double
    void print(string s) { /* ... */ }   // Signature 3: takes string
}

Operator Overloading

This allows standard C# operators (like `+`, `-`, `*`) to be redefined or customized to work with user-defined classes or structs.

public static Box operator +(Box b1, Box b2) {
    // Defines how the '+' operator works when adding two 'Box' objects
    return new Box(b1.length + b2.length, ...); 
}

2. Dynamic Polymorphism (Run-Time)

**Dynamic Polymorphism** uses **late binding**, where the specific method implementation to be executed is determined during program execution (run time). This is primarily achieved through **Method Overriding** and **Abstract Classes**.

Method Overriding (Virtual Functions)

Method overriding allows a derived class to provide a specific implementation for a method that is already defined in its base class.

  • The base class method must be declared with the **`virtual`** keyword.
  • The derived class method must be declared with the **`override`** keyword.

This allows a single base class reference variable to call the correct implementation in the derived class at runtime.

class Shape {
    public virtual int area() { /* Base implementation */ return 0; }
}
class Rectangle : Shape {
    public override int area() { /* Rectangle specific implementation */ return (width * height); }
}

Abstract Classes and Methods

An **abstract class** cannot be instantiated directly and must contain one or more **abstract methods** (methods declared without implementation). These methods must be defined (overridden) in the first non-abstract derived class.

  • Abstract methods enforce a contract for derived classes.
  • Abstract classes cannot be declared `sealed`.
abstract class Shape {
    public abstract int area(); // No body; must be implemented by derived classes
}

Polymorphism with Interfaces

Interfaces are a powerful tool for achieving dynamic polymorphism. An interface defines a contract (method signatures) that multiple, unrelated classes can implement. This allows diverse objects to be treated uniformly through the common interface type.

public interface IAnimal {
    void MakeSound(); // Contract
}

public class Dog : IAnimal {
    public void MakeSound() { Console.WriteLine("Woof!"); } // Dog implementation
}
public class Cat : IAnimal {
    public void MakeSound() { Console.WriteLine("Meow!"); } // Cat implementation
}

A variable of type `IAnimal` can hold a `Dog` or a `Cat` object, and the correct `MakeSound` method is determined at run-time.

IAnimal animal = new Dog(); // 'animal' is treated as IAnimal, but the object is a Dog
animal.MakeSound(); // Calls Dog's MakeSound()
