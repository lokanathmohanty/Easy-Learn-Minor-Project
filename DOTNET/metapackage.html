.NET Core - Metapackages and Application References

This chapter explores the concept of **metapackages** in .NET Core and how the core framework references differ between a **Console App** (using the newer project system) and a **UWP App** (which retains the older .csproj/MSBuild system).

Comparing Application References

  • .NET Core Console Application: References the **.NETCoreApp** framework. This uses the new project style, allowing you to easily drill down into the underlying packages within the Solution Explorer.
  • UWP Application: Due to using the .csproj build system, references revert to the old style. It targets the framework through the **Microsoft.NETCore.UniversalWindowsPlatform** NuGet package.

Understanding Metapackages

Both Microsoft.NETCore.App (for Console/general .NET Core) and Microsoft.NETCore.UniversalWindowsPlatform (for UWP) are considered **metapackages**.

  • A **metapackage** is a **NuGet package that does not contain code**; instead, it exists solely to define a group of other, individual NuGet packages (dependencies).
  • This structure simplifies development by allowing developers to reference a single package that pulls in all the necessary foundational libraries for a specific platform or app type (e.g., console, web, or UWP).

Inspecting Metapackage Contents

While the Console App's Microsoft.NETCore.App dependencies can often be viewed directly in Solution Explorer, the UWP metapackage contents must be inspected using external tools like **NuGet Package Explorer**.

By comparing the contents of these two metapackages, you can see that:

  • Each metapackage is composed of a **different set of underlying packages** tailored to the specific application environment.
  • The **.NET Core framework** itself is currently a **subset** of the older .NET Framework class libraries but is continually expanding toward feature parity.
  • **UWP** is built on top of .NET Core, offering a **superset of APIs** specifically available for Windows Store (Windows 10) development. This results in an overall increase in the APIs available to developers.
