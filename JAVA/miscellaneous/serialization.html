Java - Object Serialization

Mechanism and Purpose of Serialization

Object Serialization is a mechanism in Java that converts an object's state (its data) into a **sequence of bytes**. This byte stream includes the object's data, its type, and the type information of the data within it. The primary uses are:

  • Persistence: Writing an object's state to a file or database for long-term storage.
  • Networking: Transmitting an object between different Java Virtual Machines (JVMs), potentially running on different platforms.

The reverse process, reading the byte sequence and recreating the object in memory, is called **Deserialization**. This process is platform-independent, meaning an object serialized on one OS can be successfully deserialized on another.

Implementing Serialization

For a class to be serializable, two conditions must be met:

  1. Implement Serializable: The class must implement the marker interface **java.io.Serializable**. This interface has no methods; it merely marks the class as eligible for serialization.
  2. Handle Non-Serializable Fields: All fields in the class must be serializable. If a field's type is not serializable (e.g., a custom class not implementing the interface), it must be explicitly marked with the **transient** keyword.

The transient Keyword

When a field is marked transient, its value is **ignored** during the serialization process. When the object is deserialized, the transient field is initialized to its type's **default value** (e.g., 0 for numeric types, false for boolean, and null for objects), as demonstrated by the deserialized SSN value being 0.

Serialization/Deserialization Methods

The core methods are provided by the high-level stream classes, **ObjectOutputStream** and **ObjectInputStream**.

1. Serializing an Object (Writing)

Uses ObjectOutputStream, typically wrapped around a FileOutputStream:

public final void writeObject(Object x) throws IOException

This method converts the object x into a byte stream and sends it to the underlying output stream.

2. Deserializing an Object (Reading)

Uses ObjectInputStream, typically wrapped around a FileInputStream:

public final Object readObject() throws IOException, ClassNotFoundException

This method reads the byte stream and reconstructs the object. The return value is of type Object, which **must be cast** back to the original class type (e.g., (Employee) in.readObject()).

It throws **ClassNotFoundException** if the JVM cannot find the bytecode for the class during the reconstruction process.
