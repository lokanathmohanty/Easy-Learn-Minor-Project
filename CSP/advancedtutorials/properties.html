C# Properties: Get and Set Accessors

What are Properties? 🗝️

**Properties** are named members of classes, structures, and interfaces that act as an extension of **fields** (member variables). They are accessed using the same syntax as fields, but they contain **accessors** (`get` and `set`) which contain executable logic.

Properties provide a controlled and flexible way to read, write, or compute the values of underlying **private fields** (often called the *backing store* or *backing field*), adhering to the principle of **encapsulation**.

Accessors: `get` and `set`

The core of a property is its accessors. A property can have a `get` accessor, a `set` accessor, or both.

The `get` Accessor (Reading)

  • It is used to **read** the property's value.
  • It executes when the property is read (e.g., `Console.WriteLine(s.Age)`).
  • It must end with a `return` statement, returning a value of the property's type.

The `set` Accessor (Writing)

  • It is used to **write** or modify the property's value.
  • It executes when the property is assigned a new value (e.g., `s.Age = 10`).
  • The new value being assigned is implicitly available via the contextual keyword **`value`**.

Example of Full Property Implementation

// Declares an Age property that controls access to the private 'age' field
public int Age { 
   get {
      return age; // Reads the private backing field
   }
   set {
      age = value; // Writes to the private backing field, where 'value' is the assigned input
   }
}

Property Variations

Auto-Implemented Property (Automatic Property) ✨

When no extra logic (like validation) is needed in the accessors, you can use a concise syntax. The compiler automatically creates a hidden, private backing field for you.

// Auto-implemented properties: The compiler generates the private backing field.
public string Name { get; set; }
public int Age { get; set; }

Read-Only and Write-Only Properties

Properties can enforce controlled access by omitting an accessor:

  • **Read-Only:** Only has a `get` accessor (or a private `set` accessor), meaning its value can only be read from outside the class.
  • **Write-Only:** Only has a `set` accessor, meaning its value can only be written to, but not directly read (useful for secure setting of data like passwords).

Property Validation (The Power of `set`)

A key advantage of properties is the ability to include validation logic inside the `set` accessor, preventing assignment of invalid values.

public int Age {
   get { return age; }
   set {
      if (value < 18) // Validation Check
         throw new ArgumentException("Minimum age is 18.");
      age = value; // Only assign if valid
   }
}

Abstract Properties (In Abstract Classes)

An **abstract property** is declared within an `abstract` class (or interface). It does not provide an implementation for the accessors; it only acts as a **contract**, forcing derived concrete classes to provide the full implementation using the **`override`** keyword.

// Abstract class declaration
public abstract class Person {
   public abstract string Name {
      get; // No implementation here
      set; // No implementation here
   }
}
// Derived class implementation
public class Student : Person {
   private string name = "N.A";
   public override string Name {
      get { return name; }
      set { name = value; }
   }
}
