Django: File Uploading 📎

File uploading in Django involves specific configurations in the **Form**, the **Model**, and the **View** to correctly handle the binary data sent from the client's browser.

1. Model and Form Definition

Django uses dedicated field types for file uploads in both the form and the model.

  • Forms (forms.py): Use **forms.ImageField** (requires PIL/Pillow to check image validity) or **forms.FileField** (for any file type).
  • Models (models.py): Use **models.ImageField** or **models.FileField**. Both require the **upload_to** argument, which specifies the subdirectory within MEDIA_ROOT where the files will be saved.
# myapp/forms.py
class ProfileForm(forms.Form):
   name = forms.CharField(max_length = 100)
   picture = forms.ImageField() # Use ImageField for images

# myapp/models.py
class Profile(models.Model):
   name = models.CharField(max_length = 50)
   picture = models.ImageField(upload_to = 'pictures') # Files saved to MEDIA_ROOT/pictures/

Note: The **MEDIA_ROOT** setting in settings.py must define the absolute path to the directory where all uploaded files are stored.

2. Template Configuration

The HTML form used for file uploading requires a specific attribute to handle the binary data:

  • The **<form>** tag must include the attribute **enctype="multipart/form-data"**. Without this, the file data will not be transmitted correctly, and the Django form validation will fail.
  • The file input uses the standard HTML type: **<input type="file">**.
<form name = "form" enctype = "multipart/form-data" 
   action = "{% url "myapp.views.SaveProfile" %}" method = "POST" >
   {% csrf_token %}
   <input type = "file" name = "picture" />
   <!-- ... other fields ... -->
</form>

3. View Processing

The view function must handle two sources of data: the standard form fields (from request.POST) and the file data (from request.FILES).

  • When instantiating the form, both dictionaries must be passed: **ProfileForm(request.POST, request.FILES)**.
  • If request.FILES is omitted, file fields will be treated as empty, causing validation to fail.
def SaveProfile(request):
   saved = False
   if request.method == "POST":
      MyProfileForm = ProfileForm(request.POST, request.FILES) # Pass BOTH POST and FILES
      
      if MyProfileForm.is_valid():
         profile = Profile()
         profile.name = MyProfileForm.cleaned_data["name"]
         
         # File data is also in cleaned_data
         profile.picture = MyProfileForm.cleaned_data["picture"] 
         profile.save()
         saved = True
   else:
      MyProfileForm = Profileform()
		
   return render(request, 'saved.html', locals())

Once saved, Django automatically handles writing the file to the disk (at the path defined by MEDIA_ROOT + upload_to) and storing the file path in the database field.
