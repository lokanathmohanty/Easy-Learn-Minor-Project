Next.js - Authentication

What is Authentication?

Authentication is the foundational process of verifying a user's identity to ensure they are who they claim to be. In web applications, this typically involves checking user-provided credentials (like a username and password) against stored information.

The core steps in the general authentication process are:

  1. Take user's credentials (e.g., via a login form).
  2. Validate the format and content of the credentials.
  3. Verify the credentials against the database or authentication service.

Authentication in Next.js

Next.js authentication typically follows a three-step flow, leveraging **Server Actions** for secure and enhanced form handling.

Step 1: Create a Next.js Form

Next.js uses a custom **<Form>** component that extends the native HTML form tag. This component integrates with Server Actions via the **action** prop and provides enhanced features like client-side navigation, prefetching of loading UI, and progressive enhancement.

Example Signup Form:

// app/ui/signup-form.tsx
import { signup } from '@/app/actions/auth'

export function SignupForm() {
  return (
    <Form action={signup}>
      <div>
        <label htmlFor="email">Email</label>
        <input id="email" name="email" type="email" placeholder="Email" />
      </div>
      <div>
        <label htmlFor="password">Password</label>
        <input id="password" name="password" type="password" />
      </div>
      <button type="submit">Sign Up</button>
    </Form>
  )
}

Step 2: Validate Form Fields on the Server

Form field validation is crucial for ensuring data integrity and reducing server load. In Next.js, this is efficiently handled on the server side using **Server Actions** and schema validation libraries like **Zod** or **Yup**.

Example Zod Validation Schema:

// app/actions/auth.ts
import { z } from 'zod'

export const SignupFormSchema = z.object({
  email: z.string().email({ message: 'Enter a valid email.' }).trim(),
  password: z
    .string()
    .regex(/[a-zA-Z]/, { message: 'Contain at least one letter.' })
    .regex(/[0-9]/, { message: 'Contain at least one number.' })
    .regex(/[^a-zA-Z0-9]/, {
      message: 'Contain at least one special character.',
    })
    .trim(),
})

The validation function (signup) should also define a type for managing server-side validation errors and messages:

export type FormState =
  | {
      errors?: {
        name?: string[]
        email?: string[]
        password?: string[]
      }
      message?: string
    }
  | undefined

Step 3: Check User Credentials and Create Session

After successful validation, the Server Action proceeds to verify the credentials (for sign-in) or prepare the data (for sign-up). For sign-up, this involves security steps like **hashing the password** before storing it in the database and then creating the user's entry.

The final steps involve creating a user session (e.g., using a secure cookie or an external authentication library's API) and redirecting the user to a protected route.
