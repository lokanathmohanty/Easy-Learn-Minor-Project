Next.js API Routes (Pages Router) / Route Handlers (App Router) 📡

What are API Routes?

**API Routes** (used in the legacy Pages Router) are a feature that allows you to create **serverless functions** within your Next.js application. These functions run on the server and are primarily used to handle HTTP API requests from the frontend or external services. They enable you to implement **server-side logic** for tasks like data fetching, form handling, and database interactions.

**Note:** In the current **App Router** (`app/` directory), API Routes are replaced by **Route Handlers** (defined in a file named `route.js`/`.ts`).

Setting Up an API Endpoint (Pages Router)

In the **Pages Router** system, any file inside the **`pages/api`** directory is treated as an API endpoint, not a rendered page.

  • **File Name** defines the endpoint path.
  • **Default Function** handles the incoming request (`req`) and sends the response (`res`).

Basic API Route Example:

  • **File:** `pages/api/hello.js`
  • **Endpoint:** `/api/hello`
// File: pages/api/hello.js
export default function handler(req, res) {
  // Sets status to 200 (OK) and sends a JSON response
  res.status(200).json({ message: 'Hello, Next.js API!' });
}

Handling Different HTTP Methods

API routes can conditionally execute logic based on the HTTP method of the incoming request (`GET`, `POST`, `PUT`, `DELETE`, etc.).

// File: pages/api/user.js
export default function handler(req, res) {
    const { method } = req;
    
    switch (method) {
        case 'GET':
          res.status(200).json({ message: 'Fetching user data' });
          break;
        case 'POST':
          res.status(201).json({ message: 'Creating a new user' });
          break;
        default:
          res.setHeader('Allow', ['GET', 'POST', 'PUT', 'DELETE']);
          res.status(405).end(`Method ${method} Not Allowed`);
    }
}

Proxying an API Request

API Routes are often used as a **proxy layer** to securely fetch data from external APIs. This prevents exposing sensitive API keys on the client side and allows you to modify requests or add custom authentication before delivering the data to the frontend.

// File: pages/api/proxy/route.js (Proxy Endpoint)
import fetch from 'node-fetch'; 

export default async function handler(req, res) {
  try {
    // 1. Server-side fetch from external API (hides keys/secrets)
    const response = await fetch('https://jsonplaceholder.typicode.com/users'); 
    const data = await response.json();

    // 2. Send the external data to the client
    res.status(200).json(data);
  } catch (error) {
    res.status(500).json({ error: 'Failed to fetch data.' });
  }
}
