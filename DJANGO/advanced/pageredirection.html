Django: Page Redirection ➡️

Page redirection is a core requirement in web applications, used after actions like logging in, submitting forms, or in case of errors. In Django, redirection is primarily handled by the **redirect()** shortcut method, imported from django.shortcuts.

Using the redirect() Method

The redirect() function takes several types of arguments, ultimately returning an HttpResponseRedirect object that instructs the client's browser to load a new URL.

1. Redirecting to an External or Full URL

You can redirect users to an external website or a full absolute URL by passing the URL as a string argument:

from django.shortcuts import redirect

def hello(request):
   # Redirects to the Django official website
   return redirect("https://www.djangoproject.com")

2. Redirecting to an Internal View Function

You can redirect to another view function within your project by passing the **view's name** (the function object) and any required keyword arguments (like URL parameters):

from django.shortcuts import redirect

def viewArticle(request, articleId):
   # Redirects to the 'viewArticles' view, passing year and month arguments
   return redirect(viewArticles, year = "2045", month = "02")

def viewArticles(request, year, month):
   # Target view: Displaying articles of 2045/02
   text = "Displaying articles of : %s/%s"%(year, month)
   return HttpResponse(text)

3. Redirecting using a URL Name (Recommended)

The most robust way to redirect internally is by using the **name** parameter defined in your urls.py mapping. This avoids hardcoding view function names, making your code more resilient to refactoring:

If the URL pattern is mapped with name='articles', the redirection can use that name:

def viewArticle(request, articleId):
   # Redirects using the registered URL name 'articles'
   return redirect('articles', year = "2045", month = "02")

Permanent vs. Temporary Redirect

By default, redirect() performs a temporary redirect (HTTP 302/307). You can make it permanent (HTTP 301) by passing the permanent=True parameter. This distinction is important for **SEO** (Search Engine Optimization):

# Permanent redirection (HTTP 301)
return redirect("https://new.site.com", permanent = True)

The reverse() Function

The **reverse()** function (from django.urls, formerly django.core.urlresolvers.reverse) is related to redirection. It is used to generate a URL string from a view name and its arguments, but unlike redirect(), it **only returns the URL string** and does not create an HTTP response object. It's often used when you need the URL string for other purposes (like inside a template or to calculate a path).
