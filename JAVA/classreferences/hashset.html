Java HashSet Class Summary 🧩

The **java.util.HashSet** class is the primary, general-purpose implementation of the **Set** interface in Java. It is backed internally by a **HashMap**, which means it provides all the core guarantees of the Set contract, most notably **uniqueness** and **high-speed performance**.

I. Core Set Properties and Performance

  • Uniqueness: A set **cannot contain duplicate elements**. When the `add(E e)` method is called, the new element is added only if an element that is logically equal (based on the `equals()` and `hashCode()` methods) is not already present.
  • Hashing Principle: Since it is backed by a `HashMap`, basic operations like **add()**, **remove()**, and **contains()** typically have **constant time complexity ($O(1)$)**, assuming a good hash function and minimal collisions.
  • Unordered: A `HashSet` makes **no guarantee about the iteration order**. The order of elements is determined by the hash codes and internal structure and may change over time. (Use **LinkedHashSet** for insertion order or **TreeSet** for sorted order).
  • Nulls Permitted: It allows the inclusion of a **single `null` element**.
  • Non-Synchronized: It is **not thread-safe**. For concurrent use, the **ConcurrentHashMap** class (or `Collections.synchronizedSet(new HashSet())`) should be used.

II. Internal Implementation

The **HashSet** is essentially a wrapper around a **HashMap** where:

  • The elements added to the `HashSet` are stored as the **keys** of the internal `HashMap`.
  • The **values** of the internal `HashMap` are a constant placeholder object (a static dummy object). Since keys must be unique in a Map, elements are guaranteed to be unique in the Set.

III. Constructors and Capacity

Because it relies on the internal `HashMap`, its constructors allow fine-tuning the hash table's performance parameters:

  • **HashSet():** Uses the default initial capacity (16) and load factor (0.75).
  • **HashSet(int initialCapacity, float loadFactor):** Allows explicit control over the size and resizing threshold, which can prevent rehashing overhead if the final set size is known or can be estimated.
