C++ Exception Handling (try, catch, throw) ⚠️

Exception handling is a mechanism that allows a program to respond to exceptional circumstances or errors that arise during execution, providing a structured way to transfer control from the point of error to an error handler.

The Three Keywords

  • **throw**: Used to signal an exception when a problem occurs. The operand determines the **type** of the exception.
  • **try**: Identifies a block of code (protected code) where exceptions might be activated.
  • **catch**: Defines an exception handler that catches and processes a thrown exception of a specific type.

Syntax

try {
   // Code that might throw an exception
   if (b == 0) {
      throw "Division by zero condition!"; // Throws a const char*
   }
} catch(const char* msg) { 
   // Handles the exception of type const char*
   std::cerr << msg << std::endl;
} catch(...) {
   // Catch-all handler for any uncaught exception type
}

Throwing and Catching Exceptions

The type of the expression in the `throw` statement determines the type of exception. The matching `catch` block must be prepared to handle that specific type.

A single `try` block can be followed by multiple `catch` blocks to handle different types of errors (e.g., an `int` error, a `string` error, or a custom exception class).

Catching Any Exception

To catch any type of exception not explicitly caught by preceding handlers, a generic **catch-all handler** can be used:

catch(...) {
   // Code to handle any exception type
}

Standard and Custom Exceptions

C++ provides a rich hierarchy of standard exception classes defined in the **<exception>** header, all inheriting from the base class **std::exception**.

Key Standard Exceptions

Exception ClassDescription
**std::exception**The base class for all standard C++ exceptions.
**std::bad_alloc**Thrown by new upon memory allocation failure.
**std::bad_cast**Thrown by dynamic_cast when a cast fails.
**std::logic_error**Errors that can theoretically be detected by reading the code (e.g., std::invalid_argument).
**std::runtime_error**Errors that cannot easily be detected before runtime (e.g., std::overflow_error).

Defining Custom Exceptions

Best practice is to define custom exceptions by **inheriting from std::exception** and overriding the **what()** method, which returns a descriptive C-style string about the exception's cause.

struct MyException : public std::exception {
   const char * what () const throw () {
      return "Custom C++ Error Message"; // Override what()
   }
};
