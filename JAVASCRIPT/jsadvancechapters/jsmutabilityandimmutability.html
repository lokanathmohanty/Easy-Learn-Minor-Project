JavaScript - Mutability vs Immutability

If you are a web developer you have seen the terms mutable and immutable objects in JavaScript. But what these words mean, and why do they matter? This section will help you understand.

  • What mutable and immutable objects are
  • The main differences between them
  • How to make and change them
  • The benefits and drawbacks of using each type in your code

This knowledge is very helpful for writing cleaner, safer, and more reliable JavaScript code.

Mutable Objects

Mutable objects in JavaScript are ones that can be changed after they are created, including arrays, objects, functions, and dates. To add, remove or modify values in these objects, use bracket notation (object["property"]) or dot notation (object.property).

But, changing these objects can sometimes lead to problems: it can unintentionally affect other parts of your code, make debugging more difficult, and use more memory.

Example

const student = {
  name: "Aarav",
  age: 15,
  hobbies: ["drawing", "playing guitar", "cycling"]
};

const student2 = student;
console.log(student);
console.log(student2);

student2.age = 25;
console.log(student);
console.log(student2);

Changing the age of student2 affects the age of the student object because both point to the same thing in memory.

Clone Object Properties

To clone the properties of an object, use the Object.assign() function with the spread operator. These allow you to update the attributes of the cloned object while keeping the original object's properties unchanged.

Example

const student = {
  name: "Aarav",
  age: 15,
  hobbies: ["drawing", "playing guitar", "cycling"]
};

const student2 = Object.assign({}, student);
student2.age = 25;

console.log(student);
console.log(student2);

Immutable Objects

Immutable objects are those that cannot be modified after they are created. Strings, numbers, booleans, null, and undefined are all immutable in JavaScript.

Example

let student1 = "Aarti";
let student2 = student1;

student1 = "Saurabh";
console.log(student1);
console.log(student2);

Changing student1 does not affect student2. Primitive values are copied, not referenced.

Creating Immutable Objects

  • Use Object.freeze() to block changes to an existing object or array.
  • Use the const keyword to prevent reassignment of variables.

Modifying Immutable Objects

Since immutable objects cannot be changed directly, you can use the spread operator or Object.assign() to create new versions with updates.

Using Spread Operator (Array Example)

const fruits = ["apple", "banana", "orange"];
const newFruits = [...fruits, "grape"];

console.log(newFruits);
console.log(fruits);

Using Spread Operator (Object Example)

const person = { name: "Maya", age: 30 };
const newPerson = { ...person, country: "India" };

console.log(newPerson);
console.log(person);

Using Object.assign()

const person = { name: "Maya", age: 30 };
const additionalInfo = { country: "India", hobby: "reading" };

const newPerson = Object.assign({}, person, additionalInfo);

console.log(newPerson);
console.log(person);

Benefits of Immutability

  • Avoids side effects in your code
  • Improves performance in frameworks like React
  • Makes debugging and reasoning about code easier

Drawbacks of Immutability

  • Increased memory consumption due to new object creation
  • Can impact garbage collection performance
  • Requires additional methods or operators, making code verbose
