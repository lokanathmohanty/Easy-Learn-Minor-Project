Java Programming: Binding Mechanisms

Session: Static Binding (Compile-Time Polymorphism)

What is Static Binding?

**Binding** is the mechanism that links a method call to its actual code implementation. **Static Binding** (also known as **Compile-Time Binding** or **Early Binding**) is the process where this link is resolved by the compiler **before** the program is executed (at compile time).

The compiler determines exactly which method implementation to call based solely on the method signature and the reference type declared in the source code.

Characteristics of Static Binding

The compiler uses the following information to resolve method calls at compile time:

  • **Linking Time:** Resolution occurs at **Compile Time**.
  • **Resolution Mechanism:** It uses the **type of the class** (declared reference type) and the **method signature** (name, number, and type of arguments).
  • **Example:** **Method Overloading** is the primary example of static binding.
  • **Methods Involved:** **Private**, **final**, and **static** methods use static binding because they cannot be overridden, making their call fixed and predictable.

Example: Method Overloading Uses Static Binding

In method overloading, the compiler decides which version of the add method to call based on the number and type of arguments provided during the call.

class Calculator{
   public static int add(int a, int b){ ... }      // Method 1 (Two args)
   public static int add(int a, int b, int c){ ... } // Method 2 (Three args)
}

public class Tester {
   public static void main(String args[]){
      // Compiler sees two arguments, links to Method 1 (Static Binding)
      System.out.println(Calculator.add(20, 40)); 
      
      // Compiler sees three arguments, links to Method 2 (Static Binding)
      System.out.println(Calculator.add(40, 50, 60)); 
   }
}

Output:

60
150

Static Binding with Different Argument Types

The principle remains the same when methods are differentiated by argument type. The compiler matches the call to the most appropriate method signature available in the class at compile time.

class Calculator{
   public int add(int a, int b){ ... }    // Accepts int
   public double add(double a, double b){ ... } // Accepts double
}

public class Tester {
   public static void main(String args[]){
      Calculator calculator = new Calculator();   
      
      // Compiler sees int arguments, links to int method
      System.out.println(calculator.add(20, 40));
      
      // Compiler sees double arguments, links to double method
      System.out.println(calculator.add(20.0, 40.0));
   }
}

Output:

60
60.0
