Next.js - Error Handling

Error Handling in Next.js

**Next.js** provides a built-in error handling mechanism to help developers detect and handle errors in their applications. For example, if a user tries to access a page that does not exist, you can display a custom **404 error page** according to your application theme.

There are two types of errors that can occur in Next.js:

  • **Expected Errors** (e.g., specific form validation issues)
  • **Unexpected Errors** (e.g., server-side crashes)

Expected errors are often handled by creating custom error pages. Unexpected errors are harder and can be caught using the **`useActionState`** hook to return the error message to the client.

Create a Page to Handle Internal Server Error (500)

An **Internal Server Error (500)** occurs when the server is unable to process a request. By default, Next.js shows a generic 500 page, but you can create a customized one by creating a file named **`500.tsx`** (or `.js`) in the root of the **`/app`** directory (or `/pages` for Pages Router).

Code for Custom 500 Page

// /app/500.tsx

export default function Custom500() {
    return (
        <div>
            <h1>500 - Server Error</h1>
            <p>Sorry, something went wrong on our server.</p>
        </div>
    );
}

This page will be displayed when an unexpected error is thrown on the server side (e.g., inside a Server Component or a Server Action).

Create a Custom 404 Error Page

A **404 error** is raised when a user tries to access a route that does not exist in the application. To handle this, you can create a file named **`not-found.tsx`** (App Router) or **`404.tsx`** (Pages Router).

Code for Custom 404 Page (Pages Router Example)

// /app/404.tsx

export default function Custom404() {
    return (
        <div>
            <h1>404 - Page Not Found</h1>
            <p>Sorry, the page you are looking for does not exist.</p>
        </div>
    );
}

Handling Unexpected Errors (Form Validation)

Unexpected errors, especially those that result from server-side logic like failed form validation, should be handled explicitly and returned to the client for better user experience.

You can use the **`useActionState`** hook from React (imported via `'use client'`) to catch the result (including errors) of a Server Action and update the UI with a message.

  • **Recommendation**: Avoid using `try/catch` blocks for **expected errors**. Instead, model expected errors as return values of the action, not as thrown exceptions.

Example using `useActionState`

This example shows a Client Component using `useActionState` to manage the state returned by a Server Action (`createPost`).

// Component using the Server Action

'use client'
import { useActionState } from 'react'
import { createPost } from '@/app/actions'

const initialState = {
  message: '',
}

export function Form() {
  // useActionState returns a state object, the action, and the pending status
  const [state, formAction, pending] = useActionState(createPost, initialState)

  return (
    <form action={formAction}>
        <textarea id="content" name="content" required />
        {state?.message && <p>{state.message}</p>} <!-- Display error message -->

        <button disabled={pending}>Create Post</button>
    </form>
  )
}
