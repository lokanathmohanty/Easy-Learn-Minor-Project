Java Z Garbage Collector (ZGC)

What is ZGC?

The **Z Garbage Collector (ZGC)** is a scalable, low-latency garbage collection mechanism introduced in **Java 11** as an experimental feature and made a standard feature in **Java 15**. ZGC is designed for applications requiring extremely low pause times, even with very large heaps.

Key Differentiating Feature: Low Pause Time

ZGC's central guarantee is that the garbage collection **pause time is not dependent on the heap size**. Regardless of whether the heap is 2MB or 16TB, the maximum pause time will ideally **never exceed 10 milliseconds** (ms). This makes it perfect for applications like large-scale machine learning or massive data processing where responsiveness is critical.

Evolution and Enhancements (Java 16+)

Initially, ZGC had limitations, such as not being able to return unused heap memory to the operating system. Subsequent Java versions, particularly Java 16, brought significant improvements:

  • Dynamic Heap Management: ZGC now returns uncommitted heap memory to the operating system by default (unless the maximum heap size is reached).
  • Scalability: The maximum supported heap size has been increased from 4TB to a massive **16TB**.
  • Concurrent Stack Processing: Thread-stack processing was moved from being a safepoint-blocking operation to a **concurrent, incremental, and lazy** phase, dramatically reducing pause times further.
  • NUMA Awareness: Support for Non-Uniform Memory Access architectures for better performance on large servers.

Using and Configuring ZGC

ZGC is not the default collector (G1 is the default in modern JVMs) and must be explicitly enabled using a JVM flag.

Enabling ZGC

To enable the Z Garbage Collector, use the following JVM argument:

-XX:+UseZGC

Heap Uncommit/Memory Return

By default, modern ZGC (Java 15+) will return unused memory to the OS. To revert to the older behavior (pre-Java 15), you can:

  • Use the option: -XX:-ZUncommit
  • Set the initial and maximum heap sizes to be the same: -Xms<size> -Xmx<size>
