Next.js Static Site Generation (SSG) 🧱

What is Static Site Generation (Static Rendering)?

**Static Site Generation (SSG)** is an optimization technique where the HTML for a page is rendered at **build time** (when you run `next build`). This fully formed HTML is then **cached** by a Content Delivery Network (CDN) and served to the client almost instantaneously on every request.

Because the HTML is ready before the user ever asks for it, SSG provides **superior performance**, **better user experience**, and is excellent for **SEO**.

By default, all components in Next.js that do not involve data fetching are statically rendered.

Implementing SSG with Data Fetching

For pages that fetch external data but whose content rarely changes, you can use SSG to pre-render the data into the HTML at build time.

1. SSG for Simple Pages

In the **Page Router** (Next.js < 13), you export the **`getStaticProps()`** asynchronous function. This function runs only on the server at build time, fetches the necessary data, and passes it as props to the React component.

// Use getStaticProps to fetch data at build time
export async function getStaticProps() {
    const response = await fetch('https://link/to/api');
    const posts = await response.json();
  
    return {
      props: { posts }, // Data passed to the component
    };
}

2. SSG for Dynamic Routes

For dynamic pages (like product detail pages or individual blog posts), Next.js needs to know **which specific paths** to pre-render at build time. This is achieved by exporting a second function: **`getStaticPaths`**.

  • **`getStaticPaths`:** This function fetches a list of possible IDs (or slugs) from an external source and returns an array of **`paths`** to pre-render.
  • **`getStaticProps`:** This function runs for **each path** returned by `getStaticPaths`, using the `params` object to fetch the data specific to that ID.
// pages/product/[id]/page.tsx file (Page Router example)

export async function getStaticPaths() {
    // 1. Fetch all available product IDs
    const products = await fetch('...').then(res => res.json());
    
    // 2. Map IDs to path objects
    const paths = products.map((product) => ({
        params: { id: product.id.toString() },
    }));
    
    // 3. Return paths and set fallback to false (404 for unlisted paths)
    return { paths, fallback: false };
}

When to Use SSG

SSG is the ideal choice (and the Next.js default behavior) for content that prioritizes speed and does not change often:

  • ✅ **Marketing Pages:** Landing pages, company info, static FAQs.
  • ✅ **Blog Posts & Documentation:** Content that is updated only when the site is rebuilt.
  • ✅ **Any Page** that can tolerate its content being slightly outdated between deployments.
