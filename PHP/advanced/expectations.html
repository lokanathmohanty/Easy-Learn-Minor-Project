PHP Expectations (Enhanced $\text{assert()}$) 🧐

**Expectations** are a backward-compatible enhancement to the traditional $\text{assert()}$ function, introduced in PHP 7. This update allows $\text{assert()}$ to be used for **zero-cost assertions in production code** and provides the critical ability to **throw custom exceptions** when an assertion fails.

The $\text{assert()}$ Language Construct

In PHP 7, $\text{assert()}$ is no longer just a function but a **language construct**. Its primary parameter is now an **expression** that returns a value to be tested, not just a string to be evaluated.

assert(mixed $assertion, mixed $description_or_exception): bool

Parameters:

  • $\text{\$assertion}$: An expression whose resulting value is used to determine success or failure.
  • $\text{\$description\_or\_exception}$:
    • **String:** An optional description included in the failure message (PHP 5 behavior).
    • **$\text{Throwable}$ Object (PHP 7+):** The custom exception object that will be thrown if the assertion fails and the $\text{assert.exception}$ directive is enabled.

Configuration Directives for $\text{assert()}$

The behavior of $\text{assert()}$ is controlled by two key $\text{php.ini}$ directives:

Directive Value Description
$\text{zend.assertions}$ $\text{1}$ (Default) **Development Mode:** Code is generated and executed. Assertions are active.
$\text{0}$ Code is generated but **skipped at runtime** (zero-cost). The assertion still performs an internal warning check (PHP 7 behavior).
$\text{-1}$ **Production Mode:** Assertion code is **not generated** at all (true zero-cost).
$\text{assert.exception}$ $\text{1}$ When assertion fails, it **throws** the provided $\text{Throwable}$ object, or a new $\text{AssertionError}$ if none was provided. (Recommended for unit testing and development).
$\text{0}$ (Default) When assertion fails, it only generates a **warning** based on the $\text{Throwable}$ object rather than throwing it (PHP 5 compatibility).

Throwing Custom Exceptions Example

By setting $\text{assert.exception}$ to 1, you enable the "Expectation" behavior, allowing you to use a custom exception (which must ultimately implement $\text{Throwable}$ or extend $\text{AssertionError}$).

<?php
   // Enable the throwing of exceptions upon assertion failure
   ini_set('assert.exception', 1);
   
   // Define a custom error class
   class CustomError extends AssertionError {}
   
   // This assertion fails (false) and throws the CustomError object
   assert(false, new CustomError('Custom Error Message!'));
   
   // Output: PHP Fatal error: Uncaught CustomError: Custom Error Message!
?>
