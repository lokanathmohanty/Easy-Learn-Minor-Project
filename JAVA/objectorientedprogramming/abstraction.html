Java Programming: Object-Oriented Concepts

Session: Abstraction (Hiding Complexity)

What is Abstraction?

**Abstraction** is an OOP principle of **hiding the complex implementation details** and showing only the essential functionality to the user. It focuses on *what* an object does rather than *how* it does it. This is achieved in Java primarily using **Abstract Classes** and **Interfaces**.

For example, when you send an email, you interact with the simple interface (typing content and clicking send), while the underlying network protocols and server operations remain hidden.

Java Abstract Classes

An **Abstract Class** is a class declared using the **abstract** keyword.

  • **Instantiation:** An abstract class **cannot be instantiated** (you cannot create objects of it directly).
  • **Purpose:** It is meant to be **inherited** by subclasses, which then provide the concrete implementation.
  • **Contents:** An abstract class may contain **abstract methods** (methods without a body) and **concrete methods** (methods with a body) and constructors.
  • **Rule:** If a class contains at least one abstract method, the entire class **must** be declared abstract.

Java Abstract Methods

An **Abstract Method** is a method declared with the **abstract** keyword. It has a method signature but **no method body** (ending with a semicolon instead of curly braces).

public abstract class Employee {
   public abstract double computePay(); // Abstract method (no body)
   // Remainder of class definition
}

Implementation Rule: Any concrete (non-abstract) class that inherits an abstract class **must** provide implementations (override) for all of its abstract methods. If it fails to do so, the inheriting class must also be declared abstract.

Example: Abstract Class Inheritance

The abstract class Employee defines a common structure, but a subclass like Salary must implement the specific logic for methods like computePay().

abstract class Employee {
   // Abstract method, forces implementation in child classes
   public abstract double computePay(); 
   
   // Concrete method, provides default behavior
   public void mailCheck() { ... } 
}

class Salary extends Employee {
   // Must implement the abstract method
   @Override
   public double computePay() {
      // Provides specific implementation for computing salary
      return salary / 52;
   }
   
   // Overrides the concrete method from the parent
   @Override
   public void mailCheck() {
      System.out.println("Mailing check to " + getName() + " with salary " + salary);
   }
}

Demonstrating Abstraction and Polymorphism

You cannot create an Employee object, but you can use an Employee reference to point to a Salary object, demonstrating polymorphism while leveraging abstraction.

public class AbstractDemo {
   public static void main(String [] args) {
      // 1. Instantiating Employee is ERROR (it's abstract)
      // Employee e_error = new Employee(...); 

      // 2. Creating a Salary object (allowed)
      Salary s = new Salary("Mohd Mohtashim", "UP", 3, 3600.00); 

      // 3. Using polymorphic reference (allowed)
      Employee e = new Salary("John Adams", "MA", 2, 2400.00); 

      // Dynamic binding ensures the Salary version of mailCheck() runs:
      e.mailCheck();
   }
}

The code works because the reference type (`Employee`) has the `mailCheck()` method, but the runtime object type (`Salary`) determines the actual implementation that executes.
