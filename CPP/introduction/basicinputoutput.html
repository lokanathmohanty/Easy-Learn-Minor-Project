C++ Basic Input/Output (I/O) Streams

C++ I/O operations are handled in **streams**, which are sequences of bytes. **Input** is the flow of bytes from a device (e.g., keyboard) to main memory, and **Output** is the flow of bytes from main memory to a device (e.g., display screen).

The standard I/O objects are defined in the <iostream> header file and are instances of stream classes (istream for input, ostream for output).

Standard I/O Streams and Operators 🌊

The <iostream> library provides four essential stream objects:

  • Standard Output (cout): Connected to the display screen. It uses the **stream insertion operator** (<<) to send data from the memory to the output device.

    cout << "Hello" << endl;

  • Standard Input (cin): Connected to the keyboard. It uses the **stream extraction operator** (>>) to take data from the input device and store it in a variable in memory.

    cin >> name >> age;

  • Standard Error (cerr): Connected to the display screen for **un-buffered** error messages. Output appears immediately, making it suitable for critical error reporting.
  • Standard Log (clog): Connected to the display screen for **buffered** log messages. Output is held in a buffer until the buffer is full or explicitly flushed, suitable for less time-sensitive logging.

I/O Library Header Files

To use I/O features, you must include the necessary header files:

  • <iostream>: Defines the basic I/O objects (cin, cout, cerr, clog).
  • <iomanip>: Declares services for **formatted I/O**, such as setw (set width) and setprecision.
  • <fstream>: Declares services for user-controlled **file processing**.

Using <bits/stdc++.h> for I/O and More 💡

The <bits/stdc++.h> is a non-standard, GCC-specific header file that includes **most of the standard C++ libraries**, including I/O, strings, vectors, and algorithms. It simplifies code by eliminating the need to specify multiple headers individually, which is popular in competitive programming.

Effect of endl: The endl manipulator inserts a **new-line character** and also **flushes the output buffer**, ensuring the output is immediately displayed.
