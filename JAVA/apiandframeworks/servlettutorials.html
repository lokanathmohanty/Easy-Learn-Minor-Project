Java Servlets Summary 🌐🚀

Java Servlets provide a component-based, platform-independent method for building **Web-based applications**. They act as a middle tier between a web browser (or other HTTP client) and a web server, handling client requests and dynamically generating responses.

I. Key Advantages Over CGI

Servlets were developed to overcome the performance and security limitations of the older Common Gateway Interface (CGI) programs:

  • Superior Performance: Servlets execute **within the address space of the Web server** (managed by a Servlet Container like Tomcat). Unlike CGI, it is **not necessary to create a separate OS process** to handle each client request, saving significant time and resources.
  • Platform Independence: Since they're written in Java, they run on any platform with a Java Virtual Machine (JVM).
  • Robustness & Security: Servlets are managed by the Java security manager on the server, enforcing restrictions and protecting server resources.
  • Access to Java APIs: Servlets have full access to the entire Java API family, including **JDBC** for database access, RMI, and sockets.

II. Servlet Life Cycle and Core Methods

Servlets follow a strict, container-managed life cycle, primarily implemented by extending the **HttpServlet** abstract class from the **javax.servlet.http** package:

  1. **init():** Called once by the container upon loading the servlet. Used for one-time initialization (e.g., setting up a database connection pool or static configuration).
  2. **service():** The container calls this for every client request. It dispatches the request to the appropriate `doGet()`, `doPost()`, or other `do*()` method based on the HTTP method.
  3. **doGet(request, response) / doPost(request, response):** The workhorse methods. They handle the business logic of the request (e.g., retrieving data) and formulate the response.
    • **HttpServletRequest:** Provides client data (parameters, headers, cookies).
    • **HttpServletResponse:** Used to send the final response back to the client (setting content type, writing the output stream via **PrintWriter**).
  4. **destroy():** Called once by the container before the servlet is taken out of service. Used to perform cleanup (e.g., closing open database connections).

III. Applications and Functionality

Servlets perform the core server-side tasks necessary for dynamic web applications:

  • **Request Handling:** Read explicit data (HTML form fields) and implicit HTTP data (cookies, headers, session data) sent by the client.
  • **Business Processing:** Execute complex tasks, which may involve:
    • Talking to a database (via JDBC).
    • Invoking external services (Web services, RMI calls).
    • Computing the required response directly.
  • **Response Generation:** Send explicit data (the document content) to the client, which can be in various formats: **HTML**, **XML**, **JSON**, or binary data (like images). They also manage implicit HTTP responses (setting status codes, content type, and caching parameters).
