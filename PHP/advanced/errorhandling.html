PHP - Error and Exception Handling

Error Handling in PHP is the mechanism for effectively identifying, reporting, and gracefully recovering from runtime issues. PHP offers traditional error functions and a modern exception model (introduced in PHP 5 and significantly improved in PHP 7 with the $\text{Throwable}$ interface).

1. Basic Error Control: $\text{die()}$ Function

The $\text{die()}$ function (an alias of $\text{exit()}$) immediately **terminates** the execution of the current PHP script. It is often used for simple, unrecoverable errors, such as a failed file or database connection, to display a custom message before halting.

<?php
   if(!file_exists("nosuchfile.txt")) {
      die("File not found");
   } 
   // Execution stops here if file is not found.
?>

2. Custom Error Handler Function

For more elegant and non-fatal error handling, you can define a custom function to catch errors using $\text{set\_error\_handler()}$.

  • Function: $\text{set\_error\_handler(callable \$callback, int \$error\_levels)}$
  • Callback Signature: $\text{handler(int \$errno, string \$errstr, string \$errfile, int \$errline, array \$errcontext)}$
  • The custom function is automatically called when an error matching the specified $\text{\$error\_levels}$ is encountered.

Predefined Error Constants ($\text{errno}$)

Errors are categorized by integer constants, allowing handlers to differentiate error types:

  • $\text{E\_ERROR}$: Fatal, unrecoverable run-time errors (script halts). (Value: 1)
  • $\text{E\_WARNING}$: Run-time warnings (non-fatal, script continues). (Value: 2)
  • $\text{E\_NOTICE}$: Run-time notices (minor errors that may be okay). (Value: 8)
  • $\text{E\_USER\_ERROR}$: User-generated errors via $\text{trigger\_error()}$. (Value: 256)
  • $\text{E\_ALL}$: All errors, warnings, and notices. (Value: 32767)

3. Modern Error and Exception Classes (PHP 7+)

PHP 7 introduced the **$\text{Throwable}$** interface, which is the base for both the traditional **$\text{Exception}$** class and the new **$\text{Error}$** class hierarchy. This allows unrecoverable internal PHP errors to be caught like exceptions.

Key Built-in Error Classes

  • **$\text{ArithmeticError}$**: Occurs during certain mathematical operations (e.g., bit shift by a negative number).
  • **$\text{DivisionByZeroError}$**: Occurs when the denominator is zero in division ($\text{/}$) or modulo ($\text{\%}$) operations, or $\text{intdiv()}$.
  • **$\text{ArgumentCountError}$**: Thrown when a function or method is called with fewer arguments than required.
  • **$\text{TypeError}$**: Thrown when argument types do not match the declared type hints in strict mode ($\text{declare(strict\_types=1)}$), or when a built-in function is given incorrect types/counts.

4. Exception Handling ($\text{try-catch-throw}$)

Exceptions provide a structured way to handle anticipated errors. The model uses three keywords:

  • **$\text{try}$**: The block of code where an exception might be thrown.
  • **$\text{throw}$**: The keyword used to trigger an exception, creating an $\text{Exception}$ object. Code following $\text{throw}$ is not executed.
  • **$\text{catch}$**: The block that retrieves and handles the thrown exception object.

Example: Catching and Reopening Execution

<?php
   try {
      $error = 'Always throw this error';
      throw new Exception($error); // Exception thrown
      echo 'Never executed'; // Skipped
   } catch (Exception $e) {
      echo 'Caught exception: ',  $e->getMessage();
   }
   
   echo 'Hello World'; // Execution continues here
?>

Exception Methods

The $\text{Exception}$ class offers several methods for inspecting the error, including:

  • $\text{getMessage()}$: The exception message.
  • $\text{getCode()}$: The exception code.
  • $\text{getFile()}$: The source filename where the exception occurred.
  • $\text{getLine()}$: The line number where the exception occurred.

Custom Exception Handler

The $\text{set\_exception\_handler(callback \$exception\_handler)}$ function can register a default function to be called if an exception is **uncaught** anywhere in the script, preventing the default PHP fatal error from being displayed.
