Java Switch Expressions (Java 14+)

From Switch Statement to Switch Expression

The **Switch Expression** was introduced as a preview feature in Java 12, refined in Java 13 with the addition of the **yield** keyword, and became a standard feature in **Java 14**. It modernizes the traditional switch statement by allowing it to be used as an **expression** that returns a single value.

The traditional switch statement suffered from verbosity, required **break** statements to prevent fall-through (a common source of bugs), and could not directly return a value.

Key Benefits of Switch Expressions

  • Return Value: It can be used directly on the right-hand side of an assignment or as a method return value.
  • No Fall-Through: The new arrow syntax (->) eliminates fall-through, removing the need for break.
  • Conciseness: Multiple case labels can be comma-separated.
  • Exhaustiveness: When using an enum, the compiler can ensure all possible enum constants are covered, potentially allowing the default case to be omitted. Otherwise, a default case is typically required to cover all possibilities.

Syntax Options for Returning a Value

1. The Arrow (case L ->) Syntax (Recommended)

This is the most concise form. The expression, statement, or block to the right of the arrow is executed, and its result is the value of the switch expression. **Fall-through is impossible** with this syntax.

Syntax: case label1, label2 -> expression;

String dayType = switch (day) {
   case "Sat", "Sun" -> "Weekend"; // returns "Weekend"
   default -> "Weekday";
};

2. The Colon (case L:) Syntax with yield

If the traditional colon-based syntax is used, or if a case requires multiple statements (a code block), the new **yield** keyword must be used to explicitly return a value from that specific case block.

Syntax: case label: { statements; yield value; }

  • yield works similarly to return but exits only the switch expression, not the entire method.
  • If the colon syntax is used, fall-through remains possible, so a break or yield is necessary to prevent it.
String result = switch (day) {
   case "Monday": {
      System.out.println("Starting the week...");
      yield "Weekday"; // Explicitly returns the value
   }
   default: 
      yield "Invalid day";
};

Example Comparison: Old Statement vs. New Expression

The new switch expression combines logic and assignment into a single, less error-prone block:

// --- Old Switch Statement (Requires break/fall-through) ---
public static String getDayTypeOldStyle(String day) {
   String result = null;
   switch (day) {
      case "Monday": 
         result = "Weekday";
         break; // Necessary break
      // ... more cases
   }
   return result;
}

// --- New Switch Expression (Concise and returns value directly) ---
public static String getDayType(String day) {
   return switch (day) {
      case "Monday", "Tuesday", "Wednesday" -> "Weekday";
      case "Saturday", "Sunday" -> "Weekend";
      default -> "Invalid day."; // Required unless using exhaustive enum
   };
}
