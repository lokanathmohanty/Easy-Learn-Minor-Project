Java Dynamic Class Data Sharing (CDS)

What is Class Data Sharing (CDS)?

Class Data Sharing (CDS), originally introduced in JDK 5, is a feature of the JVM designed to **improve application startup time** and **reduce memory footprint**. It works by creating a pre-processed archive of class metadata and core classes (like those in java.lang).

When multiple JVMs run on the same machine, they can all share this single archive, avoiding the redundant work of:

  • Decompressing class files.
  • Validating class structure.
  • Loading and preparing class metadata.

Evolution of CDS

  • **JDK 5:** Introduced CDS for core platform classes.
  • **Java 10 (AppCDS):** Extended CDS to include **application classes**, allowing developers to archive their own classes.
  • **Java 12:** CDS became **default** for the system archive.

Dynamic CDS (Java 13+)

Prior to Java 13, creating an AppCDS archive was a tedious, multi-step process involving trial runs to generate a complete list of all classes loaded, which was then used to dump the archive.

Dynamic CDS (introduced in **Java 13**) simplifies this by allowing developers to generate the shared archive automatically when the application **exits**, eliminating the need for separate pre-run steps to collect class lists.

Creating a Dynamic Shared Archive

The shared archive file is generated during a normal run of the application using the JVM option **-XX:ArchiveClassesAtExit**:

Command to Create Archive:

$ java -XX:ArchiveClassesAtExit=sharedApp.jsa -cp APITester.jar APITester

When the APITester application finishes execution, the JVM automatically captures the metadata of all classes loaded during that run and saves it to the specified sharedApp.jsa file.

Using the Dynamic Shared Archive

To benefit from the created archive in subsequent runs, you use the **-XX:SharedArchiveFile** option:

Command to Use Archive:

$ java -XX:SharedArchiveFile=sharedApp.jsa -cp APITester.jar APITester

The JVM will then load the required class metadata directly from the sharedApp.jsa file, resulting in faster startup.
