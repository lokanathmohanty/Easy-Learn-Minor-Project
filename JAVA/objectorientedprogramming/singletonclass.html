Java Programming: Design Patterns

Session: Singleton Class (Creational Pattern)

What is the Singleton Design Pattern? 🥇

The **Singleton Pattern** is a creational design pattern that ensures a class has **only one instance** and provides a global point of access to that instance.

The class itself is responsible for creating and maintaining its single object, and it controls how that object is accessed.

Achieving the Singleton Pattern in Java

The Singleton pattern is achieved by applying three core principles to the class:

  1. **Private Constructor:** Prevents any other class from directly instantiating the class using the new operator.
  2. **Private Static Instance:** A single, private, static field holds the only instance of the class.
  3. **Public Static Factory Method:** A public static method (conventionally named getInstance()) provides the global access point to the single instance.

Advantages and Use Cases

The Singleton pattern is used when **exactly one object** is required to coordinate actions across the system.

  • **Memory Management:** Saves memory because object creation overhead occurs only once.
  • **Controlled Access:** Provides a controlled access point to the object, often controlling access to shared resources.
  • **Common Use Cases:**
    • **Logger Classes** (all code writes to the same log file instance).
    • **Configuration Managers** (one object holds all application settings).
    • **Database Connection Pools** or thread pools.

Types of Singleton Implementations

1. Eager Initialization (Initialization on Load)

The instance is created at the time of class loading, guaranteeing its availability, but possibly using resources before it's actually needed.

class Singleton {
   // Instance created immediately when the class is loaded
   private static Singleton singleton = new Singleton(); 

   private Singleton() { } // Private constructor

   public static Singleton getInstance() {
      return singleton; // Just returns the existing instance
   }
}

2. Lazy Initialization (Classic Singleton)

The instance is created only when the getInstance() method is called for the first time. This is more memory efficient if the instance is never used, but is **not thread-safe** in a multithreaded environment.

class ClassicSingleton {
   private static ClassicSingleton instance = null; // Initially null

   private ClassicSingleton() { }

   // NOT thread-safe
   public static ClassicSingleton getInstance() {
      if(instance == null) {
         instance = new ClassicSingleton(); // Created only upon first call
      }
      return instance;
   }
}

3. Thread-Safe Lazy Initialization

By adding the **synchronized** keyword, the method ensures that only one thread can execute the instance creation logic at a time, preventing multiple threads from creating multiple objects.

class ThreadSafeSingleton {
   private static ThreadSafeSingleton instance = null;

   private ThreadSafeSingleton() { }

   // Thread-safe, but adds performance overhead for every call
   public static **synchronized** ThreadSafeSingleton getInstance() {
      if(instance == null) {
         instance = new ThreadSafeSingleton();
      }
      return instance;
   }
}
