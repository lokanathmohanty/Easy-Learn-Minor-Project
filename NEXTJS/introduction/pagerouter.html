Introduction to the Page Router

The **Page Router** is the routing system used in **Next.js versions before 13**. In this model, the structure of files within the **`/pages`** directory automatically defines the application's routes. Each **React component** file inside `/pages` becomes a distinct route.

Step 1 & 2: Setup and Basic Routing

Project Creation

When starting a new project with `npx create-next-app@latest`, you must explicitly choose the **Page Router** setup when prompted.

File-System Routing

The Page Router uses files, often named `index.tsx`, inside folders to define routes:

  • `pages/index.tsx` → **`/`** (The Home Route)
  • `pages/about.tsx` → **`/about`** (or `pages/about/index.tsx`)
  • `pages/contact/index.tsx` → **`/contact`**

Step 3 & 4: Nested and Dynamic Routes

Nested Routes

To create nested routes, you create a directory inside `/pages` and place an `index.tsx` file inside it. For example, the `/about` route is defined by `pages/about/index.tsx` (or simply `pages/about.tsx`).

Dynamic Routes

To create a route that accepts a parameter, define the filename using **square brackets** (`[paramName].tsx`). The parameter is accessed using the **`useRouter`** hook from `next/router`.

  • **Route File:** `pages/users/[id].tsx` → URL is `/users/123`.
  • **Accessing Parameter:** The parameter is found in `router.query`.
// Inside pages/users/[id].tsx
import { useRouter } from 'next/router';

export default function UserProfile() {
  const router = useRouter();
  const { id } = router.query; // Retrieves the dynamic 'id' value
  return <h1>User Profile: {id}</h1>;
}

Step 5: API Routes

**API Routes** (for creating backend endpoints) are defined inside the **`pages/api`** directory. Any file within this folder becomes an API endpoint that handles incoming requests.

  • **API File:** `pages/api/hello.js` → Endpoint is **`/api/hello`**.
// Inside pages/api/hello.js
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello, Next.js API!' });
}
