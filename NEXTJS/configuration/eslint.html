Next.js ESLint Configuration 🛠️

What is ESLint?

**ESLint** is a powerful **static code analysis tool** for JavaScript (and TypeScript). It quickly examines your code without executing it, identifying and reporting issues related to code quality, style violations, potential security problems, and adherence to specific coding standards.

Next.js includes the custom **`eslint-plugin-next`** plugin bundled in its base configuration to help developers catch common framework-specific issues in Next.js applications.

Configuring ESLint in Next.js

Step 1: Installation

You install the core ESLint library and the official Next.js configuration package.

// Using npm
npm install eslint eslint-config-next --save-dev

Step 2: Configuration File (`.eslintrc.json`)

Create a configuration file to tell ESLint which ruleset to extend. The recommended setting is **`next/core-web-vitals`**, which includes rules focused on optimizing for modern web performance metrics.

// File: .eslintrc.json
{
    "extends": "next/core-web-vitals"
}

You should also ensure your `package.json` references this configuration:

"eslintConfig": {
    "extends": "next"
}

Step 3: Creating the Lint Command

Define a script in `package.json` to easily run the linting process using the built-in Next.js command:

// File: package.json
"scripts": {
    "lint": "next lint"
}

To run, execute: `npm run lint`.

Customizing Linting Behavior

1. Limiting Directories for Production Builds

By default, Next.js checks common directories (e.g., `pages/`, `app/`, `components/`). You can specify which directories should be linted during the **production build** (`next build`) using the `dirs` option in `next.config.js`.

// File: next.config.ts
module.exports = {
    eslint: {
      dirs: ['pages', 'utils'], // Only checks these directories during 'next build'
    },
};

2. Disabling Linting During Production Builds

To ensure a production build succeeds even if ESLint errors are present, you can disable linting during the build process entirely. This is generally discouraged unless you run linting checks as a separate step in your CI/CD pipeline.

// File: next.config.ts
const nextConfig = {
  eslint: {
    ignoreDuringBuilds: true, // ← Build will complete despite ESLint errors
  },
};
export default nextConfig;

3. Disabling the Cache

For better performance, Next.js caches ESLint results in the `.next/cache` directory. If you are using advanced ESLint rules that depend on files outside the one currently being processed, you may need to disable the cache:

next lint --no-cache
