Django Model Updates and the Migration System 🔄

While the **ORM** methods like create(), update(), and delete() handle **data** operations on existing tables, the **Migration System** is responsible for propagating **structural changes** (adding, deleting, or altering fields/models) to the database schema. This mechanism ensures that the changes made to your Python models are correctly reflected in your database.

The Django Migration System

The migration system is Django's way of dealing with database schema changes. Changes made to models in models.py are translated into Python migration files, which are then used to modify the underlying database.

Migration Workflow Commands

The core commands are executed using the manage.py script:

  • makemigrations [app_name]: Creates new migration scripts based on changes detected in the model definitions since the last migration.
  • migrate [app_name] [migration_name]: Responsible for applying or unapplying (rolling back) migration scripts to the database. Running python manage.py migrate for the first time creates all necessary tables for INSTALLED_APPS.
  • showmigrations: Lists all migration files for the project and indicates which ones have been applied (marked with an **[X]**).
  • sqlmigrate [app_name] [migration_name]: Displays the raw SQL commands that a migration will run.

Applying Changes Example (Adding/Altering Fields)

When you change a model's structure (e.g., dropping eemail and adding salary to the Employee model), the process involves:

  1. **Generate Script:** Run makemigrations to create a new script (e.g., 0003_...py) that records the removal and addition of fields. 
    D:\...myproject> python manage.py makemigrations myapp
Migrations for 'myapp':
   myapp\migrations\0003_remove_employee_eemail_employee_salary.py
      - Remove field eemail from employee
      - Add field salary to employee
  2. **Apply Change:** Run migrate to execute the script and modify the table structure in the database. 
    D:\...myproject> python manage.py migrate
...
Running migrations:
   Applying myapp.0003_remove_employee_eemail_employee_salary... OK

Rolling Back Changes

To undo recent structural changes and revert the database schema to a previous migration state, you run migrate specifying the target app and the **previous migration file name**.

To roll back the changes introduced by 0003_...py and restore the state of 0002_employee.py:

$ python manage.py migrate myapp 0002_employee
Unapplying myapp.0003_remove_employee_eemail_employee_salary... OK

This "unapplies" the later migration, restoring the database table structure to its former definition.
