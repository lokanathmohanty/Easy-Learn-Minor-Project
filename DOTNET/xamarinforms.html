Creating a Xamarin.Forms Project and Referencing a Private NuGet Feed

This chapter introduces **Xamarin.Forms**, a framework for creating cross-platform user interfaces, and details the steps to set up a new project and configure it to consume the NuGet package published to a private feed in the previous chapter.

Xamarin.Forms is a cross-platform, natively backed UI toolkit that abstracts user interfaces, allowing code to be shared across **Android**, **iOS**, **Windows**, and **Windows Phone**. The UI is rendered using the native controls of the target platform, maintaining the appropriate look and feel for each OS.

Visual Studio Setup for Xamarin.Forms

To enable Xamarin development in Visual Studio 2015, you must modify your installation:

  1. Run the Visual Studio 2015 setup and select the **Modify** option.
  2. Ensure the **Cross-Platform Mobile Development** option is selected and install the necessary components.
  3. After installation, check for updates by going to **Tools → Options → Xamarin → Other** and clicking **Check Now**. Download and install any available updates.

Creating the Xamarin.Forms Project

A new Xamarin.Forms solution includes a shared Portable Class Library (PCL) project and platform-specific projects for each target (Android, iOS, etc.).

  1. In Visual Studio, select **File → New → Project**.
  2. In the left pane, choose the **Visual C# → Cross-Platform** template.
  3. In the middle pane, select the **Blank Xaml App (Xamarin.Forms Portable)** template.
  4. Enter a name for the solution and click **OK**.
  5. Select the target and minimum versions for the supported platforms (e.g., UWP, Android).

The resulting solution will contain a **PCL library** at the top, which holds the shared C# and XAML code (like App.xaml and MainPage.xaml) that will run on all target platforms.

Adding the Private NuGet Feed Source

Before installing the custom package, the private NuGet feed must be added to Visual Studio's list of package sources:

  1. Open the **Manage NuGet Packages** dialog for the shared PCL project.
  2. Click the **Settings icon** (wheel) next to the "Package source" dropdown list.
  3. Click the **plus (+) button** to add a new source.
  4. Provide a **Name** (e.g., PrivateSource) and the **Source Path** (e.g., D:\PrivateNugetPackages).
  5. Click **OK** to save the new package source.

Installing the StringLibrary Package

With the private source configured, you can now attempt to install your shared library:

  1. In the NuGet Package Manager's **Browse** tab, select the **PrivateSource** from the **Package source** dropdown list.
  2. Search for and select the **StringLibrary** NuGet package.
  3. Click **Install** and proceed through the installation prompts.

⚠️ Note: At this stage, the installation will likely fail with a compatibility error, specifically related to the PCL library using **Profile 259**. This indicates a mismatch between the library's target framework and the package's requirements, a common issue that must be fixed before proceeding.
