Next.js - Session Management

What is Session Management?

Session management is the process of maintaining a user's **authenticated state** across multiple interactions, such as page reloads or closing/reopening the browser. It ensures that once a user is verified (authenticated), their state is preserved until the session expires or is manually terminated.

There are two primary approaches to session management:

  • Stateless Session (Token-based, data in cookie)
  • Database Session (State stored on the server)

Stateless Session Management

In a stateless session, the user's session data is **not stored on the server**; instead, it's stored, usually in an **encrypted form**, within a cookie on the user's browser. With every request, the browser sends this cookie to the server, where the data is verified and decrypted. This method is simpler to scale but requires robust security measures.

Implementation Steps

  1. Generate a Secret Key: Create a strong, random key (e.g., using openssl rand -base64 32) and store it securely as an **environment variable** (e.g., SESSION_SECRET). This key is used to sign and encrypt the session data.
  2. Encrypt/Decrypt Session Data: Use a library like **jose** to encrypt and sign the session payload (e.g., a **JSON Web Token - JWT**) before sending it to the browser, and to verify and decrypt it upon request.
  3. Manage Cookies: Use the Next.js **cookies API** to set the session cookie with appropriate security flags.

Example: Encrypting and Decrypting Session Data (using JWT)

The encrypt function signs the payload and sets an expiration time (e.g., 7 days), and decrypt verifies the signature and expiration.

// app/lib/session.ts - Encryption Logic
export async function encrypt(payload: SessionPayload) {
  return new SignJWT(payload)
    .setProtectedHeader({ alg: 'HS256' })
    .setIssuedAt()
    .setExpirationTime('7d')
    .sign(encodedKey) // Uses the secret key
}

export async function decrypt(session: string | undefined = '') {
  try {
    const { payload } = await jwtVerify(session, encodedKey, {
      algorithms: ['HS256'],
    })
    return payload
  } catch (error) {
    console.log('Failed to verify session')
  }
}

Example: Setting the Secure Cookie

The cookie is set with critical security flags:

  • httpOnly: true: Prevents client-side JavaScript access.
  • secure: true: Ensures the cookie is only sent over HTTPS.
  • sameSite: 'lax': Helps prevent Cross-Site Request Forgery (CSRF).
// app/lib/session.ts - Setting Cookie
export async function createSession(userId: string) {
  const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
  const session = await encrypt({ userId, expiresAt })
  const cookieStore = await cookies()
 
  cookieStore.set('session', session, {
    httpOnly: true,
    secure: true,
    expires: expiresAt,
    sameSite: 'lax',
    path: '/',
  })
}

Database Session Management

In this approach, the core session data (including user ID and expiration) is stored in a dedicated **database table** on the server. Only a small, encrypted **Session ID** is stored in the browser cookie. This method is generally **more secure** but is more complex to implement and manage, as it requires database resources and maintenance.

Implementation Steps

  1. Create Session Table: Set up a database table (e.g., sessions) to store data like id (Session ID), userId, and expiresAt.
  2. Database Logic: Implement functions for inserting, updating, and deleting sessions in the database.
  3. Sync Cookie and DB: The session ID must be created in the database, encrypted, and then stored in the user's browser cookie to keep the two synchronized.

Example: Creating a Database Session

The function creates a record in the database, takes the returned sessionId, encrypts it, and then sets it in the cookie.

export async function createSession(id: number) {
    const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
    
    // 1. Create a session record in the database
    const data = await db
    .insert(sessions)
    .values({
        userId: id,
        expiresAt,
    })
    .returning({ id: sessions.id }) // Returns the new session ID
    
    const sessionId = data[0].id
    
    // 2. Encrypt the database session ID for the cookie
    const session = await encrypt({ sessionId, expiresAt })
    
    // 3. Store the encrypted session ID in a secure cookie
    const cookieStore = await cookies()
    cookieStore.set('session', session, {
    httpOnly: true,
    secure: true,
    expires: expiresAt,
    sameSite: 'lax',
    path: '/',
    })
}
