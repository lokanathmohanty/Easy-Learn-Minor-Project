JavaScript - Immutability

Concept of Immutability

Immutable means something that cannot be changed. In programming, an immutable value is one that cannot be modified once set. Instead of changing the original value, we create a new one.

JavaScript has two categories of types:

  • Primitive types: numbers, strings, booleans, null, undefined (immutable).
  • Reference types: objects, arrays, functions (mutable).

For example, strings are immutable. If you assign a string to a new variable and later change the original, the new variable will not be affected.

Why Use Immutability?

  • Predictability: Data that does not change is easier to understand.
  • Prevent bugs: Avoids unexpected mutations that can cause errors.
  • Simple to share: Immutable data can be distributed safely across your application.

Examples of Immutability

Example 1: Strings are Immutable

// Create a string here
let greeting = "Hello, world!";

// This will not change the original string.
greeting[0] = "h"; 

console.log(greeting);

Output:

Hello, world!

Strings cannot be edited in place. Attempting to change a character creates no effect.

Example 2: Arrays with Spread Operator

// Create an array
let numbers = [1, 2, 3];

// Create a new array with an extra number.
let newNumbers = [...numbers, 4]; 

console.log(numbers);
console.log(newNumbers);

Output:

[1, 2, 3]
[1, 2, 3, 4]

Instead of changing the original array, a new one is created using the spread operator.

Example 3: Objects with Spread Operator

let person = { name: "Amit", age: 25 };

// Create a new object with an updated age.
let updatedPerson = { ...person, age: 26 };

console.log(person);
console.log(updatedPerson);

Output:

{ name: "Amit", age: 25 }
{ name: "Amit", age: 26 }

Objects are mutable by default, but immutability can be achieved by creating a new object with the spread operator.

Importance of Immutability

Immutability plays a critical role in writing reliable, maintainable, and predictable code:

  • Consistency: Values remain constant, making state management easier.
  • Readability: Code is easier to understand and debug when values do not mutate unexpectedly.
  • Functional Programming: Encourages fewer side effects and more predictable code, aligning with frameworks like Redux.

Summary

Immutability ensures that once a value is set, it cannot be altered. Instead, new values are created, which improves predictability, prevents bugs, and aligns with best practices in state management and functional programming.
