PHP - Exception Handling with $\text{try, catch, throw, and finally}$

Distinction between Errors and Exceptions

In PHP, an **Error** is typically an unexpected, unrecoverable problem that often requires script termination (handled by $\text{die()}$ or a custom error handler). An **Exception**, however, refers to an unexpected but **recoverable** situation. Exceptions are designed to be caught and managed, allowing the program to continue execution after the issue is addressed.

PHP uses the keywords $\text{try}$, $\text{catch}$, $\text{throw}$, and $\text{finally}$ to implement a structured exception model.

The $\text{try-catch-throw-finally}$ Structure

Keyword Role
$\text{try}$ Encloses the block of code that might **throw an exception**. If an exception occurs, execution immediately halts and jumps to the matching $\text{catch}$ block.
$\text{throw}$ The command used to **trigger an exception**. It creates and throws an object of the $\text{Exception}$ class (or a class that extends it).
$\text{catch}$ Follows the $\text{try}$ block and retrieves the thrown exception object, allowing the script to handle the error gracefully and continue.
$\text{finally}$ An optional block whose code **always executes**, regardless of whether an exception was thrown or caught, and even if a $\text{return}$ statement is present in $\text{try}$ or $\text{catch}$.

Simple Example: Division by Zero

The $\text{try}$ block checks for a zero denominator. If found, it uses $\text{throw new Exception()}$ to trigger the exception, which is then caught by the $\text{catch (Exception \$e)}$ block.

<?php
   $x = 10;
   $y = 0; 
   try {
      if ($y == 0) {
         throw new Exception("Division by Zero");
      }
      $z = $x/$y;
      echo "Division: $z";
   }
   catch (Exception $e) {
      echo "Exception: " . $e->getMessage(); // Output: Exception: Division by Zero
   }
?>

The $\text{Exception}$ Class and Multiple Catch Blocks

The $\text{Exception}$ Class

The base class for all user exceptions. Key methods for diagnosing the exception include:

  • $\text{getMessage()}$: Returns the error message string.
  • $\text{getCode()}$: Returns the exception code (an integer).
  • $\text{getFile()}$: Returns the filename where the exception was thrown.
  • $\text{getLine()}$: Returns the line number where the exception was thrown.

Handling Different Exceptions

You can use **multiple $\text{catch}$ blocks** to handle specific exception types (like built-in $\text{Error}$ subclasses or custom $\text{Exception}$ subclasses). PHP matches the thrown exception type with the closest matching $\text{catch}$ type in order.

try {
   // Code that might throw TypeError or DivisionByZeroError
}
catch (DivisionByZeroError $y) {
   echo "Caught a specific division error.";
}
catch (TypeError $x) {
   echo "Caught a specific type error.";
}
catch (Exception $ex) {
   echo "Caught a general exception.";
}

The $\text{finally}$ Block Behavior

The $\text{finally}$ block is used for cleanup operations (like closing file handles or database connections) because it is guaranteed to execute, regardless of the $\text{try}$ or $\text{catch}$ block's outcome.

$\text{finally}$ with $\text{return}$

Crucially, if a $\text{return}$ statement is encountered within the $\text{try}$ or $\text{catch}$ blocks, the statements within the $\text{finally}$ block are executed **before** the program control returns to the calling function.

function example() {
   try {
      return "Result"; // Return statement hit
   } finally {
      echo "Finally runs first! "; // Executes before the return
   }
}
echo example(); // Output: Finally runs first! Result
