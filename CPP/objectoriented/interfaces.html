Interfaces in C++ (Abstract Classes) 📜

In C++, an **interface** is implemented using an **abstract class**. An interface defines a set of behaviors or capabilities that a class must support, without specifying how those behaviors are implemented.

Defining an Abstract Class

A class is designated as **abstract** if it contains at least one **pure virtual function**.

  • A **pure virtual function** is a member function declared in the base class by placing **= 0** in its declaration. 
    virtual double getVolume() = 0;
  • **Abstract classes (ABCs)** serve only as a **base class** or **interface framework**. They **cannot be used to instantiate objects**.

Implementing the Interface

To use an abstract class, a derived class must be a **concrete class**. A **concrete class** is one that can be used to instantiate objects, and it must:

  • **Implement (override)** every single pure virtual function declared in its abstract base class.
  • Failure to override even one pure virtual function means the derived class also remains abstract, and you cannot create objects from it.

In the `Shape` example, the abstract base class defines the `getArea()` interface, but the implementation differs in the derived classes:

// Abstract Base Class
class Shape {
   public:
      virtual int getArea() = 0; // Pure Virtual Function (Interface)
      // ...
};

// Concrete Class (Must implement the interface)
class Rectangle: public Shape {
   public:
      int getArea() { // Implementation for Rectangle
         return (width * height); 
      }
};

Designing Strategy

Using abstract classes as interfaces provides a powerful design strategy:

  1. **Standardization:** An abstract base class establishes a common, standardized contract (interface) that all derived applications must adhere to (e.g., "every shape *must* have an `area()` function").
  2. **Flexibility:** External code can interact with any object that inherits from the abstract base class through a **base class pointer** without knowing the object's specific type. This is the foundation of **polymorphism** and makes the system easily extensible, as new derived classes can be added without altering the core system logic.
