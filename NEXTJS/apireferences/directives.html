Next.js Directives (Client and Server) 🧭

What are Directives?

**Directives** in Next.js (specifically for the App Router) are special string literals that you place at the very **top of a module file**. They instruct the Next.js build system on how to process, bundle, and execute the code within that file—specifically, whether it should run primarily on the server or the client.

The primary directives are **`"use client"`** and **`"use server"`**.

Client Components vs. Server Components

Next.js components are categorized into two types, determining where their code runs initially and where they are rendered:

Type Execution Location Primary Use Case
**Server Components** (Default) Executed on the **Server** (build time or request time). Data fetching (database/API), business logic, sensitive operations, reducing client bundle size.
**Client Components** Executed on the **Client** (Browser), though initial HTML may be rendered by the server. Interactivity, state management, event handlers, lifecycle effects, access to browser APIs (e.g., local storage).

The `"use client"` Directive

The `"use client"` directive marks a module and all its imported components as code that must be rendered and executed on the client side. The server still renders the initial non-interactive HTML, but the client takes over to enable full interactivity (a process called **Hydration**).

Example: Interactive Counter

// /app/counter/page.tsx
"use client" // ← Specifies client component

import { useState } from 'react'

export default function Hello() {
  const [count, setCount] = useState(0) // Requires client-side state
  
  return (
    <div>
        <button onClick={() => setCount(count + 1)}> ← Requires client-side event handling
            Click me
        </button>
    </div>
  )}

The `"use server"` Directive (Server Actions)

The `"use server"` directive marks asynchronous functions that should execute exclusively on the **server**, even when called from a Client Component. This is the foundation of **Server Actions** for secure and direct data mutation or backend logic execution.

Example: Server-Only Data Fetching/Mutation

// /app/api/action.ts
'use server' // ← Specifies server-only function

export async function fetchData() {
    // This code runs on the server, allowing direct use of server resources (e.g., database)
    let data = await fetch('https://jsonplaceholder.typicode.com/users', {
      cache: 'force-cache'
    }).then(res => res.json())
    return data
}
