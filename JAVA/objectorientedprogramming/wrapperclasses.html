Session: Wrapper Classes

Why Wrapper Classes Are Required 🤔

While **primitive data types** (`int`, `char`, `double`, etc.) are efficient for simple value storage, Java development often requires handling values as **objects**. Objects are needed for:

  • Working with **Java Collections** (like `ArrayList` or `HashMap`), which can only store objects.
  • Using utility methods (e.g., converting a number to a `String`).
  • Passing values over a network (e.g., in serialization).

**Wrapper Classes** solve this by providing a class counterpart for every primitive type.

Java Wrapper Classes Defined

A wrapper class is one whose objects **wrap** or contain a primitive data type within them. They are all found in the **java.lang** package (except for Void, and all the numeric wrappers are subclasses of the abstract class **Number**).

Primitive Type Wrapper Class Subclass of Number
booleanBooleanNo
charCharacterNo
byteByteYes
shortShortYes
intIntegerYes
longLongYes
floatFloatYes
doubleDoubleYes

Boxing and Unboxing

Java provides automatic conversion between primitives and their corresponding wrapper objects, a feature known as **Autoboxing** and **Unboxing**.

  • **Boxing (Autoboxing):** Converting a primitive value into a Wrapper object. (e.g., `int` to `Integer`).
  • **Unboxing:** Converting a Wrapper object back into its primitive type. (e.g., `Integer` to `int`).
public class Test {
   public static void main(String args[]) {
      Integer x = 5;      // Autoboxing: int 5 is wrapped into an Integer object
      x = x + 10;         // Unboxing: x is converted to int (5), added to 10 (result 15)
                          // Autoboxing: 15 is re-wrapped into the Integer object x
      System.out.println(x); 
   }
}

Output: 15

This automatic feature simplifies code by allowing developers to treat the wrapper objects almost as if they were primitives in expressions, while still gaining the benefits of objects.
