JavaScript - Call Stack

The JavaScript engine uses the call stack to manage the execution context. It is a key mechanism by which JavaScript keeps track of function calls in a program. Although the call stack works internally, understanding it is important for grasping how JavaScript executes functions.

The call stack follows the LIFO (Last In, First Out) principle. The last function added to the stack executes first, and once completed, it is removed from the stack.

How JavaScript Call Stack Works?

When JavaScript code is executed:

  • The global execution context is added to the stack.
  • When a function is called, it is pushed onto the call stack.
  • If a nested function is invoked, it is added on top of the stack.
  • Once a function finishes execution, it is popped from the stack, and execution continues with the next item.
  • When the call stack is empty, the script finishes running.

Example 1: Basic Function Calls

function two() {
  console.log("this is function two");
}

function one() {
  two();
  console.log("This is function one");
}

one();

The execution order would be:

  1. The stack is empty initially.
  2. one() is pushed onto the stack → [one()].
  3. one() calls two() → [two(), one()].
  4. two() executes and is popped → [one()].
  5. one() finishes execution and is popped → [].

Example 2: Demonstration with Output

<html>
<body>

JavaScript Call Stack Overflow

When the size of the call stack exceeds its defined limit, a stack overflow occurs. This typically happens with recursive functions that do not have a proper base case.

Example: Infinite Recursion

function fib() {
   fib();  // no exit condition
}
fib();

The above code will cause a RangeError: Maximum call stack size exceeded error.

Key Point

JavaScript is a single-threaded language. It has only one call stack and executes code line by line from top to bottom. This means it can process only one function at a time.
