.NET Core - MSBuild and Project File Differences

**MSBuild** is the official build platform for Microsoft and Visual Studio. While early **.NET Core** projects used the simpler **project.json** build system, the more complex needs of applications like **Universal Windows Platform (UWP)** required them to retain the traditional **.csproj** (MSBuild) build system.

This chapter illustrates the difference in file inclusion methods between the new (project.json) and old (.csproj/MSBuild) project systems.

Project File Comparison

The type of project file present dictates the build system used:

  • **UWP Applications**: Use **.csproj** (MSBuild) and also include **project.json**. The **MSBuild** system is necessary because the project.json build system was not initially sufficient for UWP's requirements.
  • **.NET Core Console Apps (Older)**: Used **project.json** and **.xproj**.

File Inclusion in MSBuild Projects (UWP)

Unlike the **.NET Core Console App**, where dropping files into the root folder automatically included them, the **UWP (.csproj/MSBuild)** project requires explicit inclusion.

If you copy existing source files (e.g., Student.cs and Course.cs) into the project folder, the following manual steps are needed in Visual Studio:

  1. **View Hidden Files**: Open the Solution Explorer and click the **Show All Files** icon. This reveals all files present in the physical project folder, including those not yet part of the project.
  2. **Include in Project**: Select the new files (they will typically appear with a dashed icon). Right-click the selected files and choose **Include in Project**.

This difference highlights the greater control but reduced automation of the MSBuild-based system. It is anticipated that future SDK tools and Visual Studio versions may adopt the simpler, automatic file inclusion approach for .csproj files as well.
