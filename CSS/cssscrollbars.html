What Are Scrollbars?

A scrollbar appears when the content inside a container exceeds the available space. It can be vertical, horizontal, or both. A typical scrollbar includes a track, a draggable thumb, optional buttons, and a corner where horizontal and vertical bars meet.

  • Vertical scrollbar allows up and down navigation.
  • Horizontal scrollbar allows left and right navigation.
  • The thumb indicates the current viewport position and relative size of visible content.

When and Why to Customize Scrollbars

  • Brand alignment and visual polish in desktop web apps.
  • Improved discoverability of overflow areas.
  • Better contrast for users with low vision.
  • Touchpad and keyboard users still benefit from visible, high-contrast thumbs.

Customization should never reduce usability. Default system scrollbars are familiar and accessible; any styling must respect contrast, size, and platform expectations.

How to Style Scrollbars

Basic steps for creating a scrollable area before styling the scrollbar:

  • Create a container element that will hold overflowing content.
  • Constrain the container with a fixed height or width as needed.
  • Enable scrolling with overflow properties.

Example container setup (text-only):

div { width: 370px; height: 120px; overflow: auto; }

Once scrolling is enabled, you can target the scrollbar using browser-specific selectors or standardized properties where supported.

Scrollbar Selectors for WebKit Browsers

Chrome, Safari, and modern Edge support a set of non-standard pseudo-elements. These allow detailed visual control.

  • ::-webkit-scrollbar — selects the entire scrollbar.
  • ::-webkit-scrollbar-button — selects the increment and decrement buttons.
  • ::-webkit-scrollbar-thumb — selects the draggable thumb.
  • ::-webkit-scrollbar-track — selects the track background.
  • ::-webkit-scrollbar-track-piece — selects an intermediate part of the track.
  • ::-webkit-scrollbar-corner — selects the corner where bars meet.
  • ::-webkit-resizer — selects the draggable resizer at the corner.

Standard Scrollbar Properties

Many browsers also support a standardized approach for basic styling:

  • scrollbar-width — controls thickness of scrollbars in compatible browsers. Values include auto, thin, and none.
  • scrollbar-color — sets thumb and track colors in compatible browsers. Format is thumb track.

These properties are useful for cross-browser coverage, especially in Firefox, and provide a simpler alternative to vendor-specific selectors.

Cross-Browser Strategy

  • Use standardized properties (scrollbar-width, scrollbar-color) for broad coverage.
  • Enhance with WebKit pseudo-elements for fine-grained control in Chrome, Safari, and Edge.
  • Always keep adequate color contrast and comfortable thumb size.
  • Provide sensible fallbacks so unstyled browsers still show usable system scrollbars.

Text-Only Examples

The following examples present CSS as plain text for clarity within this e-learning format. You can copy these declarations into your stylesheet.

Example A — Enable Scrolling

div.example { width: 370px; height: 120px; overflow: auto; }

This establishes a scrollable container. Without overflow set to auto, the browser may not display a scrollbar even if content is long.

Example B — Basic WebKit Thumb and Track

div.example::-webkit-scrollbar { width: 15px; }

div.example::-webkit-scrollbar-track { background: lightgray; }

div.example::-webkit-scrollbar-thumb { background: dimgray; border-radius: 8px; }

div.example::-webkit-scrollbar-thumb:hover { background: gray; }

This adjusts width, track, and thumb appearance for WebKit browsers only.

Example C — Standard Properties for Firefox and Others

div.example { scrollbar-width: thin; scrollbar-color: #666 #e6e6e6; }

This sets a thin scrollbar with a darker thumb and lighter track in compatible browsers.

Example D — Combining Standard and WebKit Approaches

div.example { overflow: auto; scrollbar-width: thin; scrollbar-color: #666 #f2f2f2; }

div.example::-webkit-scrollbar { width: 14px; height: 14px; }

div.example::-webkit-scrollbar-track { background: #f2f2f2; }

div.example::-webkit-scrollbar-thumb { background: #666; border-radius: 10px; border: 3px solid #f2f2f2; }

This hybrid pattern offers broad support and refined styling in WebKit browsers.

Example E — Hiding Scrollbars While Keeping Scroll

div.scrolling { overflow: auto; scrollbar-width: none; }

div.scrolling::-webkit-scrollbar { display: none; }

Use sparingly. Hiding scrollbars can harm discoverability and accessibility. Ensure keyboard and touch scrolling remain obvious.

Accessibility and Usability

  • Contrast: ensure the thumb stands out from the track. Higher contrast improves visibility.
  • Size: thin scrollbars can be hard to grab with a mouse. Avoid extremely small thumbs.
  • Hit targets: generous thumb radius and borders can improve usability.
  • Focus: do not remove keyboard focus indicators on scrollable regions.
  • Motion: avoid animated scrollbars that may distract or trigger motion sensitivity.
  • System preferences: users may expect platform-native look. Do not override without purpose.

Testing Checklist

  • Browsers: test Chrome, Safari, Edge, and Firefox on desktop.
  • Devices: test with mouse, trackpad, and touch where applicable.
  • Input: verify keyboard scrolling with arrow keys, Page Up or Page Down, Home and End.
  • Overflow cases: extremely long content, nested scroll areas, and both axes.
  • High contrast modes and forced colors where available.
  • Zoom and responsive layouts at various viewport sizes.

Troubleshooting and Pitfalls

  • No scrollbar appears: check container sizing and overflow settings; confirm content actually overflows.
  • Styles not applied: remember WebKit pseudo-elements only affect certain browsers; use standard properties for others.
  • Thumb too small to grab: increase scrollbar width or reduce border thickness.
  • Hidden scrollbars confuse users: avoid unless the pattern is well signposted.
  • Nesting: inner scroll areas may trap scroll; consider overscroll-behavior and layout choices.

Practice Exercises

  • Create a vertical article list with a fixed height and a custom thumb using WebKit selectors. Add a hover state.
  • Style the same list using scrollbar-width and scrollbar-color only. Compare results in Firefox and Chrome.
  • Build a horizontal gallery that overflows on the x axis and style its horizontal scrollbar for WebKit.
  • Audit your design for contrast ratios between thumb and track at 200 percent zoom.

Quick Reference

  • Enable scrolling: overflow: auto on a sized container.
  • Standard properties: scrollbar-width and scrollbar-color.
  • WebKit detail: ::-webkit-scrollbar, ::-webkit-scrollbar-thumb, ::-webkit-scrollbar-track, and others.
  • Do not rely on a single method; combine standard and vendor approaches.
  • Test across browsers and inputs before shipping.

Summary

Custom scrollbars can enhance clarity and branding when implemented carefully. Use standard properties for broad coverage and WebKit pseudo-elements for finer control, always prioritizing accessibility, performance, and predictable behavior across devices and input methods.
