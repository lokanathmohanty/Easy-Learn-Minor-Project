.NET Core - MSBuild and project.json Transition

The .NET Core ecosystem underwent a significant tooling change by deciding to **drop project.json** in favor of returning to **MSBuild** and the ***.csproj** project file format. This change was finalized in the **.NET Core 2.0 preview1 tooling**.

Advantages of the MSBuild/csproj Change

While project.json was considered a "breath of fresh air," the decision to revert to MSBuild offers several strategic advantages:

  • **Simplified Transition:** Makes the move of existing Visual Studio solutions to .NET Core more **straightforward**.
  • **Leveraging Existing Investment:** Allows companies to utilize existing infrastructure and expertise in Continuous Integration (CI) and Release Management (RM) systems that are built around **MSBuild**.
  • **Advanced Build Features:** Enables core MSBuild features like **incremental compilation**, resolving build-time dependencies, and robust configuration management.
  • **Broader Platform Support:** Supports a wider range of application types (console apps, UWP apps, etc.), requiring a stable and proven build system like MSBuild for the .NET CLI.

Key Changes in Tooling

The core structural changes in the project system are as follows:

  • The **project.json file (and the *.xproj file)** is replaced by **MSBuild's *.csproj** file.
  • Features previously found in project.json will be gradually merged back into the new ***.csproj** format.

The transition for packages lists (dependencies) was an open question, with possibilities of keeping it in a separate **nuget.json** file or merging it completely into the ***.csproj** file.

Advantages of the New MSBuild

  • **Open Source and Cross-Platform:** MSBuild itself is open source, available on GitHub, and is becoming fully cross-platform.
  • **Simplified Structure:** The new *.csproj structure will be dramatically **simplified and trimmed** compared to the verbose, older .NET Framework versions.
  • **New Project System:** Microsoft introduced a new project system (details available at https://github.com/dotnet/project-system) aimed at making project work seamless, both inside the Visual Studio IDE and outside of it.

Comparing project.json vs. MSBuild/csproj

The shift in tooling is clearly visible when creating new projects using the command line:

Using .NET Core preview2 tooling (Old)

Running dotnet new -t console and then dir creates two files:

  • Program.cs
  • project.json

Using .NET Core 2 preview1 tooling (New)

Running dotnet new console and then dir creates three files:

  • Program.cs
  • NuGet.config
  • **MSBuild.csproj** (replaces project.json)

File Format Comparison

A side-by-side comparison shows the difference between the old and new project files:

  • **project.json:** Uses the **JSON** format. Specifies the target framework as **netcoreapp1.0**.
  • **MSBuild.csproj:** Uses the **XML** format. Specifies the target framework as **netcoreapp2.0** (demonstrating the tooling update).
