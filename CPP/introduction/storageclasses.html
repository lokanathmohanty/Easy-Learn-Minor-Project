Storage Classes in C++ 💾

A **storage class** defines the **scope (visibility)** and **life-time** of variables and functions within a C++ program. These specifiers precede the data type they modify.

1. The auto Storage Class

The auto specifier is the **default storage class for all local variables** (variables declared inside a function or block).

  • Scope: Local (visible only within the function/block).
  • Life-time: Exists only while the program control is inside that function/block.
  • Note (C++11 and later): The primary modern use of auto is for **type deduction** (letting the compiler automatically deduce the variable's type from its initializer), which superseded its original role as a storage specifier.

2. The register Storage Class

The register storage class is a **suggestion to the compiler** to store the local variable in a CPU register instead of standard memory (RAM) for faster access. This is ideal for frequently accessed variables like counters.

  • Constraint: Since it might not have a memory address, the unary address operator (&) cannot be applied to a register variable.
  • Reality: The compiler decides whether to honor the request based on hardware and implementation constraints.

3. The static Storage Class

The static specifier changes the behavior of variables and functions in two primary ways, depending on its location:

For Local Variables (Inside a function):

  • Life-time: The variable is created only once and remains in existence for the **entire life-time of the program**. It retains its value between function calls.
  • Scope: Remains local (visible only within the function).

For Global Variables and Functions (Outside all functions, in a file):

  • Scope: The variable or function's visibility is restricted to the **file in which it is declared** (internal linkage). It cannot be accessed by other files using extern.

For Class Members: It ensures that only one copy of the member is shared by all objects of the class.

4. The extern Storage Class

The extern storage class is used to **declare** a global variable or function that is **defined elsewhere** (often in a separate file). It provides a reference to a globally visible storage location.

  • Purpose: To declare a variable or function without defining it (i.e., without allocating storage for it) in the current file. This is crucial for linking multiple source files that share global resources.
  • Constraint: An extern declaration cannot initialize the variable because it merely points to an existing definition.

5. The mutable Storage Class

The mutable specifier applies only to class data members (not functions or local variables). Its sole purpose is to allow a member variable to be modified **even if it belongs to a const object** or is being modified within a const member function.
