C# Preprocessor Directives

Introduction and Syntax

Preprocessor Directives are instructions to the compiler to preprocess information *before* the actual compilation phase begins. They primarily help in **conditional compilation** and code organization.

  • All preprocessor directives begin with the hash symbol (**#**).
  • They are **not statements**, so they do not end with a semicolon (;).
  • They must be the **only instruction** on a line.

Unlike C/C++, C# doesn't have a separate preprocessor but processes these directives internally to control which code blocks are included in the final assembly.

Conditional Compilation Directives

These directives control which sections of code are compiled based on whether a symbol is defined.

Defining and Undefining Symbols:

  • #define symbol: Creates a symbolic constant that can be tested later. It does not assign a value; it only defines existence.
  • #undef symbol: Undefines a previously defined symbol.
#define DEBUG_MODE // Symbol defined
#undef RELEASE_MODE // Symbol undefined

Conditional Logic:

Used to check if a symbol is defined. Only the code within the true block is passed to the compiler.

  • #if symbol: Tests if a symbol evaluates to true.
  • #else: Executes if the preceding #if or #elif is false.
  • #elif symbol: Checks an additional condition if the preceding #if is false (a combination of #else and #if).
  • #endif: Marks the end of a conditional directive block.
#if DEBUG && !VC_V10 // Using logical operators (&&, ||, !)
   Console.WriteLine("Debug build is active.");
#elif !DEBUG
   Console.WriteLine("Release build is active.");
#else
   Console.WriteLine("Configuration not matched.");
#endif

Diagnostic and Utility Directives

#error and #warning:

These directives are used to manually generate compiler errors or warnings, often placed inside conditional directives to flag improper configurations or incomplete code.

  • #error "Custom error message": Stops compilation and displays the message.
  • #warning "Custom warning message": Displays a warning but allows compilation to proceed.
#if BETA_VERSION
   #warning "This is a beta version. Use with caution."
#endif

#region and #endregion:

These directives are purely for **code organization** within the IDE (like Visual Studio). They allow blocks of code to be defined as collapsible regions, improving readability by letting the developer outline and collapse sections of code.

#region Public Methods
// Code for public methods
#endregion

#region Private Fields
// Code for private fields
#endregion

#line:

Used to change the compiler's line number and (optionally) the file name output for errors and warnings. This is useful for code generation tools.

  • **#line 100 "MyFile.cs"**: Sets the current line number to 100 and the filename to "MyFile.cs" for error reporting.
  • **#line default**: Reverts the line numbering and filename back to the default setting.
