PHP Cross-Site Request Forgery ($\text{CSRF}$) Protection 🛡️

**CSRF** ($\text{Cross-Site Request Forgery}$) is an exploit where an attacker tricks a trusted user's browser into executing an unwanted action on a web application where the user is currently authenticated. This often leverages $\text{GET}$ requests or automatic form submissions.

The Exploit Point (GET Requests)

Attackers often exploit $\text{GET}$ requests because they can be embedded in innocuous $\text{HTML}$ elements on other sites. For example, if a vulnerable application uses a $\text{GET}$ request for a critical action:

/delete.php?empcode=1234

An attacker can embed this request on their site using an image tag, which the user's browser automatically loads when the page is visited, executing the command:

<img src="http://example.com/delete.php?empcode=1234" width="0" height="0" />

Solution: CSRF Tokens

A **CSRF Token** is a unique, unguessable, random string generated by the server and associated with the user's session. It is embedded in forms and validated upon submission, ensuring the request originated from the intended application workflow, not from a forged external link.

Implementation Steps in PHP

1. Generate and Store the Token (Form Script)

The first script generates a token and stores it in the user's session ($\text{\$\_SESSION}$):

<?php
   session_start();
   if (!isset($_SESSION["csrf_token"])) {
      // Generate a new, secure token (using secure methods like random_bytes() is best, 
      // but md5(uniqid(rand(), true)) is shown here for illustration)
      $token = md5(uniqid(rand(), true)); 
      $_SESSION["csrf_token"] = $token;
   } else {
      $token = $_SESSION["csrf_token"];        
   }
?>
<html><body>
   <form method="get" action="test.php">
      <!-- Embed the token in a hidden field -->
      <input type="hidden" name="csrf_token" value="<?php echo $token;?>" />
      <input type="submit" />
   </form>
</body></html>

2. Validate the Token (Processing Script)

The receiving script ($\text{test.php}$) compares the token received in the $\text{GET}$ or $\text{POST}$ request with the token stored in the $\text{\$\_SESSION}$.

<?php
   session_start();
   
   // Ensure both tokens exist and match
   if (isset($_GET["csrf_token"]) && 
       $_GET["csrf_token"] === $_SESSION["csrf_token"]) {

      echo "
CSRF token validation successful. Proceed to further action
";
      
      // OPTIONAL: Regenerate the token after a successful request (Token Reset)
      // unset($_SESSION["csrf_token"]); 
      // $_SESSION["csrf_token"] = md5(uniqid(rand(), true)); 
      
   } else {
      echo "
CSRF token validation failed
";
   }
?>

If the tokens do not match (or the token is missing), the request is rejected as unauthorized.
