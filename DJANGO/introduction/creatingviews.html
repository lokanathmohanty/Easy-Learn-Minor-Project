Django: Creating View Functions 💻

A **view function**, or simply a **view**, is a **Python function** that serves as the **Controller logic** in Django's MVT pattern. It takes an incoming web request (HttpRequest) and is responsible for returning an appropriate web response (HttpResponse).

The response can be simple HTML content, a redirect, an HTTP error (like 404), or raw data (like XML or JSON).

Simple View (Direct HTML)

Views are created in the application's **views.py** file. The simplest view uses **HttpResponse** to return hardcoded HTML content. While functional, this method violates the MVT principle by mixing logic and presentation:

from django.http import HttpResponse

def hello(request):
   text = "<h1>welcome to my app !</h1>"
   return HttpResponse(text)

MVT-Compliant View (Using Templates)

The best practice is to use Django's **render()** shortcut. This method correctly separates the view logic from the presentation (Template) layer by:

  1. Receiving the request object.
  2. Specifying the path to the **Template file** (e.g., myapp/templates/hello.html).
  3. Passing a dictionary of **context data** (variables) to the template (here, an empty dictionary {}).
from django.shortcuts import render

def hello(request):
   return render(request, "myapp/template/hello.html", {})

Views Accepting Parameters

View functions can also accept arguments, which are typically captured from the URL and passed to the view by Django's URL routing system:

from django.http import HttpResponse

def hello(request, number):
   text = "<h1>welcome to my app number %s!</h1>" % number
   return HttpResponse(text)

When this view is mapped to a URL that includes a placeholder for a number (e.g., /hello/123/), the view function will receive and display that number.
