Java - Exceptions

An exception in Java is a problem or unexpected event that occurs during program execution. If not handled, an exception will disrupt the normal flow of the program and may cause it to terminate abnormally. Java provides robust mechanisms for handling these exceptions to help create reliable applications.

Why Exceptions Occur?

  • User provides invalid input data.
  • A required file is missing or cannot be opened.
  • Network issues such as lost connections or unavailable resources.
  • Programmer errors like accessing array elements out of range.

Exceptions may arise from user mistakes, programming errors, or unexpected failures in the environment (like disk or memory errors).

Java Exception Categories

  • Checked Exceptions: Checked at compile time, must be handled or declared in method signatures. Example: FileNotFoundException
  • Unchecked Exceptions: Occur at runtime (subclasses of RuntimeException), usually caused by programming bugs. Example: ArrayIndexOutOfBoundsException
  • Errors: Severe problems beyond control of the program, like OutOfMemoryError. These are not intended to be handled by applications.

Java Exception Hierarchy

All exceptions derive from java.lang.Throwable, with two direct subclasses: Exception (for normal exceptions) and Error (for serious failures). The Exception class branches into checked and unchecked exceptions.

  • Checked: IOException, SQLException, etc.
  • Unchecked: NullPointerException, ArithmeticException, etc.

Handling Exceptions: try-catch

Java uses try and catch blocks to handle exceptions. Code that may cause exceptions is placed within a try block. Exceptions thrown are caught by matching catch blocks that follow.

try {
   // Code that may throw exceptions
} catch (ExceptionType name) {
   // Handling code
}

Multiple catch blocks can handle different types of exceptions.

throws and throw Keywords

  • throws declares that a method may throw one or more exceptions, passing responsibility to the caller.
  • throw explicitly throws an exception in code (e.g., throw new IOException();).

Example:

public void deposit(double amount) throws IOException {
   if (amount < 0) throw new IOException("Invalid deposit");
}

finally Block & try-with-resources

  • finally always executes after try/catch, allowing for resource cleanup.
  • try-with-resources (Java 7+) closes resources automatically after use:
try(FileReader fr = new FileReader("file.txt")) {
   // Use the resource
} catch (IOException e) {
   e.printStackTrace();
}

User-defined Exceptions

You can define custom exceptions by extending Exception (checked) or RuntimeException (unchecked). This is useful for application-specific error handling.

class MyException extends Exception { }
