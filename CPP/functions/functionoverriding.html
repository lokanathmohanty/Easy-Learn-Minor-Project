C++ Function Overriding (Runtime Polymorphism) ⚙️

Function Overriding is a core concept in **Object-Oriented Programming (OOP)** that allows a **derived class** to provide a specific implementation for a function that is already defined in its **base class**.

For overriding to occur, the function in the derived class must have the **exact same name, return type, and parameter list** as the function in the base class. The function in the base class must also be declared with the **virtual** keyword to enable runtime polymorphism.

How Overriding Works (Dynamic Binding)

Overriding facilitates **runtime polymorphism** (dynamic binding). When a function is overridden, and you call that function using a **base class pointer** or **reference** that actually points to a derived class object, the system determines which version of the function to execute at runtime based on the **actual object type**, not the pointer type.

Key Requirements for Overriding:

  1. **Inheritance:** Must occur in a derived class.
  2. **Signature Match:** The function signature (name, parameters, return type) must be identical in both the base and derived classes.
  3. **Base Class virtual:** The function in the base class **must** be declared with the virtual keyword.
  4. **Derived Class override:** (C++11 standard practice) Use the override specifier in the derived class definition to ensure the signature is correct and intent is clear.

Example (Polymorphic Call)

// Base class with virtual function
class Shape { 
public: 
    virtual void draw() const { ... }
}; 

// Derived class overriding the function
class Circle : public Shape { 
public: 
    void draw() const override { 
        cout << "Drawing a circle" << endl; 
    }
}; 

// Runtime Call: The *actual* object type (Circle) determines the output.
Shape* shapePtr = new Circle();
shapePtr->draw(); // Executes Circle::draw()

Overriding vs. Overloading

These two concepts are distinct forms of polymorphism:

FeatureFunction OverridingFunction Overloading
Scope Different scopes (Base class and Derived class) Same scope (Single class or namespace)
Signatures Must have the **same** signature (name, parameters, return type) Must have **different** signatures (different parameters)
Binding Runtime Polymorphism (Dynamic Binding) Compile-Time Polymorphism (Static Binding)
Inheritance **Required** Not required

Advanced Overriding Concepts

Virtual Destructors

If you intend to delete a derived class object through a base class pointer (e.g., `delete shapePtr;`), the base class destructor **must** be declared `virtual`. This ensures that the **derived class destructor** is called first, preventing memory leaks by properly releasing resources allocated by the derived class.

The final Keyword

The final keyword (C++11) can be applied to a virtual function in a derived class to prevent it from being overridden in any further derived classes. It guarantees that a specific implementation is the final one in the hierarchy.
