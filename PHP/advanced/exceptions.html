PHP Exceptions and the $\text{Throwable}$ Interface

In PHP (especially since version 7), the traditional error reporting mechanism has largely been replaced by throwing **Error Exceptions**. This allows developers to use the structured exception handling keywords ($\text{try}$, $\text{catch}$, $\text{throw}$, and $\text{finally}$) for managing runtime errors as well as user-defined exceptions.

The $\text{Throwable}$ Interface (PHP 7+)

The $\text{Throwable}$ interface is the **base type** for any object that can be thrown using the $\text{throw}$ statement. All PHP errors and exceptions are instances of classes that implement $\text{Throwable}$.

  • The hierarchy includes two main branches: **$\text{Error}$** (for internal PHP errors) and **$\text{Exception}$** (for code exceptions).
  • A user-defined exception class **cannot** implement $\text{Throwable}$ directly; it must **extend the $\text{Exception}$ class**.

Uncaught Exceptions and $\text{set\_exception\_handler()}$

When an exception is thrown:

  1. PHP looks for a matching $\text{catch}$ block in the current $\text{try}$ scope.
  2. If no match is found, the exception "bubbles up" the call stack (unwinding previous function calls).
  3. If the exception reaches the global scope without being caught, the script terminates with a fatal error, **unless** a default exception handler is set.

The $\text{set\_exception\_handler()}$ Function

This function registers a default handler to catch any **uncaught exception** that reaches the global scope. Once the handler function is executed, the program execution will stop.

set_exception_handler(?callable $callback): ?callable

The handler function must accept one parameter: the thrown $\text{Exception}$ object.

function handler($ex) {
   echo "Uncaught exception is: " , $ex->getMessage();
}
set_exception_handler('handler');
throw new Exception('Not Found Exception');
// Output: Uncaught exception is: Not Found Exception

Standard PHP Library (SPL) Exceptions

The SPL provides a set of predefined, specialized $\text{Exception}$ classes, which help categorize specific error types. Using these specific classes is better practice than just throwing the base $\text{Exception}$ class.

Exception Class Purpose
$\text{LogicException}$ Represents errors in the program **logic** (should be prevented by the developer).
$\text{InvalidArgumentException}$ Thrown if an argument is not of the **expected type or value**.
$\text{BadFunctionCallException}$ Thrown if a callback refers to an **undefined function** or method ($\text{BadMethodCallException}$).
$\text{RuntimeException}$ Thrown if an error occurs that can **only be found at runtime** (e.g., file access issues).
$\text{OutOfBoundsException}$ Thrown when an **illegal index** or key is requested (e.g., accessing an array index that doesn't exist).

User-Defined Exceptions

You can create custom exception classes by **extending the base $\text{Exception}$ class**. This allows you to define specific exception types for your application logic and add custom helper methods (like the $\text{message()}$ method below).

class myException extends Exception {
   // Custom method to format the error output
   function message() {
      return "Error: ". $this->getMessage(). " in line no ". $this->getLine();
   }
}

$num=125;
try {
   if ($num>100 || $num<0)
   throw new myException("$num is invalid number");
}
catch (myException $m) {
   echo $m->message(); // Calls the custom message method
}
