Java PriorityQueue Class Summary 🥇

The **java.util.PriorityQueue** class implements the **Queue** interface and provides an **unbounded priority queue** based on a **priority heap** (specifically, a min-heap by default). It ensures that the element at the head of the queue is the one with the highest priority according to the defined ordering.

I. Ordering and Priority

Elements in a PriorityQueue are not ordered based on insertion time (like a standard FIFO queue) but based on their priority, determined by one of two mechanisms:

  • **Natural Ordering (Default):** The elements must implement the **Comparable** interface. By default, it uses a **min-heap**, meaning the smallest element (lowest value) is considered the highest priority and is at the head.
  • **Custom Ordering:** An external **Comparator** can be provided during construction to define a custom priority scheme, which can establish a max-heap or any other ordering.

Note: The iteration order (when using an iterator or `forEach`) is **not guaranteed** to be the priority order; it simply traverses the heap structure. Only the retrieval operations (`poll()`, `peek()`) access the highest-priority element.

II. Restrictions and Null Policy

  • **No Null Elements:** A `PriorityQueue` **does not permit `null` elements**.
  • **Comparable Elements:** If relying on natural ordering, all inserted elements must be mutually comparable.
  • **Unbounded:** The queue can grow dynamically; its initial capacity (default 11) is just a starting point.

III. Essential Queue Operations

While PriorityQueue inherits many Collection methods, the critical methods for queue management are:

Method Action Time Complexity (Typical)
boolean offer(E e) / boolean add(E e) Inserts the element into the queue and maintains the heap property. $O(\log n)$
E peek() Retrieves (but **does not remove**) the element at the head (highest priority). $O(1)$
E poll() Retrieves and **removes** the element at the head. $O(\log n)$
E remove(Object o) Removes a single instance of a specified element. This is generally inefficient. $O(n)$

Example: Priority Ordering vs. Iteration Order

In the example, the `Integer` elements are added (e.g., 20, 30, 15, 22, 11). Since `Integer` uses natural ordering (min-heap), the highest priority element is the smallest number (11).

When iterating with `for (Integer number : queue)`, the output order is **not sorted** (e.g., 11, 20, 15, 30, 30, 22, 20), because the iterator traverses the underlying heap structure, which only guarantees the root (11) is smallest, not that all nodes are in total order.

To retrieve elements in priority order, you must use a loop with **poll()**:

while (!queue.isEmpty()) {
    System.out.print(queue.poll() + " ");
} 
// Output: 11 15 20 20 22 30 30
