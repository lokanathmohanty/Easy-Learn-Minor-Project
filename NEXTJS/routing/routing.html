Next.js Routing: App Router vs. Page Router 🧭

What is Routing in Next.js?

**Routing** is the mechanism that determines how an application navigates between different URLs. Next.js includes a **built-in, file-system based router**, meaning you don't need external routing libraries. The structure of your files and folders inside a specific root directory defines the application's URL paths.

  • **Folders:** Define a route segment (a path).
  • **Files (e.g., `page.js`):** Define the UI component rendered for that specific route.

Types of Routing Systems in Next.js

When creating a project, you choose one of two routing systems:

1. App Router (Current Standard, from v13+)

This is the **new, recommended** routing system, built on **React Server Components**. It uses the **`/app`** directory.

  • **Basic Route:** `app/about/page.tsx` maps to `/about`.
  • **Shared Layouts:** Uses special files like `layout.js` (or `layout.tsx`) to define persistent UI across routes.
  • **Nested Routing:** Achieved naturally by creating nested folders (e.g., `app/dashboard/[id]/page.js`).
  • **Special Files:** Supports dedicated files for loading states (`loading.js`) and error handling (`error.js`).

2. Page Router (Legacy)

This is the older system used in Next.js versions before 13. It uses the **`/pages`** directory.

  • **Basic Route:** `pages/about.js` (or `pages/about/index.js`) maps to `/about`.
  • **File-to-Route Mapping:** Any file inside the `/pages` directory automatically becomes a route.
  • **API Routes:** Defined strictly within the **`pages/api`** directory.
  • **Dynamic Routes:** Uses square brackets in filenames, e.g., `pages/product/[id].js`.
