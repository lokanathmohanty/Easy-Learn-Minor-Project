Next.js Incremental Static Regeneration (ISR) ♻️

What is ISR?

**Incremental Static Regeneration (ISR)** is a Next.js feature that allows you to **update static pages after deployment** without needing a full site rebuild. It bridges the gap between the high performance of **Static Site Generation (SSG)** and the up-to-date content of **Server-Side Rendering (SSR)**.

Pages are initially generated at build time, but they can be *incrementally* updated while the application is running, ensuring content remains fresh without sacrificing speed.

How ISR Works (Stale-While-Revalidate)

  1. **Build Time:** The page is pre-rendered into static HTML (like SSG).
  2. **User Request (Before Expiration):** If the page's cache time has not expired, the **cached static version** is served instantly.
  3. **User Request (After Expiration):**
    • The user is immediately served the **stale (old) static version**.
    • Next.js triggers a **revalidation process in the background** to generate a new version of the page.
  4. **Subsequent Requests:** Once the new version is ready, subsequent users will receive the **newly generated, fresh static version**.

Implementing ISR

ISR is configured in two primary ways: **Time-based** and **On-demand**.

1. Time-based Revalidation ⏰

This method automatically checks for updates after a defined time interval. This is primarily done using the **`revalidate`** option:

  • **Page Router:** Set the `revalidate` property in the return object of **`getStaticProps`**.
  • **App Router:** Export a **`revalidate`** constant from a component file.
// App Router Example: Revalidate every 5 seconds
export const revalidate = 5

async function getData() {
  // ... fetch data ...
}
// This page will update its timestamp/data at most every 5 seconds
export default async function Page() { /* ... */ }

2. On-demand Revalidation (Event-based) ✨

This technique allows you to update the page cache manually based on an event (e.g., content changes in a CMS, a button click, or a webhook call) rather than waiting for a timeout.

  • **Mechanism:** Uses the **`revalidatePath`** function (or `revalidateTag`) inside a Server Action or an API Route.
// Example using Server Actions (App Router)
import { revalidatePath } from 'next/cache'

async function handleRevalidate() {
  'use server'
  // Clears the cache for the home page (the next request will re-generate it)
  revalidatePath('/') 
}
