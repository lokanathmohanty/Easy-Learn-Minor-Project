Next.js Folder Structure: File-Based Routing 📂

Routing System Overview 🗺️

Next.js utilizes a **file-based routing system**, meaning the organization of files inside the designated routing folders (either `/app` or `/pages`) automatically determines the application's URLs.

The provided structure focuses on the **App Router** (`/app` directory), which is the current recommended structure:

nextjs-app-router/
     app/
        counter/
           page.tsx  // → http://localhost:3000/counter
        page.tsx     // → http://localhost:3000/ (Home Page)
     public/ 
     ...

Top-Level Folders and Their Purpose

  • /app: The **root folder for the App Router** (recommended). The file `page.tsx` directly inside this folder serves as the application's home page (`/`).
  • /pages: (Optional/Legacy) The root folder for the older **Page Router**. `index.tsx` serves the home page.
  • /public: Contains **static assets** like images, fonts, and stylesheets. Files here are served directly from the root of the domain (e.g., `/image.png`).
  • /src: An **optional folder** used to separate application logic (source code) from configuration and top-level routing files, enhancing code organization.

Top-Level Configuration Files

These files are located in the root directory and configure the Next.js application environment:

  • next.config.js: The main file for configuring Next.js features, like environment variables, headers, and image optimization settings.
  • package.json: Defines project dependencies and executable scripts (`npm run dev`, `npm run build`).
  • middleware.ts: Used to define **middleware logic** that runs before a request is completed, allowing for authentication or routing redirects.
  • .env / .env.local: Used to define **environment variables** for the application (e.g., API keys). `.env.local` is for local development and is typically ignored by Git.

Special Routing Files (App Router)

These special files placed within a route folder (/app/) control the UI and behavior of that route:

  • page.tsx: **The actual UI component** rendered for a specific route segment.
  • layout.tsx: Defines the shared UI (e.g., navigation bar, header, footer) for a route and its child routes.
  • route.ts: Used to define **API endpoints** (Route Handlers) within the Next.js application.
  • loading.tsx: Renders a loading state (UI) while the content for a route segment is being fetched.
  • error.tsx: Renders an error boundary UI to gracefully handle errors within a route segment.
  • not-found.tsx: Renders a custom **404 page** when a requested route is not found.
