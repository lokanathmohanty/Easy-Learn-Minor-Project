Next.js API Middlewares (Pages Router) 🛡️

What are API Middlewares?

**API Middlewares** are **reusable functions** that execute *before* the main logic of a Next.js API Route (Pages Router). They are designed to **pre-process** the incoming request, inspect or modify data, validate input, and handle common concerns like authentication or logging, ensuring that the main API handler only receives validated and authorized requests.

Key Roles:

  • **Authentication/Authorization:** Checking for valid tokens or API keys.
  • **Input Validation:** Ensuring request bodies or query parameters meet requirements.
  • **Logging & Rate Limiting:** Recording requests or blocking excessive traffic.
  • **Centralization:** Reduces code duplication across multiple API files.
  • **Early Termination:** Can stop the request processing immediately (e.g., sending a `401 Unauthorized` response) without ever calling the main handler.

Creating an Authentication Middleware Function

An API middleware function typically takes the primary API handler function as an argument and returns a new function that executes the middleware logic before conditionally calling the original handler.

Example: API Key Checker

This middleware checks if a valid `API_KEY` is present in the request headers or query parameters. If validation fails, it terminates the request immediately with a **401 Unauthorized** status.

// File: middlewares/authMiddleware.js
export default function authMiddleware(handler) {
    // Returns the enhanced request handler function
    return (req, res) => {
      const headerApiKey = req.headers.apikey;
      const queryApiKey = req.query.apiKey;
      const validApiKey = process.env.API_KEY; // Fetched from .env

      // Check for missing or invalid key
      if ( (!headerApiKey && !queryApiKey) || 
           (headerApiKey !== validApiKey && 
            queryApiKey !== validApiKey) ) {
        
        // Terminate early if unauthorized
        return res.status(401).json({ message: 'Unauthorized' });
      }
      
      // If authorized, pass the request to the original API handler
      return handler(req, res);
    };
}

Using the Middleware in an API Route

To apply the middleware, you simply wrap the API Route's default export function with the middleware function.

// File: pages/api/hello.js
import authMiddleware from '../../middlewares/authMiddleware';

// The authMiddleware function wraps and protects the main handler
export default authMiddleware(function handler(req, res) {
    // This code only runs if the authMiddleware successfully passes the request
    res.status(200).json({ message: 'Hello, Next.js API!' });
});

When a client calls `/api/hello`:

  1. The **`authMiddleware`** runs first.
  2. If the API key is missing or invalid, it returns a 401 response.
  3. If the API key is valid, the original **`handler`** function is called, returning the "Hello" message.
