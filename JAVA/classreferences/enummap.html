Java EnumMap Class Summary 🔢🗝️

The **java.util.EnumMap** class is a highly specialized and efficient **Map** implementation designed exclusively for use with keys of a single **enum type**. Its internal structure, which leverages the fixed and sequential nature of enum constants, allows it to achieve performance superior to a general-purpose HashMap.

I. Key Characteristics and Performance

EnumMap is optimized for enum keys, making it a powerful choice when applicable:

  • Enum Keys Only: All keys in an `EnumMap` **must** belong to the single enum type specified when the map is created.
  • **Predictable Iteration Order:** Entries are always maintained and iterated over in the **natural order of their keys** (the order in which the enum constants are declared in the `enum` definition).
  • **Performance:** Due to its specialized implementation (internally, it may use an array where the enum's ordinal value acts as the array index), basic operations like `get()`, `put()`, and `remove()` are extremely fast—often approaching **constant time ($O(1)$)**, faster than the general-purpose $O(1)$ for HashMap.
  • **Non-Synchronized:** It is **not thread-safe**. External synchronization is necessary for concurrent modification.
  • **Null Values:** It **permits null values**, but it **does not permit null keys** (unlike HashMap).

II. Construction and Key Type

Unlike other map implementations, the key type must be provided during construction. This is necessary because the `EnumMap` needs to know the size and order of the underlying enum:

// 1. Define the Enum
public enum Numbers {ONE, TWO, THREE, FOUR, FIVE}

// 2. Instantiate the EnumMap, providing the Class literal
EnumMap<Numbers, Integer> map = 
   new EnumMap<>(**Numbers.class**);

Other constructors allow initializing from an existing `EnumMap` or a standard `Map` while inferring the key type from the source.

III. Example of Ordering

In the example, the enum constants are declared as `ONE, TWO, THREE`. Even though the internal hashing might differ, the output preserves this declaration order:

Enum Declaration Order:

public enum Numbers{**ONE**, **TWO**, **THREE**, FOUR, FIVE}

Output (Iteration Order):

{**ONE**=1, **TWO**=2, **THREE**=3}
