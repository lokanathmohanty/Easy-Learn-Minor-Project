Python - Mocking and Stubbing

Python mocking and stubbing are important techniques in unit testing that help isolate the functionality being tested by replacing real objects or methods with controlled substitutes.

Python Mocking

Mocking is a testing technique where mock objects simulate behaviors of real objects, useful when dealing with complex or unpredictable dependencies like databases or web services. It isolates the code under test from its dependencies.

  • Behavior Simulation: Mocks can return specific values, raise exceptions, or mimic real object behavior.
  • Interaction Verification: Mocks record usage allowing verification of method calls and arguments.
  • Test Isolation: Mocks let tests focus on code logic without external dependencies.
from unittest.mock import Mock

database = Mock()
database.get_user.return_value = {"name": "Prasad", "age": 30}

user = database.get_user("prasad_id")
print(user)

database.get_user.assert_called_with("prasad_id")

Output:

{'name': 'Prasad', 'age': 30}

Python Stubbing

Stubbing replaces methods or functions with stubs that return fixed, predetermined responses without recording interactions. Stubs simplify tests by providing consistent inputs.

  • Fixed Responses: Stubs always return specific predefined values.
  • Simplified Dependencies: Avoid managing complex dependencies setup.
  • Focus on Inputs: Emphasizes consistent inputs and outputs for tests.
from unittest.mock import patch

def get_user_from_db(user_id):
   pass

with patch('__main__.get_user_from_db', return_value={"name": "Prasad", "age": 25}):
   user = get_user_from_db("prasad_id")
   print(user)

Output:

{'name': 'Prasad', 'age': 25}

Python Mocking Vs. Stubbing

The table below compares mocking and stubbing to clarify their distinctions and help choose the right method.

Criteria Mocking Stubbing
Purpose Simulate behavior of real objects Provide fixed, predetermined responses
Interaction Verification Can verify method calls and arguments Typically does not verify interactions
Complexity More complex; simulates various behaviors Simpler; focuses on controlled inputs
Use Case Isolate and test code with complex dependencies Simplify tests by providing known responses
Recording Behavior Records how methods were called Does not record interactions
State Management Can maintain state across calls Usually stateless; returns fixed output
Framework Support Primarily uses unittest.mock with Mock and MagicMock Uses unittest.mock's patch for simple replacements
Flexibility Highly flexible; simulates exceptions and side effects Limited flexibility; focused on return values
