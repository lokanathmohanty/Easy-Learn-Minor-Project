Java Database Connectivity (JDBC) Summary 🔗💾

The **JDBC API** (Java Database Connectivity) is a standard Java API that provides **database-independent connectivity** between the Java programming language and a wide range of databases (especially Relational Databases, RDBMS).

I. Core Concepts and Purpose

  • **Definition:** JDBC is a specification providing interfaces for portable access to an underlying database. It allows Java programs to access tabular data.
  • **Functionality:** The API enables core database tasks like:
    1. Making a **connection** to the database.
    2. Creating and executing **SQL statements** (queries).
    3. Processing and viewing the resulting **records**.
  • **Applications:** JDBC drivers can be used by various Java executables, including Java Applications, Applets, Servlets, JSPs, and EJBs.
  • **Packages (JDBC 4.0):** The primary packages are **java.sql** and **javax.sql**. Modern versions (4.0+) include features like automatic driver loading and enhanced exception handling.

II. Key Interfaces and Classes (JDBC API Components)

These components are the building blocks of any JDBC application:

Component Type Function
**DriverManager** Class Loads the correct JDBC **Driver** and establishes a **Connection**.
**Connection** Interface Represents an active session with the database. Used to create **Statement** objects.
**Statement** Interface Used for executing simple, static SQL queries (without parameters).
**PreparedStatement** Interface Used for executing parameterized SQL queries (with placeholder values, `?`). Offers better performance and security (prevents SQL injection).
**CallableStatement** Interface Used for executing stored procedures and functions in the database.
**ResultSet** Interface Represents the **tabular data** retrieved from a database query. Allows iteration over the rows of the result set.
**ResultSetMetaData** Interface Provides information about the columns in a ResultSet (names, types, count).

III. JDBC Driver Types

JDBC drivers are categorized based on their implementation approach:

  • **Type 1 (JDBC-ODBC Bridge Driver):**
    • **Mechanism:** JDBC API calls are translated to ODBC calls. Requires an ODBC driver on the client.
    • **Status:** Legacy and generally discouraged/removed from modern JDKs.
  • **Type 2 (JDBC Native API Driver):**
    • **Mechanism:** JDBC API calls are converted into native C/C++ API calls specific to the vendor database.
    • **Requirement:** Requires native vendor-provided libraries to be installed on the client machine. (e.g., Oracle OCI driver).
  • **Type 3 (JDBC-Net Pure Java Driver):**
    • **Mechanism:** A three-tier approach. Java client communicates with a **middleware application server** using standard network sockets, and the middleware translates the calls to the DBMS format.
    • **Advantage:** Client-side only needs the JDBC driver and Java Runtime.
  • **Type 4 (Pure Java Driver / Direct-to-Database):**
    • **Mechanism:** A pure Java driver that communicates **directly** with the vendor's database through socket connections (e.g., MySQL Connector/J).
    • **Advantage:** Highest performance, entirely database-independent on the client side, and highly portable. **This is the most common type used today.**
