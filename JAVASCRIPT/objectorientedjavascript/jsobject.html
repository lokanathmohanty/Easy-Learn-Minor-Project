Session Goals: Understand what JavaScript objects are, how to create them, work with properties and methods, traverse and transform them, and apply best practices used in modern applications.

  • Define objects and distinguish them from primitive values.
  • Create objects using multiple patterns (literal, constructor function, Object.create(), classes).
  • Read, write, delete, and enumerate properties safely.
  • Use prototypes and understand delegation.
  • Apply common utility methods from Object.
  • Avoid common pitfalls and adopt robust patterns.

1) What Is an Object?

An object is a non-primitive value that stores data as key–value pairs. Keys (also called property names) are strings or symbols; values can be any type, including functions (methods). Objects are unordered collections.

  • Keys → property names (string or symbol)
  • Values → any JS value (number, string, array, object, function, etc.)
  • Methods → properties whose values are functions and can use this

2) Creating Objects — Patterns

  • Object Literal: Use curly braces to define keys and values directly.
  • new Object(): Rarely needed in modern code; creates an empty object.
  • Constructor Function + new: Functions that initialize instances via this.
  • Object.create(proto): Creates a new object with the specified prototype.
  • ES6 Class: Syntactic sugar over prototypes for defining constructors and methods.

Examples — Creating Objects

  • Literal: { title: "Perl", author: "Mohtashim", pages: 355 }
  • Constructor Function: function Book(t,a){ this.title=t; this.author=a; } then new Book("Perl","Mohtashim")
  • Object.create: Object.create(null) (no prototype) or Object.create(proto) (delegation).
  • Class: class Book { constructor(t,a){ this.title=t; this.author=a; } } then new Book("Perl","Mohtashim")

3) Reading & Writing Properties

  • Dot notation: obj.key (simple identifiers only).
  • Bracket notation: obj["key-name"] (computed or special characters).
  • Create/Update: obj.price = 100
  • Delete: delete obj.price
  • Check own property: Object.hasOwn(obj,"key") or obj.hasOwnProperty("key")

Examples — Reading & Writing

  • Get document title: var t = document.title
  • Add method then call it: obj.say = function(){ return "hi"; } then obj.say()
  • Dynamic key: const k = "full-name"; obj[k] = "Ada Lovelace"

4) Methods, this, and Binding

When a function is invoked as a method (obj.fn()), this refers to the object before the dot (in non-strict mode rules aside). Arrow functions capture this from the surrounding scope and are not suitable as methods when you rely on dynamic this.

  • Method form: const user = { name:"Ada", greet(){ return "Hello " + this.name; } }
  • Avoid arrow for methods needing dynamic this.
  • Use Function.prototype.bind to fix this when passing methods as callbacks.

5) Enumerating Properties

  • Object.keys(obj) → array of own enumerable keys.
  • Object.values(obj) → array of own enumerable values.
  • Object.entries(obj) → array of [key, value] pairs.
  • for...in loops over enumerable keys, including inherited. Filter with Object.hasOwn.

Examples — Enumeration

  • Map values: Object.values(stats).map(n => n * 2)
  • Entries to object: Object.fromEntries([["a",1],["b",2]])

6) Prototypes & Delegation

Every object has an internal link to another object called its prototype (except those created with Object.create(null)). When you access a property not found on the object, JavaScript looks up the prototype chain.

  • Set prototype (rarely needed): Object.setPrototypeOf(obj, proto)
  • Get prototype: Object.getPrototypeOf(obj)
  • Check relation: proto.isPrototypeOf(obj)

Examples — Prototypes

  • Delegating object: const child = Object.create(parent) then child.missing resolves via parent.
  • Class methods live on ClassName.prototype, shared by instances.

7) Built-in (Native) Objects

  • Number, String, Boolean
  • Array, Date, RegExp
  • Math (namespace-like object)
  • Symbol
  • Set, WeakSet
  • Map, WeakMap
  • TypedArray (Int8Array, Uint8Array, etc.)
  • Reflect

8) Useful Object Utilities

  • Object.assign(target, ...sources) — shallow copy / merge.
  • Object.freeze(obj) — make object immutable (shallow).
  • Object.seal(obj) — disallow add/remove but allow modify existing (unless read-only descriptors).
  • Object.preventExtensions(obj) — disallow adding new properties.
  • Object.getOwnPropertyNames(obj), Object.getOwnPropertySymbols(obj) — introspection.
  • Object.getOwnPropertyDescriptor(obj, key) — read descriptors.
  • Object.fromEntries(iterable) — build objects from pairs.
  • Object.hasOwn(obj, key) — safe own-property check.

Examples — Utility Patterns

  • Shallow clone: const clone = Object.assign({}, obj)
  • Pairs to object: Object.fromEntries([["id",1],["name","Ada"]])
  • Freeze config: const cfg = Object.freeze({ retries: 3 })

9) Copying: Shallow vs Deep

  • Shallow copy duplicates only the top level; nested objects are shared references.
  • Deep copy duplicates nested structures; use libraries or structured cloning when needed.
  • Structured clone (where available): structuredClone(obj)

Examples — Copying

  • Shallow: const copy = { ...original }
  • Deep (built-in): const deep = structuredClone(original)

10) Modern Syntax with Objects

  • Property shorthand: const user = { name, age }
  • Method shorthand: const obj = { greet(){ return "hi"; } }
  • Computed keys: const k = "id-"+n; const o = { [k]: 42 }
  • Destructuring: const { x, y: alias = 0 } = point
  • Optional chaining: user.profile?.avatar?.url
  • Nullish coalescing: value ?? defaultValue

Examples — Modern Syntax

  • Safe access: config.db?.host ?? "localhost"
  • Destructure with defaults: const { retries = 3 } = options

11) JSON vs JavaScript Objects

  • JSON is a data format (text) with strict rules; object literals are executable JS expressions.
  • JSON keys and string values must use double quotes.
  • Functions, undefined, and Symbol are not valid in JSON.

Examples — JSON

  • Parse: const data = JSON.parse(text)
  • Stringify: const text = JSON.stringify(obj)

12) Immutability & Safety

  • Prefer pure functions that return new objects instead of mutating inputs.
  • Freeze critical configuration objects.
  • Validate external data before merging into objects.

13) Common Pitfalls

  • Using arrow functions for methods that rely on this.
  • Assuming property order; objects are unordered (iteration order is defined but should not be relied upon for semantics).
  • Using for...in without filtering own properties.
  • Accidentally sharing nested references after a shallow copy.
  • Mutating frozen or sealed objects (silently fails in non-strict mode, throws in strict mode).

14) Practice — Guided Exercises

  • Create a Book object with keys title, author, and a method summary() that returns a string.
  • Write a function that safely reads user.profile.avatar using optional chaining and returns a fallback URL.
  • Implement a shallow clone utility using Object.assign and show how a nested object remains shared.
  • Build a prototype chain with Object.create and demonstrate delegation.

  • How does method shorthand differ from assigning a function to a property?
  • What are the trade-offs between shallow and deep copies?
  • Why can optional chaining improve robustness when accessing nested data?
  • What is the role of prototypes in property lookup?

16) Quick Reference

  • Create literal: { key: value }
  • Access: obj.key or obj["key"]
  • Existence (own): Object.hasOwn(obj,"key")
  • Enumerate: Object.keys / Object.values / Object.entries
  • Clone (shallow): { ...obj } or Object.assign({}, obj)
  • Freeze: Object.freeze(obj)
  • From entries: Object.fromEntries(pairs)
