C++ Web Programming: Common Gateway Interface (CGI) 🌐💻

The **Common Gateway Interface (CGI)** is a standard set of rules defining how an **HTTP Web Server** communicates with an external program (the **CGI Program** or **Script**). Instead of sending a static file, the web server executes the CGI program, and the program's output is sent back to the client's browser.

This mechanism allows C++ (or Perl, Python, etc.) programs to generate dynamic web content (like HTML pages, personalized data, or results from a database query).

CGI Core Principles

Web Server Interaction

When a browser requests a file in the configured CGI directory (conventionally `/cgi-bin/`), the web server:

  1. Executes the requested file (the C++ executable).
  2. Collects the program's output (usually via **STDOUT**).
  3. Sends that output back to the client's browser.

The HTTP Header

The CGI program's first output lines must form a valid **HTTP Header**, which informs the browser about the type of content to expect. The most crucial part is the `Content-type` line:

Content-type: text/html\r\n\r\n

The double newline (`\r\n\r\n`) is essential; it separates the HTTP header from the actual page content (HTML).

Environment Variables

CGI programs receive request-specific data from the web server through **Environment Variables**. Key variables include:

  • **`REQUEST_METHOD`**: (`GET` or `POST`).
  • **`QUERY_STRING`**: Contains data sent via the `GET` method.
  • **`CONTENT_LENGTH`**: The length of the data available for `POST` requests.
  • **`REMOTE_ADDR`**: The IP address of the client.

Data Passing Methods (GET vs. POST)

Web browsers use two primary methods to pass user input (often from HTML forms) to the CGI script:

MethodDescriptionAccess Point
**GET**Data is appended to the URL (e.g., `url?key=value`). It's limited in size and **visible** in the browser's address bar, making it unsuitable for sensitive data.**`QUERY_STRING`** environment variable.
**POST**Data is sent in the body of the HTTP request, appearing on the CGI script's **Standard Input (STDIN)**. It supports large amounts of data and is preferred for sensitive information.The script reads from STDIN.

In the provided examples, the **C++ CGI Library (`cgicc`)** simplifies accessing data for both `GET` and `POST` methods by abstracting whether the data came from the environment variables or STDIN.

State Management with Cookies

Since HTTP is a **stateless protocol**, **Cookies** are used to maintain session information across multiple page requests. They work as follows:

  1. **Setting Cookies:** The CGI script sends the `Set-Cookie` HTTP header before the `Content-type` line.
  2. **Retrieving Cookies:** The browser automatically sends stored cookies back to the server in the **`HTTP_COOKIE`** environment variable on subsequent requests. The `cgicc` library processes this variable to provide easy access to the stored key/value pairs.
// Setting a cookie (sent in the HTTP header)
cout << "Set-Cookie:UserID = XYZ;\r\n";
