Next.js Interview Questions and Answers

This list covers fundamental, intermediate, and advanced topics to help you prepare for your Next.js job interview.

Basic Next.js Interview Questions

1. What is Next.js and how is it different from React?

Next.js is a full-stack **React framework** that is built on top of React and Node.js. It adds features like **Server-Side Rendering (SSR)**, **Static Site Generation (SSG)**, file-system routing, and API Routes to create production-ready web applications.

React is primarily a **JavaScript library** focused on building user interfaces (UIs) in the browser (Client-Side Rendering). Next.js uses React as its core UI library but provides the necessary structure and rendering strategies to build complex, high-performance, and SEO-friendly applications.

2. Mention some key features of Next.js.

  • Server-Side Rendering (SSR) & Static Site Generation (SSG): Advanced pre-rendering capabilities for performance and SEO.
  • File-based Routing: Routes are automatically created based on the file and folder structure in the app/ directory.
  • API Routes: Allows you to create serverless functions (backend endpoints) directly within your Next.js project.
  • Automatic Code Splitting: Code is automatically split into smaller chunks, reducing the initial load time.
  • Image & Font Optimization: Built-in components (<Image>, next/font) handle performance optimization automatically.

7. Explain the concept of routing in Next.js.

Routing in Next.js is **file-system based**. The structure of files and folders within the **app/** directory (App Router) automatically defines the application's routes. A route is typically defined by a folder path, and the leaf file, **page.tsx** (or page.js), creates the UI for that route segment.

For example, a file at app/users/profile/page.tsx automatically creates the route accessible at /users/profile.

8. What are App Router and Page Router in Next.js?

These are two different approaches to handling routing and rendering in Next.js:

  • App Router (Next.js 13+): The modern and recommended approach using the **app/** directory. It is built on **React Server Components**, offering advanced features like nested routing, shared layouts, and a flexible rendering model (SSR, SSG, Static).
  • Page Router (Legacy): The traditional approach using the **pages/** directory. It is simpler and primarily relies on Client-Side Rendering with optional classic data fetching methods like getServerSideProps.

9. Explain the concept of static site generation in Next.js.

Static Site Generation (SSG) is a pre-rendering strategy where the complete HTML page is generated **at build time** (when you run npm run build). This HTML file is then cached by a CDN (Content Delivery Network) and served to the user almost instantly upon request.

SSG is ideal for content that does not change frequently, such as blog posts, documentation, and marketing pages. By default, Next.js components that don't involve external data fetching use static rendering.

13. What is the difference between client-side and server-side rendering?

These are the two main ways a web page's HTML is generated:

Criteria Client-side Rendering (CSR) Server-side Rendering (SSR)
Rendering HTML is built in the **browser** using JavaScript after the initial load. HTML is fully generated on the **server** and sent ready-to-display to the browser.
Initial Load Time Slower (must download, parse, and execute JavaScript first). Faster (browser receives rendered HTML instantly).
SEO Less ideal; search engines may struggle with the initial blank HTML shell. Excellent; content is fully rendered and immediately available for crawlers.

14. Explain pre-rendering and its types in Next.js.

Pre-rendering is the technique where Next.js generates the HTML for a page in advance, rather than sending a blank page and waiting for the client's JavaScript to render the content. This leads to faster Time to Interactive (TTI) and better SEO.

The process of loading JavaScript to the pre-rendered HTML page to make it interactive is called **Hydration**.

Next.js primarily uses two types of pre-rendering:

  • Static Site Generation (SSG): HTML is generated at **build time**.
  • Server-Side Rendering (SSR): HTML is generated **per request** on the server.

Medium Level Next.js Interview Questions

17. What are API Routes in Next.js?

API Routes are a feature that allows you to create **backend endpoints** (serverless functions) directly within your Next.js application, typically inside the **app/api/** directory.

They are used to handle server-side logic, such as:

  • Fetching data from a database.
  • Handling form submissions.
  • Implementing authentication or server-side utility functions.

The file name defines the API endpoint (e.g., app/api/users/route.ts is the endpoint /api/users).

21. What is middleware? Why is it used in Next.js?

A Next.js **Middleware** is a function that runs **before** a request is completed, but after a user navigates to a URL. It allows you to execute code logic before a route segment is rendered.

Middleware is defined in a **middleware.ts** (or middleware.js) file in the root or an app directory.

It is primarily used for:

  • Authentication: Checking if a user is logged in before allowing access to a page.
  • Authorization/A/B Testing: Applying different layouts or logic based on user roles or group.
  • URL Rewriting/Redirecting: Programmatically changing the destination of a request (e.g., forcing a redirect using NextResponse.redirect).

24. What is lazy loading in Next.js?

Lazy Loading is a performance optimization technique that delays the loading of non-critical resources until they are actually needed. By default, Next.js handles route-based code splitting, which is a form of lazy loading.

Developers implement lazy loading for components or modules using the built-in **next/dynamic** function:

import dynamic from 'next/dynamic'

const DynamicComponent = dynamic(() => import('../components/HeavyComponent'), {
  loading: () => <p>Loading...</p>,
})

This ensures the JavaScript bundle for HeavyComponent is not included in the initial page load, thus improving the application's TTI.

25. Explain how to implement dynamic routing in Next.js.

Dynamic routing allows you to create flexible routes where a segment of the URL path is determined by dynamic data (like a product ID or a slug).

In the App Router, you create a dynamic segment by enclosing the folder name in **square brackets** ([]). The name inside the brackets becomes the parameter accessible in your page component via the params prop.

Example:

A file at app/products/[id]/page.tsx creates a route structure where [id] is the dynamic segment. Accessing /products/123 makes 123 available as params.id in the component.

// app/products/[id]/page.tsx
export default function ProductPage({ params }) {
  // params.id will be the value in the URL, e.g., '123'
  return <h1>Product ID: {params.id}</h1>
}

27. What is Incremental Static Regeneration (ISR)?

Incremental Static Regeneration (ISR) is an advanced Next.js feature that allows you to update statically pre-rendered pages **after** the site has been built and deployed, without requiring a full rebuild of the application.

It works by setting a **revalidate** time (a time-to-live) in seconds on a page's data fetching function (e.g., getStaticProps in the Page Router or using fetch options in the App Router).

  • When a user requests a page older than the revalidate time, they are served the **stale (cached) page** instantly.
  • Next.js then regenerates the page **in the background**.
  • Subsequent users receive the newly regenerated version.

ISR provides the performance of static sites while retaining the freshness of server-side rendering.

Advanced Next.js Interview Questions

15. What is Partial Pre-rendering (PPR) in Next.js?

Partial Pre-rendering (PPR) is a key rendering pattern in the App Router that automatically optimizes dynamic content by treating it as a performance enhancement rather than a blocker.

  • It enables the rendering of the **Static Shell** (the majority of the page's HTML) at build time or cache time.
  • The remaining **Dynamic Holes** (e.g., a personalized cart icon or weather widget) are rendered on the server only when requested and streamed in later.
  • This provides a fast initial load time (similar to SSG) while ensuring the dynamic parts are always fresh (like SSR), without relying on client-side fetching.

26. How to create custom Metadata for each page in Next.js?

In the **App Router**, you create dynamic metadata (like title or description) by exporting an asynchronous **generateMetadata()** function from a page.tsx file. This function runs on the server and receives the route **params**, allowing the metadata to be dynamically set before the page is rendered.

// app/products/[id]/page.tsx
import { Metadata } from "next";

type Props ={ params: { id: string } };

// This runs on the server
export const generateMetadata = ({ params }: Props): Metadata => {
    return {
        // Dynamic title based on the route parameter
        title: `Product ${params.id} - My Store`, 
    };
}

This pattern is crucial for **SEO**, as it ensures search engines receive the correct, dynamic metadata when crawling the page.

28. What is the next.config.js file? Explain its key properties.

The **next.config.js** file is a JavaScript or TypeScript file located in the root of your project that allows you to **customize the default behavior** of your Next.js application, including the build process, runtime options, and more. It is an extension of the framework's core functionality.

Key properties include:

  • output: Controls the build output (e.g., "standalone" for optimized self-hosting or "export" for static HTML export).
  • redirects(): An asynchronous function used to define a list of URL redirects that are applied early in the request lifecycle.
  • headers(): An asynchronous function to define custom HTTP headers (e.g., caching policies, security headers) to be applied to responses.
  • env: Defines environment variables that should be exposed to the application.
