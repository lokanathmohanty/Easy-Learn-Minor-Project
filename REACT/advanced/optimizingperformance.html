ReactJS - Optimizing Performance

React performs many optimizations automatically, but developers can apply additional techniques to improve application responsiveness and reduce resource usage. This session covers common strategies and an applied example using windowing for large lists.

Techniques of Performance Optimization

  • Use production build instead of development mode for deployed apps.
  • Load libraries from a CDN in their production builds when appropriate.
    • Example CDN references: react.production.min.js and react-dom.production.min.js
  • Bundle optimizations: use build tools (Create React App, Rollup, Brunch) with terser/minification.
  • Profile with React DevTools Profiler to find render hotspots before optimizing.
  • Windowing / virtualization: render only the visible portion of large lists.
  • Avoid unnecessary reconciliation by preventing unnecessary renders.
  • Use PureComponent or memoization for components that render identical output for identical inputs.

Production Builds

Development builds include debug helpers and warnings which slow runtime performance. Create a production build before deploying. Example commands:

  • Create React App: run the build command to produce an optimized bundle.
  • Bundlers: enable terser/minification and commonjs/replace plugins for Rollup or similar tooling.

Avoiding Unnecessary Reconciliation

React compares previous and next element trees (reconciliation) to apply updates. You can reduce work by skipping renders when nothing meaningful changed.

  • shouldComponentUpdate: a class component hook that can return false to skip rendering.
  • PureComponent (or React.memo for function components): performs a shallow comparison of props and state and skips renders when unchanged.
  • For reference-type props (arrays/objects), prefer immutable updates so shallow comparisons detect changes. Do not mutate existing objects if you expect PureComponent / memo to detect updates.

Windowing Technique (Virtualization)

For very large lists, rendering all items can be expensive. Windowing renders only the items visible in the viewport (plus a small buffer), drastically reducing DOM nodes and improving scrolling performance.

  • Use libraries such as react-window or react-virtualized.
  • Choose a fixed-size or variable-size list component depending on item heights.
  • Provide an item renderer that receives index and style and returns the list item element.

Example: Applying Windowing Technique

This example outlines steps to virtualize a large user list using react-window.

  • Create a new React app (for example with Create React App).
  • Install react-window as a dependency.
  • Add a users.json data file containing many user entries in the public folder.
  • Create a list component that:
    • Fetches the users.json data on mount.
    • Renders a FixedSizeList (or suitable component) from react-window.
    • Passes the fetched data as itemData and configures itemCount and itemSize.
    • Implements the item renderer to return an <li>-style element for each visible index.
  • Render the virtualized list inside the app root. The component will only mount DOM nodes for visible rows.

Summary

Start by profiling and applying changes where the app spends the most time. Use production builds, avoid unnecessary renders, prefer pure/memoized components for stable props, and apply windowing for very large lists to achieve the best perceived and actual performance.
