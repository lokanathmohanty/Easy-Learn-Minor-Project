Java 9 - Major New Features Summary

Core Theme: Modularity (Project Jigsaw) 🧩

The primary and most impactful feature of **Java 9 (released September 2017)** was the implementation of the **Java Platform Module System (JPMS)**. The main goals were to enhance security, improve performance, simplify maintenance, and enable the platform to be scaled down for smaller devices.

The Module System

A **Module** is a self-describing collection of code and data (packages and resources) that is explicitly named and defines which of its packages are **exported** (accessible to other modules) and which other modules it **requires**.

  • module-info.java: The module descriptor file where dependencies (requires) and exposed packages (exports) are defined.
  • Strong Encapsulation: By default, module internals are hidden. Only explicitly exported packages are accessible outside the module, improving security and stability.
  • JDK Modularization: The entire JDK was divided into modules (e.g., java.base, java.desktop).

Developer Productivity Enhancements

REPL Tool: JShell

The **Read-Evaluate-Print Loop (REPL)** tool, called **JShell**, was introduced as an interactive command-line environment. It allows developers to execute arbitrary snippets of Java code, expressions, and statements instantly without the need for a full file, compilation, and execution cycle, significantly accelerating learning and prototyping.

Collection Factory Methods (List.of(), Set.of(), Map.of())

New static factory methods were added to the List, Set, and Map interfaces for easily creating **immutable** and concise instances of collections, eliminating boilerplate code.

// Java 9+ concise, immutable list creation
List<String> list = List.of("Java", "HTML 5", "C");

Improved @Deprecated Annotation

The annotation was enhanced with two new attributes for clearer deprecation policy:

  • forRemoval=true: Indicates that the element is explicitly scheduled to be removed in a future release.
  • since="9": Specifies the Java version in which the element first became deprecated.

API and Language Enhancements

Private Interface Methods

Interfaces can now contain **private** and **private static** methods. This allows multiple non-private methods (like default methods) within the same interface to share and encapsulate common utility code, avoiding code duplication while keeping the helper logic hidden from the implementing classes.

Process API Improvements

The OS process control API was significantly updated, centered around the **ProcessHandle** class. This provides rich, platform-independent access to process information (PID, start time, CPU usage, command, user) and better control (asynchronous onExit() with CompletableFuture).

Stream API Enhancements

New methods were added to the Stream interface for more flexible flow control:

  • takeWhile(Predicate): Takes elements from the start until the predicate is false.
  • dropWhile(Predicate): Discards elements from the start until the predicate is false, then keeps the rest.
  • iterate: Now supports an explicit **stop condition** (predicate), making it easy to create bounded streams.
  • ofNullable(T t): Returns a single-element stream if the value is non-null, or an empty stream if null, simplifying null checks in stream pipelines.

Try-With-Resources Simplification

Resources that are effectively final can now be used directly in the try-with-resources statement without needing to be declared inside the parenthesis, making the syntax more concise.

BufferedReader br = new BufferedReader(inputString);
try (br) { // 'br' is the effectively final resource
   return br.readLine();
}
