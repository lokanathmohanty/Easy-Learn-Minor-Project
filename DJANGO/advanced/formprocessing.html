Django: Form Processing and Validation 📝

Creating forms in Django is similar to creating models: you define a class that inherits from a base Django form class, and the class attributes become the form fields. This system handles rendering, data cleaning, and validation.

Defining a Form (forms.py)

Forms inherit from forms.Form (for standard forms) or forms.ModelForm (for forms linked directly to a database model).

  • Fields are defined using classes like forms.CharField.
  • Widgets are used to control how a field is rendered in HTML (e.g., forms.PasswordInput() hides the input).
from django import forms

class LoginForm(forms.Form):
   user = forms.CharField(max_length = 100)
   password = forms.CharField(widget = forms.PasswordInput())

Form Handling in a View

A typical Django view handles form submission by checking the HTTP request method (GET or POST).

  1. **GET Request:** If the request method is **GET**, the view creates an empty form instance and renders the template containing the form.
  2. **POST Request:** If the request method is **POST**, the view binds the submitted data (from request.POST) to a form instance.
def login(request):
   if request.method == "POST":
      # 1. Bind submitted data to the form
      MyLoginForm = LoginForm(request.POST) 
      
      # 2. Validate the form
      if MyLoginForm.is_valid():
         # 3. Access clean data
         username = MyLoginForm.cleaned_data['username'] 
   else:
      # GET request: create an empty form
      MyLoginForm = LoginForm() 
		
   return render(request, 'loggedin.html', {"username" : username})

Key Concepts in Form Processing

  • **request.method**: An attribute of the request object used to determine if the request is a GET (initial load) or POST (form submission).
  • **LoginForm(request.POST)**: Binds the submitted data to the form, creating a "bound" instance.
  • **is_valid()**: Executes all validation checks on the bound form. If successful, the method returns True and cleans the data.
  • **cleaned_data**: A dictionary containing the submitted data after it has been successfully validated and converted to the appropriate Python type. You must check is_valid() before accessing this.
  • **{% csrf_token %}**: A template tag required inside any POST form in Django to protect against **Cross-site Request Forgery (CSRF)** attacks.

Custom Form Validation

Beyond Django's automatic checks (like required fields or valid email format), you can define custom validation methods within your form class.

To validate a specific field (e.g., username), define a method named **clean_<field_name>**.

from django import forms
from myapp.models import Dreamreal

class LoginForm(forms.Form):
   # ... fields defined here ...

   def clean_username(self):
      username = self.cleaned_data.get("username")
      dbuser = Dreamreal.objects.filter(name = username)
      
      if not dbuser.exists(): # Check if user exists in the DB
         # Raise an error if validation fails
         raise forms.ValidationError("User does not exist in our db!")
      return username # Return the cleaned value if validation succeeds

If the custom validation fails, the method should raise a **forms.ValidationError**. If it succeeds, it must return the cleaned value for that field.
