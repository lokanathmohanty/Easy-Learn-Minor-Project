Power BI - Develop Star Schema

A Star Schema is a data modeling structure where a central Fact table connects to multiple Dimension tables. Each Dimension table typically has a One-to-Many relationship with the Fact table. The Fact table contains measurable data (mostly integers), while the Dimension tables hold descriptive or categorical information used for filtering and analysis.

The Fact table helps summarize numeric fields and supports data segmentation and strong relational modeling in business analysis.

Case Study

The task "Generating the Star Schema in Data Modeling" is given to Richard by a Data Analytics mentor.

Solution

Richard needs to understand the roles of Fact and Dimension tables to effectively build a Star Schema model.

How to Develop a Star Schema?

Below are the steps Richard follows to create a Star Schema:

Step 1

Import the following datasets into Power BI Desktop:

  • D:\custid.xlsx
  • D:\ck.xlsx (select both sheets)
  • D:\date.xlsx

After import, Power BI shows four tables: ck, customer_salary, dt, and Sheet1. It auto-detects relationships among them.

Step 2

Switch to the Model view to inspect and edit the relationships. Initially, the model shows:

  • One-to-Many between Sheet1 and dt
  • One-to-One between ck and Sheet1
  • One-to-One between Sheet1 and customer_salary

Step 3

Edit the model to match Star Schema by deleting the existing relationship between ck and Sheet1. Then, create a new One-to-Many relationship from ck.Cust_key to dt.Cust_key. Confirm the relationship direction is unidirectional.

Step 4

Delete the relationship between Sheet1 and customer_salary. Confirm the bidirectional filter is removed.

Step 5

Use Manage Relationships from the Home tab to create a new relationship between customer_salary and dt.

Step 6

In the "Create Relationship" dialog:

  • First Table: customer_salary
  • Second Table: dt
  • Cardinality: One-to-Many (1:*)

Click OK to add the relationship.

Step 7

The new One-to-Many relationship is now added and visible in the relationship model.

Step 8

Now, Richard has successfully developed the Star Schema. In this schema:

  • dt is the Fact table
  • ck, customer_salary, and other tables are Dimensions
  • Each Dimension table has a One-to-Many relationship with the Fact table

Key Points While Developing the Star Schema

  • Clearly identify the Fact table and Dimension tables.
  • Hide unnecessary columns to simplify the model.
  • Ensure Dimension tables have unique values for One-to-Many relationships.
  • Fact table may contain duplicate values.
  • Eliminate redundant relationships between Dimension tables.
  • A shared column must exist between Fact and Dimension tables.
  • Fact table should contain the foreign key referencing Dimension table’s primary key.

How to Identify a Fact Table vs a Dimension Table?

  • A table with One cardinality is a Dimension table.
  • A table with Many cardinality is a Fact table.
  • Dimension tables generally have fewer fields.
  • Fact tables often include multiple measurable fields.
