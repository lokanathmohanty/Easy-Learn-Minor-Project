Next.js - Testing With Vitest

What is Vitest?

Vitest is a modern, fast, and feature-rich **JavaScript testing framework** built on top of **Vite**, the popular build tool. It is often preferred for its speed and native support for modern web standards, making it an excellent choice for testing Next.js applications.

  • It supports various testing types, including **unit tests**, **integration tests**, and basic **end-to-end** scenarios.
  • Key features include a **watch mode** for real-time feedback, **snapshot testing**, and **code coverage** reporting.

Setting Up Vitest in Next.js

Installation and Dependencies

In your existing Next.js project, install Vitest and the necessary testing libraries:

// Install Vitest, JSDOM (for browser environment simulation), and React Testing Library
npm install --save-dev vitest jsdom @testing-library/react @testing-library/jest-dom

Configuration (vitest.config.ts)

Create a configuration file in the project root to define the testing environment:

// File - /vitest.config.ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
    test: {
        // Use 'jsdom' to simulate a browser environment for testing components
        environment: 'jsdom',
        // Enable globals (like 'describe', 'it', 'expect') without explicit import
        globals: true,
        // Path to setup file for global configurations/polyfills
        setupFiles: './vitest.setup.ts',
    },
})

Scripts in package.json

Add scripts to run Vitest efficiently:

// File - /package.json
{
    "scripts": {
        "test": "vitest", // Runs tests in watch mode by default
        "test:ui": "vitest --ui", // Runs tests with a visual interface
        "coverage": "vitest run --coverage" // Generates code coverage report
    }
}

Test File Location

Store your test files in a **__tests__** directory (or use files ending in .test.tsx/.test.jsx) in the root or component folders.

Writing Component Tests with Vitest and RTL

Vitest syntax is highly compatible with Jest, allowing the use of familiar testing utilities like describe, it, and expect, in conjunction with the React Testing Library (RTL).

The Component (app/Home/page.tsx)

export default function Home() {
    return (
        <div>
            <h1>Welcome to Next.js</h1>
            <button onClick={() => alert('Hello!')}>
                Click Me
            </button>
        </div>
    );
}

The Test File (/__tests__/Home.test.tsx)

The test uses RTL functions like **render** and **screen** for user-centric testing, and Vitest's **vi.spyOn** for mocking browser functions.

import { describe, it, expect, vi } from 'vitest';
import { render, screen, fireEvent } from '@testing-library/react';
// Assuming '@/pages/index' maps to the Home component
import Home from '@/pages/index'; 

describe('Home Page', () => {
    // Test 1: Verifies the content is rendered
    it('renders welcome message', () => {
        render(<Home />);
        // Assert that the text is present in the document
        expect(screen.getByText('Welcome to Next.js')).toBeDefined(); 
    });

    // Test 2: Verifies component behavior on click
    it('handles button click', () => {
        render(<Home />);
        // Use vi.spyOn to mock and monitor the window.alert function
        const alertSpy = vi.spyOn(window, 'alert');
        
        // Simulate a click on the button
        fireEvent.click(screen.getByText('Click Me'));
        
        // Assert the alert function was called with the correct argument
        expect(alertSpy).toHaveBeenCalledWith('Hello!');
        
        alertSpy.mockRestore(); // Restore the original function
    });
});

Running the Tests

Execute your tests using the command defined in package.json:

npm test
