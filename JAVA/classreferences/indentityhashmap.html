Java IdentityHashMap Class Summary 👤🗺️

The **java.util.IdentityHashMap** class is a specialized implementation of the **Map** interface that uses **reference equality (`==`)** instead of **object equality (`equals()`)** when comparing keys and values. This unique feature fundamentally changes how the map operates compared to a standard HashMap.

I. Key Feature: Reference Equality (`==`)

In all standard `Map` implementations (like `HashMap` and `TreeMap`), two keys are considered equal if `key1.equals(key2)` is true. In contrast, `IdentityHashMap` uses the following rule:

  • A key `k1` is equal to a key `k2` **if and only if** **`k1 == k2`** (they are the exact same object instance in memory).
  • This means two separate objects (even if their contents are identical, such as `new String("A")` and `new String("A")`) are treated as **two distinct keys** in an `IdentityHashMap`.

II. Use Cases and Purpose

This class is not intended as a general-purpose map. It is primarily used for:

  • **Serialization and Deep Copying:** Maintaining a map of objects that have already been processed to avoid infinite loops when traversing object graphs that contain cycles (i.e., when an object references itself or is referenced by a subsequent object).
  • **Internal Map Views:** When creating a view of another structure where uniqueness must be based on object identity, rather than logical equality.
  • **Testing/Debugging:** Storing state associated with specific object instances.

III. Characteristics and Behavior

  • **Non-Synchronized:** It is **not thread-safe**.
  • **Unordered:** The iteration order is **not predictable** and is not guaranteed to remain constant.
  • **Nulls Permitted:** It allows **one null key** and **multiple null values**.
  • **Primitive Keys:** When using keys that are **immutable wrappers** (like `Integer` or `String`), the behavior can be confusing due to Java's use of caching or interning. For example, `new Integer(100)` and `new Integer(100)` are distinct, but `Integer.valueOf(5)` and `Integer.valueOf(5)` might be the same object due to caching (if the value is small).

Behavior Contrast Example:

String s1 = new String("hi");
String s2 = new String("hi"); // s1.equals(s2) is true, but s1 != s2

// HashMap: Treats s1 and s2 as the same key. Map size: 1
// IdentityHashMap: Treats s1 and s2 as different keys. Map size: 2
