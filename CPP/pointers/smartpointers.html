C++ Smart Pointers (Automatic Memory Management) 🧠

A **smart pointer** is a class template that wraps around a **raw pointer** to manage dynamically allocated memory automatically. They implement the **RAII (Resource Acquisition Is Initialization)** principle, ensuring that dynamically allocated memory is correctly deallocated when the smart pointer object goes out of scope.

Smart pointers solve common C++ memory problems:

  • **Memory Leaks:** Automatically calls delete when the memory is no longer needed.
  • **Dangling Pointers:** Prevents pointers from pointing to deallocated memory by managing object lifespan.

Types of Smart Pointers (<memory>)

The three modern smart pointers are unique_ptr, shared_ptr, and weak_ptr. (The older auto_ptr is deprecated and removed since C++17).

1. unique_ptr (Exclusive Ownership) 🔒

A unique_ptr is a smart pointer that maintains **exclusive ownership** of an object. It guarantees that only one pointer can point to the resource at a time.

  • **No Copying:** You cannot copy a unique_ptr.
  • **Ownership Transfer:** Ownership can be **transferred** using std::move(). Once transferred, the original pointer becomes null.
  • **Use Case:** Use when you need a single, clear owner of an object, ensuring automatic cleanup upon scope exit.
unique_ptr<int> ptr1 = make_unique<int>(200); // Owner 1
unique_ptr<int> ptr2 = move(ptr1);             // Ownership transferred. ptr1 is now null.

2. shared_ptr (Shared Ownership) 🤝

A shared_ptr allows **multiple pointers** to share ownership of the same object. It uses a **reference counter** to track the number of pointers pointing to the object.

  • **Automatic Deletion:** The object is automatically deleted only when the reference count reaches zero.
  • **Use Case:** Use when multiple parts of your program need to maintain access to the same dynamically allocated object, and its lifetime should be managed jointly.
shared_ptr<int> ptr1 = make_shared<int>(300);
cout << ptr1.use_count(); // Output: 1

shared_ptr<int> ptr2 = ptr1;      // Copying increases the count
cout << ptr1.use_count(); // Output: 2

3. weak_ptr (Non-Owning Observation) 🔭

A weak_ptr is a **non-owning** smart pointer that observes an object managed by a shared_ptr. It **does not affect the reference count**.

  • **Purpose:** Primarily used to **break circular dependencies** that can occur between shared_ptr objects, which would otherwise prevent memory from being released.
  • **Access:** To safely access the observed object, you must first call the .lock() method, which returns a temporary shared_ptr. If the object has already been destroyed, lock() returns an empty shared_ptr.
shared_ptr<int> owner = make_shared<int>(400);
weak_ptr<int> observer = owner; // Does not increase count

if (auto locked = observer.lock()) {
    // locked is a valid, temporary shared_ptr
}

Smart Pointers vs. Raw Pointers

Raw PointerSmart Pointer
Stores a memory address. Stores a raw pointer but wraps it in a class template for management.
Requires **manual** calls to new and delete. Uses RAII to manage allocation and **automatic** deallocation.
High risk of memory leaks and dangling pointers. Eliminates memory leaks and dangling pointers.
