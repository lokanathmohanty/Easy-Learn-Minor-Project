Java Programming: Relationships Between Classes

Session: Understanding Aggregation (HAS-A Relationship)

What is Aggregation?

**Aggregation** is a specialized form of association between two classes that represents a **HAS-A relationship**. It occurs when one class (the 'whole') contains an instance of another class (the 'part') as one of its instance variables.

It is a **one-way, weak relationship** where the existence of the 'whole' object does **not** control the existence of the 'part' object. If the 'whole' object is destroyed, the 'part' object can continue to exist independently.

Use of Aggregation

The primary use of aggregation is **code reusability**. By having one class contain an object of another class, it can utilize all the utility methods and properties defined in the contained object, without having to recreate that logic.

This design helps reduce code duplication and improves maintenance.

Example: Van HAS-A Speed

In this example, the Van class contains an instance of the Speed class. The Speed object can exist separately from the Van object.

class Speed {
   private double max;
   public double getMax() { ... }
   // ... setter methods
}

class Van extends Vehicle {
   private Speed speed; // Aggregation: Van HAS-A Speed

   public void setSpeed(Speed speed) {
      this.speed = speed;
   }

   public void print() {
      // Van uses Speed's method:
      System.out.println("Max Speed: " + speed.getMax() );
   }
}

Output:

Vin: abcd1233, Max Speed: 120.0

Example: Student HAS-A Address

A Student object has an Address object. The address can be shared by multiple students or can exist even if the student object is deleted, making this a typical aggregation relationship.

class Address {
   // ... fields like strNum, city, state
   Address(int street, String c, ...) { ... }
}

class Student {
   int rno;
   String stName;
   Address stAddr; // Aggregation: Student HAS-A Address

   Student(int roll, String name, Address address){
      this.stAddr = address; // Address object passed in
   }
}

Output:

Roll no: 1
Name: Aashi
Street: 10
City: Bareilly
State: UP
Country: India

Aggregation vs. Composition

Aggregation is often compared to **Composition**. While both represent a HAS-A relationship:

  • **Aggregation (Weak Association):** The 'part' can exist without the 'whole'. Terminating the main object does not terminate the contained object.
  • **Composition (Strong Association):** The 'part' cannot exist without the 'whole'. The parent object "owns" the child entity, and they have the same lifecycle.
